# 后端目录架构

黑金 ERP 当前采用按业务领域拆分的后端结构。实现包是内部技术边界，不要求与用户侧一级导航一一对应：

```text
app/
├── core/                   # 配置、数据库、金额、安全、审计等基础设施
├── domain/                 # 当前 ORM 模型与领域对象
├── foundation/             # 基础主数据与业务类型
├── parties/                # 客户、合作方等主体
├── orders/                 # 交易履约：订单、事件、表单与编号
├── stocks/                 # 账号资产：库存、成本与出入库
├── value_added_services/   # 分期合约等交易履约扩展能力
├── finance/                # 资金结算：资金池、流水、押金、返点
├── reporting/              # 只读经营分析与报表
├── policy/                 # 规则版本、策略与利润分配计算
├── imports/                # 数据接入、映射、对账与批次处置
├── quality/                # 数据质量扫描与异常检查
├── auth/                   # 登录、令牌、人员与团队
├── attachments/            # 附件中心
├── notifications/          # 系统通知
├── search/                 # 通用搜索
├── options/                # 选项字典
├── lists/                  # 通用列表能力
└── audit/                  # 审计查询接口
```

每个业务能力通常由路由、服务、模式和测试组成；写路径统一经过 Service 事务、权限校验和审计记录。横向能力不得取得订单、库存或资金事实的独立写权限。

领域治理目标是 6 个核心业务域（客户与合作方、交易履约、账号资产、资金结算、经营分析、规则与配置）加 2 个支撑域（数据接入、平台治理）。

- 返点记录、返点结算属于资金结算域，由 `finance` 统一维护，不保留独立运行域。
- 导入与对账属于数据接入域，由 `imports` 统一维护。
- 数据质量、审计、通知、附件、认证、搜索、字典和通用列表属于平台治理能力。
- HS、TH、DG 是交易履约下的业务类型，不是独立顶层领域。

跨域写入必须通过主责域服务提供的命令入口；跨域查询可以复用只读查询门面，但不得由查询方反向写入主责对象。具体归属、链路和门禁见 [领域归属台账](../docs/ERP_领域归属台账_v1.0.md)、[关键业务链路基线](../docs/ERP_关键业务链路基线_v1.0.md) 和 [领域边界审计清单](../docs/ERP_领域边界审计清单_v1.0.md)。
