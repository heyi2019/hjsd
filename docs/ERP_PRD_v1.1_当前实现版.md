# 宜游轩 ERP 产品需求文档 v1.1（当前实现版）

> **文件编号**：HJ-ERP-PRD-002
> **版本**：v1.1
> **状态**：当前开发成果对齐稿
> **日期**：2026-10-17
> **事实源**：当前仓库 `frontend/src`、`backend/app`、`backend/tests/v1`
> **适用范围**：宜游轩单团队经营系统

## 1. 文档目的

本 PRD 只描述当前代码已经形成的产品能力、数据对象、用户流程和下一步缺口。旧版 PRD 中的历史金额、迁移假设、未落地页面和待裁决业务规则不作为本版本功能依据；只有当前代码、接口契约和现有测试能证明的能力才写入“已实现”。

系统定位为工作室经营台账：统一记录业务订单、账号库存、资金流水、分期回款、返点、客户与合作方，并提供经营报表、权限控制、审计和标准导入能力。系统不接支付通道，不自动打款，所有资金事实由用户录入或由已登记业务事件生成。

## 2. 用户与权限

系统支持登录、退出登录、修改密码、首次登录强制改密和基于角色的后端鉴权。前端按钮显隐只用于体验，不能替代后端权限校验。

| 角色 | 主要能力 |
|---|---|
| 系统管理员 `admin` | 全部主数据、业务、资金、报表、导入、用户和团队管理 |
| 业务经办人 `operator` | 客户、合作方只读/建档/更新；创建和更新订单；发布业务事件；查看资金与报表 |
| 财务 `finance` | 资金池、押金、划转及资金相关事件；查看客户、合作方、报表 |
| 业务审核人 `auditor` | 查看资金；处理订单异常；审批经营规则；查看合作方和报表 |
| 经营查看人 `viewer` | 只读查看资金和经营报表 |

权限点覆盖客户、合作方、订单、业务事件、资金、押金、划转、规则、活字段、审计、报表、导入、用户和业务类型等领域。用户还可配置数据范围、所属资金池和团队。

## 4. 核心业务功能

### 4.0 业务模式

系统业务统一分为两种模式：

| 业务模式 | 代码 | 定义 | 当前业务 |
|---|---|---|---|
| 自营 | `SELF` | 工作室承担账号取得、资金占用、库存管理和销售结果，账号进入自营库存并按成本与售出事件核算 | 回收 `HS`；自营库存售出；自营库存分期出售 |
| 分销 | `DISTRIBUTION` | 工作室通过同行/供货方取得或代售账号，按提号、代挂或代分期服务核算；是否占用资金由具体事件决定 | 提号 `TH`；代挂 `DG`；代分期 `DFQ` |

业务模式与订单类型是两个维度：订单类型决定业务流程，业务模式决定库存归属和经营视图。新建订单时必须由业务类型带出默认模式；特殊业务可由后端按规则覆盖，但不能由前端随意把分销单当作自营库存售卖。

库存账号使用 `business_mode` 保存模式，使用 `inventory_type` 保存来源类型（`RECOVERY`、`PICKUP`、`CONSIGNMENT`）。`PICKUP` 属于分销提号实体，可追踪资金和执行过程，但不计入自营库存资产；`CONSIGNMENT` 属于分销代挂实体，不得按自营回收成本核算。

### 4.1 工作台

工作台提供四类当前业务的快速建单入口：

| 业务代码 | 页面名称 | 当前建单入口 |
|---|---|---|
| `HS` | 回收 | 自营回收 |
| `TH` | 提号 | 分销提号 |
| `DG` | 代挂 | 分销代挂 |
| `DFQ` | 代分期 | 增值服务 |

工作台还提供“售出库存账号”入口和进行中/已完成业务数量摘要。摘要只来自订单列表，不重复实现经营报表。

### 4.2 订单与业务事件

订单创建支持业务类型、交易日期、报价、服务费、结算日期、账号快照/库存账号、负责人、资金性质、备注、活字段、客户角色、合作方角色、首笔买入和分期合约等信息。

订单状态为 `ACTIVE`、`COMPLETED`、`CANCELLED`。订单号按业务类型独立递增，创建后不可由前端修改。订单详情包含：

- 业务事件时间线：`BUY`、`COST`、`SELL`、`PAYMENT`、`DELIVER`、`CANCEL`；
- 关联订单、资金流水、返点、分期合约/期次、附件和审计摘要；
- 订单编辑、取消和事件登记；
- 资金池路由：显式指定资金池优先，否则使用业务默认路由。

业务事件登记后生成对应资金事实，并驱动订单、库存和分期状态；已登记事实只能通过冲销或补充事件修正。

### 4.3 账号库存

库存台账以账号为管理对象，展示来源订单、业务模式、库存类型、游戏类型、账号标识、平台、状态、成本和未售时长。支持：

- 按状态、业务模式、库存类型和关键词筛选；
- 展开查看执行明细、订单事件、资金流水、返点和合作方；
- 全款售出、寄售、返点登记；
- 编辑账号资料、描述、图片和活字段；
- 导出当前筛选结果 CSV。

账号状态为 `IN_STOCK`、`INSTALLMENT`、`SOLD`、`VOID`。库存类型为 `RECOVERY`、`PICKUP`、`CONSIGNMENT`；`PICKUP` 可追踪但不允许通过库存售出动作重复售卖。账号密码默认不在普通列表返回，只有具备相应权限的详情读取才可展示。

### 4.4 分期与回款

系统支持两类分期合约：

| 合约类型 | 来源 | 页面动作 |
|---|---|---|
| `STOCK_SALE` | 已进入库存的自营售出 | 查看期次、登记收款、结清后交付 |
| `ADVANCE_PURCHASE` | `DFQ` 代分期订单 | 查看期次、登记收款、结清后换绑交付 |

合约记录本金、首付、服务费、期数、每期金额、首期日期、交付方式和备注；期次状态为 `PENDING`、`PARTIAL`、`PAID`、`OVERDUE`、`WAIVED`。收款必须选择首付或期次并记录日期；只有 `SETTLED` 合约可以执行交付。

### 4.5 客户与合作方

客户档案支持客户编号、名称、联系人、手机、微信、QQ、来源、备注、标签和活字段。联系方式默认脱敏，按权限显式读取并记录审计；重复联系方式只提示候选，不阻止建档。

客户详情展示订单参与关系、分期合约、汇总指标和审计记录。客户可停用或合并；`DISABLED`、`MERGED` 客户不能作为新订单参与方。

合作方与客户分开建模，类型为 `PEER`（同行）、`SUPPLIER`（供货方）、`PLATFORM`（平台），支持建档、启停和在订单中绑定角色。

### 4.6 资金中心

资金池是可配置主数据，字段包括代码、名称、用途类型、归属和状态。资金归属为 `OWNED`、`CUSTODY`、`THIRD_PART`；停用池保留历史流水，不允许破坏历史归属。

资金池总览展示收入、支出、转入、转出、现金余额、押金占用和可用余额。资金流水区分 `EXTERNAL_IN`、`BUSINESS_IN`、`BUSINESS_OUT`、`INTERNAL`，并记录方向、类别、日期、金额、订单/事件/押金/划转来源。

当前前端已提供流水只读、押金占用和部分/全部释放；后端已提供独立流水审核、拒绝、冲销、池间划转、日对账和账期锁定接口，需继续补齐页面闭环。

### 4.7 返点

返点必须关联来源订单，记录返点类型 `BUY`/`SELL`、渠道、费率、基数、预计/实际日期和状态。到账支持多次结算，每次记录到账金额、平台手续费、净额、回款池和现金流关联。

返点状态为 `OPEN`、`PARTIALLY_SETTLED`、`SETTLED`、`VOID`。库存详情已提供返点登记入口；独立返点工作台组件已实现，但尚未接入一级导航。

### 4.8 经营报表

经营中心提供以下只读报表：

| 报表 | 内容 |
|---|---|
| R1 库存健康 | 在库账号、买入成本、附加成本、占用成本、持有天数 |
| R2 月度损益 | 销售收入、账号直接成本、运营费用、净返点、经营利润，可按日期区间筛选 |
| R3 提成对账 | 人员、订单、利润基数、费率、应付、已付和差异，可按日期区间筛选 |
| R4 资金日报 | 各资金池期初、收入、支出、押金、现金余额和可用余额 |
| R5 业务损益 | 各业务订单数、主营收入、主营成本、主营利润、已结算返点、未归集返点和完整收益 |
| 订单利润 | 订单收入、直接成本、返点和净利润，可按日期区间筛选 |
| 数据中心 | 资金池和订单的快捷分析入口 |

报表接口支持按权限范围取数，并提供 CSV 导出接口；前端导出入口仍需补齐。

### 4.9 设置与可配置能力

- 业务类型：读取业务类型、资金性质和启停状态；后端支持创建、编辑、停用和路由配置。
- 资金池：前端支持新增和列表；后端支持编辑、停用、删除保护和余额查询。
- 活字段：支持 `TEXT`、`NUMBER`、`DATE`、`BOOLEAN`、`SELECT`、`MULTI_SELECT`，可按订单、账号、客户、分期、资金池、流水、需求和合作方挂载；有历史值的字段只能停用。
- 经营规则：支持规则定义、版本、生效区间、发布/审批和引用快照；订单、返点、分期创建时保存规则版本与参数快照。
- 人员与团队：管理员可创建、更新、停用、重置密码、设置数据范围、资金池范围和团队归属。
- 标准导入：支持订单、账号、流水、分期、需求五类批次；导入只保存原始行和人工映射，不自动猜测关联。

## 6. 数据与技术约束

1. 金额数据库类型为 `DECIMAL(18,2)`，接口金额以字符串传输，禁止以浮点数参与核算。
2. 所有写操作通过 Service 事务完成，并写入审计日志；路由层不直接修改模型。
3. 业务事件、现金流、库存状态和分期状态必须保持可追溯关联；已登记事实不可直接编辑或删除。
4. API 统一返回 `{code, message, details}` 错误结构；参数校验失败返回 422，并给出字段路径。
5. 请求带 `X-Request-ID`，后端在响应中回传；错误和审计记录使用同一请求上下文。
6. 生产环境使用 JWT 登录和令牌撤销；开发环境仅保留本地角色直通用于权限联调。
7. 数据库通过 Alembic 管理，启动前必须完成迁移和基础种子；历史导入批次保留原始行、映射依据和回滚记录。

## 7. 当前开发成果与缺口

### 7.1 已形成闭环

工作台、四类业务建单、订单事件、库存查询与售出、分期收款与交付、客户/合作方、资金池总览与押金、R1–R5 报表、登录/改密/角色权限、活字段、经营规则版本、标准导入工作台已具备前后端主要链路。

### 7.2 已有后端能力但前端入口不足

独立收付款审核/冲销、池间划转、日对账、返点独立工作台、质量异常工单、审计日志、通知中心、附件中心、全局搜索、客户需求池、报表导出按钮、业务类型和资金池完整编辑/路由配置均已有部分接口或组件基础，但未全部形成可发现的前端流程。

### 7.3 后续迭代顺序

| 优先级 | 迭代内容 | 完成定义 |
|---|---|---|
| P0 | 补齐当前主流程测试与财务恒等式回归 | 后端契约、前端构建、关键业务 E2E 均通过 |
| P1 | 资金审核/划转/对账、返点工作台、质量中心、需求池 | 有一级入口、权限、错误态、审计和验收用例 |
| P2 | 审计/通知/附件/搜索、导出入口、主数据完整维护 | 统一接入订单、客户、资金和设置页面 |
| P3 | 数据范围增强、池账户、路由影响预览和自动提醒 | 在不改变现有事实模型的前提下提升效率 |

## 8. 验收标准

### 8.1 功能验收

- [ ] 六个一级导航页面和用户中心可按角色正确显示。
- [ ] 可分别创建 HS、TH、DG、DFQ，并为订单绑定客户/合作方、账号和资金路由。
- [ ] 订单事件登记后，订单状态、账号状态、资金流水和分期状态保持一致。
- [ ] 库存账号可筛选、查看完整执行明细、售出、寄售、登记返点和导出。
- [ ] 分期收款只允许首付/期次入账，未结清不可交付。
- [ ] 客户联系方式按权限脱敏/显隐，停用与合并保留历史关系。
- [ ] 返点新建必须绑定来源订单，分次到账的 gross、fee、net 勾稽一致。
- [ ] R1、R2、R3、R4、R5、订单利润在前后端显示同一口径，并可按权限取数。

### 8.2 数据与安全验收

- [ ] 金额精度、统一错误结构、422 字段校验、请求号和审计日志通过测试。
- [ ] 角色越权访问在后端被拒绝；前端隐藏按钮不能绕过后端权限。
- [ ] 已登记事件、已审核流水、已结算返点、已发生分期收款不能被直接覆盖。
- [ ] 导入批次可查看原始行、映射依据、未关联划转、提交结果和回滚记录。

### 8.3 当前未完成项验收

- [ ] 资金审核、池间划转和日对账形成前端闭环。
- [ ] 质量异常、客户需求、通知、审计、附件、搜索形成可发现页面。
- [ ] 报表导出按钮与接口、数据范围和导出审计联通。
