## 1. 文档目的

本 PRD 只描述当前代码已经形成的产品能力、数据对象、用户流程和下一步缺口。只有当前代码、接口契约和当前验收结果能证明的能力才写入“已实现”；没有被当前实现证明的内容列入缺口或后续计划。

系统定位为工作室经营台账：统一记录业务订单、账号库存、资金流水、分期回款、返点、客户与合作方，并提供经营报表、权限控制、审计和标准导入能力。系统不接支付通道，不自动打款，所有资金事实由用户录入或由已登记业务事件生成。

## 2. 用户与权限

系统支持登录、退出登录、修改密码、首次登录强制改密和基于角色的后端鉴权。前端按钮显隐只用于体验，不能替代后端权限校验。

| 角色 | 主要能力 |
|---|---|
| 系统管理员 `admin` | 全部主数据、业务、资金、报表、导入、用户和团队管理 |
| 业务经办人 `operator` | 客户、合作方只读/建档/更新；创建和更新订单；发布业务事件；查看资金与报表 |
| 财务 `finance` | 资金池、押金、划转及资金相关事件；查看客户、合作方、报表 |
| 业务审核人 `auditor` | 查看资金；处理订单异常；审批经营规则；查看合作方和报表 |
| 经营查看人 `viewer` | 只读查看资金和经营报表 |

权限点覆盖客户、合作方、订单、业务事件、资金、押金、划转、规则、活字段、审计、报表、导入、用户和业务类型等领域。用户还可配置数据范围、所属资金池和团队。

## 4. 核心业务功能

### 4.0 业务、类型与增值服务边界

产品分类拆成三个层级，必须分别记录“业务”“类型”和“增值服务”，不能把三者混称为同一个业务类型：

| 层级 | 取值 | 含义 | 当前实现 |
|---|---|---|---|
| 业务 | 自营 `SELF` / 分销 `DISTRIBUTION` | 经营模式，描述账号和资金由谁承担、库存如何归属 | 订单列表和库存台账可按业务筛选 |
| 类型 | 回收 `HS` / 提号 `TH` / 代挂 `DG` | 主业务类型，描述当前做的核心交易 | 工作台和建单弹窗分别提供三类入口 |
| 增值服务 | 分期出售 `STOCK_SALE` / 代分期 `ADVANCE_PURCHASE` / 提号分期 `PICKUP_SALE` / 代挂分期 `CONSIGNMENT_SALE` | 在主业务之外提供的分期收款服务；HS 仍保留自营库存处置链路 | 分期合约按业务类型独立编码，不把分期收款混入三类主业务类型 |

具体归属关系如下：

| 产品分类 | 订单/合约编码 | 业务模式 | 说明 |
|---|---|---|---|
| 自营·回收 | 订单 `HS` | `SELF` | 工作室买入账号，进入 `RECOVERY` 自营库存 |
| 分销·提号 | 订单 `TH` | `DISTRIBUTION` | 从同行/供货方取得账号，形成 `PICKUP` 提号实体；不计入自营库存资产 |
| 分销·代挂 | 订单 `DG` | `DISTRIBUTION` | 受托销售账号，形成 `CONSIGNMENT` 实体；只记录卖出金额、订单利润、寄售方和平台，不配置抽成比例、金额来源或自动结算公式 |
| 自营·分期出售 | 合约 `STOCK_SALE`，不新增业务订单 | `SELF` | 已买入的 HS 自营库存分期卖给客户；分期收齐后交付 |
| 增值服务·代分期 | 订单 `DFQ` + 合约 `ADVANCE_PURCHASE` | `DISTRIBUTION` | 客户向本方借款并按合约分期还款，按实际情况登记付款与收款；DFQ 在系统里有独立订单编码，但产品分类属于增值服务，不列入“类型”的三项 |

最终归属口径固定为：

| 产品 | 归属 |
|---|---|
| 回收 | 自营·类型 |
| 提号 | 分销·类型 |
| 代挂 | 分销·类型 |
| 分期出售 | 自营·增值服务 |
| 代分期 | 分销·增值服务 |

系统必须按以上归属处理展示、筛选、库存、资金和报表口径：

- `SELF` 只能承载自营回收，以及从自营回收库存发起的分期出售；
- `DISTRIBUTION` 承载分销提号、分销代挂和分销代分期；
- `STOCK_SALE` 是自营库存的增值服务合约，不能被记录成 `DFQ`；
- `DFQ` 是分销代分期的独立订单和增值服务合约，不能关联库存账号，也不能计入自营库存售出收入；
- 错误组合必须由后端拒绝，前端只负责按字典提供可选项和提示。

`capital_type`（`STOCK`、`ZERO`、`CREDIT`）是核算维度，不等同于业务、类型或增值服务：它决定资金和成本如何处理，允许按单覆盖，但不能改变产品分类。库存字段使用 `business_mode` 保存业务，使用 `inventory_type` 保存来源（`RECOVERY`、`PICKUP`、`CONSIGNMENT`）。

### 4.1 工作台

工作台提供三类主业务和分销代分期的快速建单入口；自营分期出售从自营库存账号的售出入口发起，不新建一张独立主业务订单：

| 分类 | 编码 | 页面名称 | 当前建单入口 |
|---|---|---|---|
| 自营·类型 | `HS` | 回收 | 自营回收 |
| 分销·类型 | `TH` | 提号 | 分销提号 |
| 分销·类型 | `DG` | 代挂 | 分销代挂 |
| 分销·增值服务 | `DFQ` | 代分期 | 分销增值服务·代分期 |

增值服务分为四类：`STOCK_SALE`（自营分期出售）、`DFQ + ADVANCE_PURCHASE`（代分期）、`TH + PICKUP_SALE`（提号分期）和 `DG + CONSIGNMENT_SALE`（代挂分期）。工作台还提供“售出库存账号”入口和进行中/已完成业务数量摘要。摘要只来自订单列表，不重复实现经营报表。

订单类型接口统一返回 `business_mode`、`business_type`、`value_added_service` 分类字段；前端筛选、订单详情和报表使用这些后端字段，不再从 `capital_type` 或库存字段推断业务归属。

### 4.2 订单与业务事件

订单创建支持业务类型、交易日期、账号快照或库存账号、负责人、资金类型、备注、活字段、客户角色和合作方角色；代分期仍可在建单时提交首笔付款和分期合约。提号、代挂不在建单时勾选分期，必须到出售动作中选择全款或分期并建立对应合约。代挂不再使用独立抽成结算字段。

订单状态为 `ACTIVE`、`COMPLETED`、`CANCELLED`。订单号按业务类型独立递增，创建后不可由前端修改。订单详情包含：

- 业务事件时间线：`BUY`、`COST`、`SELL`、`PAYMENT`、`DELIVER`、`CANCEL`、`REFUND`；每条事件记录操作人和发生日期；
- 动作性质统一为买号、售出、运营：回收/提号/代挂归入买号，运营人员按订单配置；公司只作为利润归属。售出统一绑定实际操作人：全款售出记录 `SELL`，分期出售记录合约及操作人，并通过 `PAYMENT` 收款；
- 关联订单、资金流水、返点、分期合约/期次、附件和审计摘要；
- 订单编辑、取消和事件登记；
- 业务台账的“操作”列和订单详情统一通过“更多”菜单提供利润分配、登记退款、取消交易；行级操作会重新读取订单最新状态，避免使用列表快照执行资金动作；
- 资金池路由：显式指定资金池优先，否则使用业务默认路由。

金额类业务事件登记后生成对应资金事实；交付事件不产生现金流。业务事件按类型驱动订单、库存和分期状态；已登记事实只能通过冲销或补充事件修正。

#### 4.2.1 动作性质与人员

动作性质用于区分订单中由谁完成哪类业务工作，并作为利润分配项。每项动作性质均关联人员：

| 动作性质 | 业务含义 | 人员绑定 |
|---|---|---|
| 买号 `BUY` | 回收、提号、代挂均属于买号动作 | 绑定对应业务的操作人；当前回收、提号取已登记的买号事件操作人，代卷取建单操作人 |
| 售出 `SELL` | 账号售出统一使用标准售出动作；代挂和分期出售不另设售出名称 | 绑定执行售出的操作人；全款售出取售出事件操作人，分期出售取创建分期合约的操作人 |
| 运营 `OPERATION` | 订单的运营工作 | 不建立独立运营动作台账；在每张订单的利润分配中选择运营人员和比例 |

公司是利润归属方，不是动作性质，也不绑定个人。分期是收款方式，不是独立动作性质。订单事件中的成本、回款、交付、退款和冲销用于记录具体业务或资金事实，不因此新增利润分配动作性质。

利润分配按订单配置买号、售出、运营和公司归属四项，比例合计 100%。买号收益绑定买号操作人，售出收益绑定售出操作人，运营人员按订单选择，公司归属不绑定个人。分配基数为订单利润，即售出金额减买入成本和直接成本；返点收益单独核算，不参与分配。库存售出订单可追溯同一账号的买号事件；分期出售根据分期合约登记人绑定售出人员。

退款规则要求交付前使用取消或冲销，交付后可登记全额或部分退款；原因和责任方必填，退款不得超过已收减已退，原收入与收款事实保留。取消交易完成后必须显示实际退款金额，并按原资金池回执；`REFUND` 校验交付状态、退款上限及责任方，支持已完成订单退款。

### 4.3 账号库存

库存台账以账号为管理对象，展示来源订单、业务模式、库存类型、游戏类型、账号标识、平台、状态、成本和未售时长。支持：

- 按状态、业务模式、库存类型和关键词筛选；
- 展开查看执行明细、订单事件、资金流水、返点和合作方；
- 全款售出、寄售、返点登记；
- 编辑账号资料、描述、图片和活字段；
- 导出当前筛选结果 CSV。

账号状态为 `IN_STOCK`、`INSTALLMENT`、`SOLD`、`VOID`。库存类型为 `RECOVERY`、`PICKUP`、`CONSIGNMENT`；`PICKUP` 可追踪但不允许通过库存售出动作重复售卖。账号密码默认不在普通列表返回，只有具备相应权限的详情读取才可展示。

### 4.4 分期与回款

系统支持两类分期合约：

| 合约类型 | 来源 | 页面动作 |
|---|---|---|
| `STOCK_SALE` | 已进入库存的自营售出 | 每一期可单独选择服务费；查看期次、登记收款、结清后交付 |
| `ADVANCE_PURCHASE` | `DFQ` 代分期订单 | 客户借款后按期还款，每一期均包含分期收益/服务费；查看期次、登记还款、结清后换绑交付 |
| `PICKUP_SALE` | `TH` 提号订单 | 分期收款、逾期/违约、结清后交付 |
| `CONSIGNMENT_SALE` | `DG` 代挂订单 | 分期收款、逾期/违约、结清后交付 |

合约记录本金、首付、期数、首期日期、服务费计算基数、交付方式和备注；服务费按期记录：`ADVANCE_PURCHASE` 代分期每一期必须有分期收益/服务费，`STOCK_SALE` 分期出售每一期可单独选择服务费，也可以为零。每一期可单独配置服务费利率，合同层可提供默认利率；每期利率与计算基数配套：`FIXED_PRINCIPAL` 固定本金（按合约本金计算，每期基数不变）或 `OUTSTANDING_PRINCIPAL` 实际剩余本金（按未收本金计算，已收本金增加后，后续服务费基数同步减少）。每期应收由当期本金和当期服务费组成。逾期费用可手工填写，非必填，不按逾期天数或比例自动生成。具体利率数值和金额算法由后续业务规则确认。收款必须选择首付或期次并记录日期；只有 `SETTLED` 合约可以执行交付。

分期状态和处置动作按以下规则执行：

| 项目 | 当前定义 |
|---|---|
| 逾期 `OVERDUE` | 期次到期日早于业务日期，且 `received_amount + waived_amount < due_amount` 时，系统将期次标记为逾期；合约存在未结清逾期期次时进入 `OVERDUE`。逾期只改变状态，不新增或冲销应收金额。 |
| 减免 `WAIVED` | 对未收期次登记经授权的减免金额，原 `due_amount` 不改写，只累计 `waived_amount` 并记录原因和审计。减免后收款额与减免额合计达到应收时，期次为 `WAIVED`；部分减免仍保留未收余额。减免不自动生成资金流水。 |
| 展期 | 展期是期次处置动作，不是独立状态。只能对未收、未减免完成的期次执行；更新 `due_on`，保留原到期日、操作人和原因。逾期期次展期后恢复为 `PENDING`，后续按新到期日重新判断。 |
| 违约 `DEFAULTED` | 违约是合约级状态，只能从 `OVERDUE` 合约登记并填写原因。登记后保留未收期次和原应收，不能直接交付或自动核销。 |
| 逾期后回收 | 四类分期合约均可回收关联账号。DFQ 若只有订单快照，首次回收时将快照转成自营库存账号；HS/TH/DG 则恢复原关联库存账号并进入对应库存类型。 |
| 逾期后出售 | 回收完成后，通过库存中心选择全款或分期出售，形成新的出售事实；全款出售生成 `SELL`，分期出售生成新的分期合约，系统均根据同一账号最近一次未转售的回收处置自动生成 `RESELL` 关联。原分期应收不被新出售金额冲销。 |

期次状态为 `PENDING`、`PARTIAL`、`PAID`、`OVERDUE`、`WAIVED`；合约状态包括 `PENDING`、`ACTIVE`、`OVERDUE`、`SETTLED`、`DELIVERED`、`DEFAULTED`、`CANCELLED`。

减免和违约沿用现有 `order.exception.approve` 异常处置权限，不新增专门审批角色，也不增加额度判断。展期不设单期次数和最长天数限制，只校验新到期日晚于原到期日并要求填写原因。回收后的资产保管期限和转售定价不预设固定规则，只记录实际处置事实并沿用现有库存与订单核算口径；转售收入及相关收益归公司。

### 4.5 客户与合作方

客户档案支持客户编号、名称、联系人、手机、微信、QQ、来源、备注、标签和活字段。联系方式默认脱敏，按权限显式读取并记录审计；重复联系方式只提示候选，不阻止建档。

客户详情展示订单参与关系、分期合约、汇总指标和审计记录。客户可停用或合并；`DISABLED`、`MERGED` 客户不能作为新订单参与方。

合作方与客户分开建模，类型为 `PEER`（同行）、`SUPPLIER`（供货方）、`PLATFORM`（平台），支持建档、启停和在订单中绑定角色。

### 4.6 资金中心

资金池是可配置主数据，字段包括代码、名称、用途类型、归属和状态。资金归属为 `OWNED`、`CUSTODY`、`THIRD_PART`；停用池保留历史流水，不允许破坏历史归属。

资金池总览展示收入、支出、转入、转出、现金余额、押金占用和可用余额。资金流水采用三层属性：

| 层级 | 当前采用的定义 |
|---|---|
| 资金性质 | `BUSINESS` 本方经营资金、`EXTERNAL` 外部/受托资金、`INTERNAL` 内部资金 |
| 现金方向 | `IN` 收入流入、`OUT` 支出流出 |
| 核算属性 | 具体归类收入、成本、费用、收款、付款、返点、押金或划转 |

资金性质、现金方向和以下核算属性均已确认：

| 核算属性 | 定义 | 典型场景 |
|---|---|---|
| `SELF_REVENUE` | 自营销售或自营分期回款收入 | HS 售出、`STOCK_SALE` 分期回款 |
| `SELF_DIRECT_COST` | 自营账号买入及订单直接成本 | HS `BUY`、订单 `COST` |
| `TH_DIRECT_COST` | 为客户需求向同行采购账号形成的分销直接采购成本 | TH 向同行买号 |
| `TH_REVENUE` | 将按客户需求采购的账号卖给客户形成的分销销售收入 | TH 向客户售号 |
| `DFQ_PRINCIPAL` | 代分期借款发放与本金还款的核算分类，不等同于收入或利润 | DFQ 付款、客户本金还款 |
| `SERVICE_REVENUE` | 已确认的服务费、佣金等收入 | DFQ 已确认服务费；DG 仅在实际结算口径确认后使用 |
| `REBATE_INCOME` | 买号或售出返点到账 | `REBATE` 资金流水 |
| `OPERATING_EXPENSE` | 与具体订单无直接对应的日常经营费用 | 平台费、人工、办公等 |
| `DEPOSIT` | 外部/受托押金的占用、释放或损失 | `DEPOSIT_HOLD`、`DEPOSIT_RELEASE` |
| `EXTERNAL_FUNDING` | 非经营性的外部资金注入或退出 | 股东注资、借款 |
| `INTERNAL_TRANSFER` | 资金池或账户之间的内部调拨 | `TRANSFER` |
| `REVERSAL` | 对原资金事实的反向冲销 | 流水、返点或费用冲销 |

外部/受托资金的所有权不属于本方，例如代客户暂存的款项和客户/合作方押金；DFQ 的付款和本金收款按现有实现归 `BUSINESS`，使用 `DFQ_PRINCIPAL`，不能直接当作收入或利润，付款和收款通过现金方向及来源事件区分。TH 是客户需求驱动的分销直接买卖：向同行采购形成 `TH_DIRECT_COST`，卖给客户形成 `TH_REVENUE`，不归入泛化的“业务往来”。服务费、佣金和返点实际归本方后，按经营资金和对应收入属性记录。核算属性不替代资金性质和现金方向；同一核算属性可根据业务动作产生收入或支出方向，但必须关联来源订单、事件、押金或划转记录。

当前前端已提供流水查询、新增、审核、拒绝、冲销、押金占用与部分/全部释放、池间划转、日对账和差异核销；后端接口、权限门控和异常提示已接入。

返点作为资金中心的一项核算属性（不单独拆分产品章节）：

返点不单独作为业务类型或资金性质，而是直接挂入资金流水的核算属性：返点实际归本方时使用 `BUSINESS + IN + REBATE_INCOME`；返点冲销使用 `BUSINESS + OUT + REVERSAL`，并通过 `reversal_of_id` 关联原流水。返点金额进入经营收入统计，但必须与订单收益和平台手续费分开核算，避免重复计入销售收入。

业务口径：返点是收入，返点收益为返点金额；平台手续费作为成本或费用单独记录，不从返点收益中扣除。报表按返点金额展示；返点结算分别生成收入流水和平台手续费支出流水，冲销时分别关联原流水。

返点业务事实仍必须关联来源订单，记录返点类型 `BUY`/`SELL`、渠道、费率、基数、预计/实际日期和状态。到账支持多次结算，每次记录返点金额、平台手续费、回款池、资金性质、现金方向、核算属性和收入/费用流水关联；只有审核通过的结算才生成 `REBATE_INCOME` 资金流水。

返点状态为 `OPEN`、`PARTIALLY_SETTLED`、`SETTLED`、`VOID`。库存详情提供返点登记入口，返点工作台负责登记与结算，资金中心负责查看其资金属性和冲销结果，并受 `rebate.read`、`rebate.create`、`rebate.settle` 权限控制。

### 4.7 经营报表

经营中心提供以下只读报表：

| 报表 | 内容 |
|---|---|
| R1 库存健康 | 在库账号、买入成本、附加成本、占用成本、持有天数 |
| R2 月度损益 | 销售收入、账号直接成本、运营费用、返点和经营利润，可按日期区间筛选；返点收益按返点金额统计，平台手续费计入费用 |
| R3 提成对账 | 人员、订单、利润基数、费率、应付、已付和差异，可按日期区间筛选 |
| R4 资金日报 | 各资金池期初、收入、支出、押金、现金余额和可用余额 |
| R5 业务损益 | 各业务订单数、主营收入、主营成本、主营利润、已结算返点、待结算返点和完整收益；页面“未归集返点”指已关联订单的待结算金额 |
| 资金属性分析 | 已审核流水按资金性质、核算属性、现金方向和资金池账户聚合，展示发生额与净方向金额 |
| 订单利润 | 订单收入、直接成本、返点和净利润，可按日期区间筛选 |
| 数据中心 | 资金池和订单的快捷分析入口 |

报表接口支持按权限范围取数，并提供 CSV 导出接口；经营中心已提供七类业务/资金报表导出按钮、统一起止日期筛选和 `report.export` 权限门控。

### 4.8 设置与可配置能力

- 业务类型：读取业务类型、资金性质和启停状态；后端支持创建、编辑、停用和路由配置，前端支持名称/说明/排序编辑、启停和路由影响预览。
- 资金池：前端支持新增、名称/用途/归属/备注编辑和启停；后端支持编辑、停用、删除保护和余额查询。

- 标准导入：支持订单、账号、流水、分期、需求五类批次；导入只保存原始行和人工映射，不自动猜测关联。

## 6. 数据与技术约束

1. 金额数据库类型为 `DECIMAL(18,2)`，接口金额以字符串传输，禁止以浮点数参与核算。
2. 所有写操作通过 Service 事务完成，并写入审计日志；路由层不直接修改模型。
3. 业务事件、现金流、库存状态和分期状态必须保持可追溯关联；已登记事实不可直接编辑或删除。
4. API 统一返回 `{code, message, details}` 错误结构；参数校验失败返回 422，并给出字段路径。
5. 请求带 `X-Request-ID`，后端在响应中回传；错误和审计记录使用同一请求上下文。
6. 生产环境使用 JWT 登录和令牌撤销；开发环境仅保留本地角色直通用于权限联调。
7. 数据库通过 Alembic 管理，启动前必须完成迁移和基础种子；历史导入批次保留原始行、映射依据和回滚记录。
8. 资金流水必须同时具备资金性质、现金方向和核算属性；TH 向同行采购归 `BUSINESS + OUT + TH_DIRECT_COST`，向客户售出归 `BUSINESS + IN + TH_REVENUE`；DFQ 付款和本金收款归 `BUSINESS + DFQ_PRINCIPAL`，通过现金方向区分，不直接计入收入或利润；客户/合作方押金归 `EXTERNAL + DEPOSIT`。
