## 1. 视觉方向

| 维度 | 设计要求 |
|---|---|
| 气质 | 冷静、专业、可审计；让金额、状态、异常和操作结果成为视觉重点 |
| 主色 | 使用高可读性的商务蓝，而非科技霓虹蓝或紫蓝渐变 |
| 材质 | 以干净表面、细边框和轻投影区分层级；玻璃效果只能用于导航或浮层，不能遮蔽数据 |
| 信息密度 | 适合长时间看表与连续录入；通过对齐、分组和留白组织信息，不依赖大卡片或装饰图形 |
| 品牌表达 | 蓝色聚焦于当前定位、可执行操作和可交互信息；页面其余部分保持中性 |

**设计签名**：深蓝色的当前定位与操作焦点，配合近白数据表面和稳定的数字排版；不是“蓝色大屏”。

## 2. 色彩系统

### 2.1 核心色板

| 角色 | 浅色模式 | 深色模式 | 用途 |
|---|---:|---:|---|
| 品牌主蓝 | `#0A63D8` | `#6AAEFF` | 主按钮、当前导航、主链接、图表首序列 |
| 品牌深蓝 | `#0757C7` | `#9BC9FF` | 焦点环、重要链接、强调文字、按钮渐变起点 |
| 轻蓝选择底 | `#EAF3FF` | `#13253B` | 选中行、当前菜单、轻量提示 |
| 蓝色描边 | `#B7D5FB` | `#7DB5F4` | 焦点、选中边框、可编辑状态 |
| 页面底 | `#F2F2F7` | `#0B1420` | 应用最底层背景 |
| 内容表面 | `#FFFFFF` | `#14263E` | 卡片、表格、抽屉、弹窗 |
| 主文字 | `#1C1C1E` | `#EAF3FF` | 标题、正文、关键数值 |
| 次文字 | `#48484A` | `#C3D2E4` | 标签、解释、辅助信息 |

| 语义色 | 浅色模式 | 深色模式 | 使用约束 |
|---|---:|---:|---|
| 成功 | `#14724B` | `#34D399` | 已完成、已到账、校验通过；同时显示文字或图标 |
| 警告 | `#B45309` | `#FBBF24` | 待处理、临期、需关注；不能用于普通次操作 |
| 错误 | `#B23B3B` | `#F87171` | 失败、超限、逾期、不可提交；必须说明原因与修复方式 |
| 信息 | `#0A84FF` | `#64A8FF` | 中性通知、帮助、可钻取信息 |

### 2.2 色彩使用规则

| 使用场景 | 应这样做 | 不应这样做 |
|---|---|---|
| 主操作 | 每个局部任务只保留一个蓝色实底主按钮 | 一行摆放多个同等蓝色按钮 |
| 选中状态 | 蓝色文字/图标 + 浅蓝底 + 必要时描边 | 只改变色相，不提供文字或形状差异 |
| 金额 | 默认使用主文字；异常才叠加语义标签 | 把所有收入染绿、所有支出染红 |
| 状态标签 | 淡色背景、语义色文字、简短状态名 | 使用高饱和实底标签铺满表格 |
| 渐变 | 仅限主按钮和极少量品牌强调区域 | 卡片、表格、内容背景使用大面积渐变 |
| 紫色兼容变量 | `--violet-*` 变量已于 2026-11 前**全部删除**（`tokens.css` 实测 0 处）；如需紫色语义必须按维护规则重新定义 | 以已删除的 `--violet-*` 名称为依据写样式，或新增紫色 |

### 2.3 对比度基线

| 组合 | 对比度 | 结论 |
|---|---:|---|
| `#0A63D8` / 白色 | 5.54:1 | 可用于主蓝色文字或按钮底 |
| `#0757C7` / 白色 | 6.57:1 | 可用于强调文字和按钮渐变端点 |
| `#1C1C1E` / 白色 | 17.01:1 | 可用于正文和关键数字 |
| `#EAF3FF` / `#0B1420` | 16.53:1 | 深色模式主文字可读 |
| `#6AAEFF` / `#0B1420` | 8.03:1 | 深色模式主蓝可读 |

## 3. 排版与数字

| 类型 | 建议样式 | 规则 |
|---|---|---|
| 页面标题 | 20px / 600 | 每页一个；不使用全大写或装饰字体 |
| 区块标题 | 16px / 600 | 用于卡片、表格、分组标题 |
| 正文与表格 | 正文 13px / 表头 13px·600 / 表格正文 15px | 正文基线取 Footnote 13（2026-09-03 裁定：正文小于导航）；表格正文用 Subheadline 15；不使用细字重 |
| 辅助信息 | 12px / 400 | 仅用于时间、说明、次级标签，不承载关键决策 |
| 字号来源 | 一律取 `--fs-*` / `--font-*` 长度型令牌 | rem 锚点 = `:root` 106.25%（17px ≈ iOS Body）；**禁止手写 px 字号**，`ui_guards.mjs` 会拦截 |
| 金额与数量 | 继承正文或区块标题 / `tabular-nums` | 金额右对齐，小数位规则一致，负数使用负号而非只变色 |
| 编号与代码 | 等宽或可区分字符的系统字体 | 可复制；过长时截断并提供完整值悬停提示 |

## 4. 间距、表面与层级

| 层级 | 视觉处理 |
|---|---|
| 应用背景 | 页面底色，不参与信息分组 |
| 一级表面 | 白色/深色内容表面，轻边框，几乎无投影 |
| 浮层表面 | 抽屉、弹窗、下拉菜单使用更清晰的边界与适度投影 |
| 当前或可编辑状态 | 轻蓝底、蓝色描边或焦点环，不使用过重阴影 |
| 危险状态 | 使用语义色边框/图标/文字；背景保持克制，避免整块纯红 |

| 尺寸 | 规范 |
|---|---|
| 页面外边距 | 24px |
| 区块间距 | 16px |
| 卡片内边距 | 16px |
| 表单项间距 | 12px |
| 紧凑表格行内间距 | 8px |
| 控件圆角 | 输入/按钮 10–11px（antd 主题 `borderRadius: 10`，自定义控件 `--radius-control: 11px`）；浮层 12px、玻璃浮层 18px。`--radius-pill: 999px` **仅用于状态标签、chip 与状态点**，不用于输入框和按钮 |
| 桌面可点击区域 | 常用控件建议不小于 32×32px；最小不小于 28×28px |

## 5. 组件规范

| 组件 | 视觉与状态要求 |
|---|---|
| 按钮 | 主按钮为品牌蓝实底白字；次按钮使用描边/文字样式；禁用态降低对比与饱和但仍可辨；危险按钮使用错误色且文案明确 |
| 输入框 | 默认中性边框；聚焦使用深蓝焦点环；错误时边框、说明文字和图标同时变化；不以 placeholder 代替字段标签 |
| 下拉与日期选择 | 保持与输入框相同高度、边框和焦点；已选值优先于占位符显示 |
| 标签 | 高度一致、文字不小于 12px；语义标签采用淡底，筛选标签可关闭且关闭命中区清晰 |
| 表格 | 表头与正文对比明确；宽表支持横向滚动、固定关键列、隔行浅底；悬停行不覆盖选中行状态 |
| 卡片 | 只服务于摘要、分组或待办；不把每一个字段包进独立卡片 |
| 抽屉与弹窗 | 背景和内容层级清晰；关闭按钮可见；同一时刻只承载一个短任务；危险确认默认聚焦“取消” |
| 提示与通知 | 成功使用短暂轻提示；错误尽量在字段/对象旁显示；仅不可逆或会造成重大影响的操作使用阻断确认 |
| 空状态 | 使用简单图标、事实描述与一个下一步动作；不使用插画抢夺业务注意力 |

## 6. 图标、图表与数据可视化

| 元素 | 规范 |
|---|---|
| 图标 | 使用同一套线性图标，尺寸通常为 16px 或 20px；图标按钮提供文字标签或可访问名称 |
| 图表序列 | 默认顺序：品牌蓝 `#0A63D8`、信息蓝 `#0A84FF`、青色 `#30C4B0`、绿色 `#34C759`、琥珀色 `#F59E0B` |
| 图表语义 | 颜色仅用于区分序列；必须有图例、悬停数值和可读标签；重要趋势不能只靠颜色表达 |
| 数据强调 | 仅突出需要决策的单一数值或异常点；不要让每个指标都使用大字号和高饱和颜色 |
| 空图表 | 明确缺少的时间范围或筛选条件，并提供调整入口 |

## 7. 动效、主题与无障碍

| 维度 | 规范 |
|---|---|
| 动效 | 只用于打开/关闭浮层、加载完成和状态切换；短、可预测、可中断；不以动效传递唯一信息 |
| 深色模式 | 默认跟随系统，**同时提供顶栏三态切换（跟随系统 / 浅色 / 深色）**，选择持久化在 `localStorage`（键 `heijin-theme-mode`）；`data-theme` 打到 `documentElement`，antd 侧由 `darkAlgorithm` 同步；每个组件必须同时检查浅色和深色表现 |
| 透明度 | 毛玻璃只用于非数据承载的导航或中性浮层；降低透明度时退化为不透明表面 |
| 对比度 | 正文最少 4.5:1，大字最少 3:1；小字号不使用轻字重 |
| 键盘与焦点 | 焦点环可见；键盘顺序符合视觉顺序；弹窗关闭后焦点回到触发控件 |
| 色彩以外提示 | 成功、警告、错误、选中、禁用都至少提供文字、图标、形状或位置其中之一 |
| 缩放 | 浏览器缩放到 200% 时文字、控件、错误信息和关键操作仍可阅读与操作；表格可横向滚动 |

## 8. 视觉验收清单

| 编号 | 验收项 | 判定标准 |
|---|---|---|
| UI-01 | 蓝色主题 | 没有紫色主题视觉；主色、选中态、焦点与深色模式均来自现有令牌 |
| UI-02 | 层级清晰 | 标题、正文、辅助信息、表面与浮层能在 3 秒内辨别层级 |
| UI-03 | 数据易读 | 数字对齐一致；表头、状态、选中行、异常信息不互相遮挡 |
| UI-04 | 语义准确 | 成功/警告/错误均有文字或图标辅助，普通金额不被滥用语义色 |
| UI-05 | 组件一致 | 按钮、输入、标签、表格、抽屉和提示的圆角、字号、焦点与禁用态一致 |
| UI-06 | 双主题 | 浅色与深色下，文字、边框、浮层、图表、禁用态和焦点均可读 |
| UI-07 | 无障碍 | 键盘焦点、缩放、降低透明度和减少动效均有可用表现 |

## 9. 维护规则

| 变更 | 规则 |
|---|---|
| 新增颜色 | 先定义语义、浅深色值、使用范围与对比度，再加入令牌；不允许单页专属主题色 |
| 新增组件 | 先复用已有组件状态；确需新增时必须定义默认、悬停、聚焦、禁用、错误和深色状态 |
| 新增图标 | 保持与现有图标的线宽、尺寸、留白一致；禁止使用 emoji 代替业务图标 |
| 视觉例外 | 需要在本文件记录原因与适用范围，不能在页面 CSS 中以硬编码长期保留 |
