## 2. 测试环境与方法

### 2.1 环境

| 项 | 值 |
| --- | --- |
| 前端 | 本项目 `frontend/`，Vite dev server，`http://localhost:5180`（本次临时实例，测试后已关闭） |
| 后端 | `http://127.0.0.1:8123`（在跑实例 PID 14972，库 `backend/data/heijin_erp_v1.db`） |
| 浏览器 | Chromium（Playwright headless），桌面 1440×900 / 平板 768×1024 / 手机 375×812 |
| 代码基线 | 分支 `main`，HEAD `784cc92` |
| 身份 | 开发态直通（`X-Dev-User`），角色 ADMIN |

### 2.2 方法

对 7 个页面场景（工作台、业务中心默认落点、业务台账、客户中心、资金中心、经营中心、设置）逐页自动采集 12 项指标：

1. 布局偏移（PerformanceObserver `layout-shift`，累计 CLS）
2. 文字对比度（自实现 WCAG 相对亮度算法，逐文本节点取有效背景色）
3. 触控目标尺寸 / 可访问名 / 图片 alt / 标题层级
4. 键盘 Tab 序列（前 20 个焦点位）与焦点环可见性
5. 三档视口横向溢出
6. 控制台错误与页面异常
7. 空态与内容渲染量
8. 全站 API 注入 500 后的错误可见性
9. 导航状态保持性
10. 响应式可逆性（1440→375→1440）

### 2.3 已知局限（结论适用边界）

- **不解析 `background-image`**：首轮报告期审计器不解析渐变背景，白字落渐变会被误判低对比度。第二轮巡检脚本已修正——渐变背景按最亮停点（最坏情形）判定，并豁免语义状态色（`ant-tag`），故第二轮对比度失败归 0 不含此类误报。
- 未做屏幕阅读器实机朗读、未做真机触控（iOS/Android）验证。
- 首屏耗时 3.9s 为 **Vite dev 冷编译**结果，**不可作为生产性能指标**；本次不评性能。
- 对比度为静态计算，未考虑浏览器缩放与用户自定义字体。

## 4. 缺陷清单

### P0-1 资金中心整页白屏，且拖垮整个应用外壳

**现象**：进入「资金中心」后页面全白（正文 0 字、侧栏与顶栏一并消失），截图见 `outputs/ux_20261021/funds-desktop.png`。用户唯一出路是刷新浏览器。

**证据链**：

1. 页面异常：`TypeError: cashflows.filter is not a function`（React 错误栈 `<FundsPage>` → `Suspense` → `AppShell`）。
2. 前端消费端：`frontend/src/pools/FundsPage.tsx:95` —— `setCashflows(await cashflowsApi.list({ limit: 500 }))`，把返回值直接当数组。
3. 前端类型声明：`frontend/src/shared/api/catalog.ts:613-623` —— `api.get<Cashflow[]>("/cashflows")`，按**数组**声明。
4. 后端磁盘代码：`backend/app/finance/router.py:252` —— `response_model=list[schemas.CashflowOut]`，返回**数组**。
5. 后端运行态（实测 `curl /api/v1/cashflows?limit=2`）—— 返回 `{"items":[…],"total":N}`，即**分页对象**。
6. 进程状态：PID 14972 于 **10-21 00:09:03** 启动，命令行**无 `--reload`**。

**根因**：运行中的后端进程与工作树代码版本不一致。该进程加载的是「流水服务端分页」改造版（返回 `{items,total}`），而磁盘 `main` 已回到数组契约（该改造提交 `8bc3317` 不在 `main` 祖先链上）。前端按数组消费 → 断言崩溃。属**运行态契约漂移**，非 `main` 源码自身的逻辑错误。

**影响**：资金中心在当前 8123 环境完全不可用；因缺错误边界，崩溃扩散到 `AppShell`，用户丢失导航能力。

**处置建议（三选一，按成本排序）**：

1. **重启 8123 后端**使其加载 `main` 代码（最低成本，一次性）。需注意这是用户常驻服务，应先确认。
2. 前端 `FundsPage` 对返回值做形状兼容（`Array.isArray(x) ? x : x.items ?? []`），提升对后端灰度/回滚的容忍度。
3. 在 `AppShell` 页面槽位外包一层 ErrorBoundary，单页崩溃降级为「本页加载失败 + 重试」，不再整壳白屏。

**建议同时补**：一条跨端契约冒烟用例（真后端 `GET /cashflows` → 断言前端解析函数不抛错），避免同类漂移再次以白屏形式暴露。

### P1-1 移动端全局横向溢出 70px

**现象**：375px 视口下，7/7 页面 `documentElement.scrollWidth = 445 > clientWidth = 375`，页面可左右拖动。截图 `business-default-mobile.png`。

**证据**：`main` 元素自身 `scrollWidth = 375`（不溢出），但 `.app-shell` 为 445；表格 `.ant-table` 计算宽度 680px、左边界 29px，`.ant-table-content` 虽为 `overflow-x:auto`，其祖先未形成约束宽度。

**影响**：移动端出现"幽灵横滑"，表格右列（状态/操作）需横向拖动才能看全；触控误触概率上升。

**建议**：为表格容器链（`.page-slot` / 卡片容器 / `.ant-table-container`）补 `max-width:100%; min-width:0`，把横向滚动收敛到 `.ant-table-content` 内部。

### P1-2 筛选占位符与次要文字对比度 1.83:1（55 处）

| 采样 | 前景 / 背景 | 对比度 | 阈值 | 出现页 |
| --- | --- | --- | --- | --- |
| 「按状态筛选」「按业务筛选」「按类型筛选」 | `rgba(0,0,0,0.25)` / `#fff` | **1.83** | 4.5 | 库存中心 53、客户中心 1、经营中心 1 |
| 「合并」「拉黑」（次要按钮） | `rgba(0,0,0,0.25)` / `#f5f5f5` | 1.82 | 4.5 | 客户中心 2 |
| 分页「•••」 | `rgba(0,0,0,0.25)` / `#fafafc` | 1.83 | 4.5 | 业务台账 1 |

**影响**：筛选区是高频入口，占位符肉眼接近不可见（截图 `business-default-desktop.png` 可见）。深色主题下同类问题为 1.75:1（3 处）。

**建议**：占位符改用令牌化的次级文字色（目标 ≥4.5:1），并在令牌层统一，避免逐页改。

### P1-3 行内操作链接对比度不足（浅色 3.65:1 / 深色 2.25:1，共 80 处）

| 主题 | 采样 | 前景 / 背景 | 对比度 | 出现页 |
| --- | --- | --- | --- | --- |
| 浅色 | 「返点」「编辑」「查看详情」 | `rgb(10,132,255)` / `#fff` | 3.65 | 库存中心 20、业务台账 10 |
| 深色 | 「售出」「寄售」 | 行内次要文字 | **2.25** | 库存中心 50 |
| 深色 | 「返点」「编辑」 | 行内链接 | 3.36 | 库存中心 20 |

**影响**：表格行内操作是业务主操作路径，深色主题下 2.25:1 已接近"看不清"。

**建议**：链接色加深（浅色目标 ≥4.5:1）；深色主题的行内次要文字提亮至 ≥4.5:1。

---

### P1-4 导航不保留页面状态

**实测**：业务中心 → 切到「分期与回款」→ 去客户中心 → 返回业务中心，活动 Tab 变为「库存中心」（`activeBefore=分期与回款`，`activeAfter=库存中心`）。同时 URL 全程不变（`urlChanged=false`）。

**影响**：跨页核对数据时必须重新定位 Tab/筛选；无法把"某个 Tab + 某组筛选"分享或收藏给同事；刷新即回工作台。

**建议**：引入 HashRouter（`#/business?tab=installments` 级别），或至少把一级页 + Tab 写入 `location.hash`。

### P1-5 触控目标小于 24px（26 处）

| 页面 | 数量 | 典型元素 |
| --- | --- | --- |
| 库存中心 | 12 | 行内图标按钮 18×18、筛选输入 140×22 |
| 业务台账 | 11 | 「查看详情」链接 56×17 |
| 客户中心 | 2 | 输入框 154×22 |
| 经营中心 | 1 | 搜索输入 4×28 |

**影响**：移动端误触率高；「查看详情」高度 17px 低于 WCAG 2.5.8 的 24px 最小目标。

**建议**：图标按钮统一 24×24 命中区（可用 `::before` 扩展热区，不改视觉尺寸）。

### P2-1 键盘焦点环缺失（10 处）

库存中心 4 处、业务台账 3 处、客户中心 2 处、经营中心 1 处：这些位置获得焦点后 `outline:none` 且无 `box-shadow`，键盘用户看不到当前焦点（典型为搜索框与自定义下拉触发器）。

**建议**：统一 `:focus-visible` 令牌，禁止业务样式直接写 `outline:none`；可加一条静态门禁（与现有 `ui_guards` 同机制）。

---

### P2-2 控件缺可访问名（12+ 处）

- 分页上一页/下一页按钮（`button.ant-pagination-item-link`）无 `aria-label`；
- 筛选下拉的内部搜索框（`input.ant-select-selection-search-input`）无名称；
- 纯图标按钮（`span.ant-btn-icon` / `button.ant-btn-icon-only`）无 `aria-label`。

**影响**：屏幕阅读器读作"按钮"，用户无法判断功能。

---

### P2-3 侧栏品牌字 11px / 2.03:1

「宜游轩 · 经营工作台」在 6 个页面重复出现，11px + 38% 透明 → 浅色 2.03:1、深色 2.43:1。属装饰性信息，但仍低于可读下限；若保留应提至 12px + ≥4.5:1，否则应移除。

---

### P2-4 500 错误暴露后端原始消息

**实测**：全站 API 返回 `{code:"INTERNAL", message:"boom"}` 时，页面出现 1 个可见告警，文案为「**boom**重新加载」——直接把后端 `message` 原文拼进 UI。

**建议**：前端按错误码映射用户可读文案（"数据加载失败，请稍后重试"），原始 message 只进控制台/日志。业务页目前无错误提示文案统一层。

---

### P2-5 破坏性操作确认近乎缺失（静态取证）

`main` 分支仅 **1 个文件**含 `Popconfirm` / `Modal.confirm`；`loading={` 覆盖 13 个文件；`MoneyInput` 覆盖 8 个文件；仍有 1 处裸 `type="number"`。对照 2026-10-20 已完成的交互整改（`ConfirmButton` / `useAsyncAction` / `InlineError` 共享基建），该批成果**未合入 `main`**。

---

### P2-6 React `findDOMNode` 弃用警告

库存中心与业务台账控制台出现 `Warning: findDOMNode is deprecated`（antd 内部组件）。当前不影响功能，升级 React 19 前需处理。

## 5. 与历史整改的关系（重要事实澄清）

本报告基线为 `main`，**不包含** 2026-10-20 的交互整改批次（`af74c9c`、`881a94d`、`7fbefe3`、`60a08ff`、`8bc3317`、`1864d49`、`21d5636`），这些提交在 `test/speedup-prebundle` 分支，`git merge-base --is-ancestor` 已确证不在 `main` 祖先链上。

因此：

- 第 4 章 P1-4（无路由）、P2-5（确认/loading 缺失）在整改分支上**已闭环**，`main` 上仍开放；
- 资金中心 P0 也源于该分支的后端契约（分页）与 `main` 前端契约（数组）混跑；
- 若要"整改成果真正生效"，需要先把该分支合回 `main`（或反向 cherry-pick），再以本报告脚本复测一轮。
