# ERP 权限矩阵 v1.0

> 权限为“角色权限 + 数据范围”两层。角色决定能否执行动作；数据范围决定可见哪些订单、客户、资金池和报表。默认最小授权，所有高风险动作写审计。

## 1. 角色定义

| 角色 | 典型职责 | 默认数据范围 |
|---|---|---|
| 系统管理员 | 用户、角色、主数据、活字段、客户合并 | 全部 |
| 业务经办人 | 建客户、建单、推进本人业务 | 本人及被授权团队 |
| 财务 | 资金流水、划转、押金、对账 | 被授权资金池 |
| 业务审核人 | 审核例外、DG 混合单、折让/展期 | 被授权团队 |
| 经营查看人 | 查看脱敏经营报表 | 被授权经营范围 |

## 2. 权限点与矩阵

| 权限点 | 管理员 | 业务经办人 | 财务 | 审核人 | 经营查看人 | 说明 |
|---|---|---|---|---|---|---|
| `customer.read` | 是 | 是 | 按范围 | 按范围 | 否 | 默认返回脱敏微信、QQ、手机号 |
| `customer.contact.read` | 是 | 本人范围 | 按范围 | 按范围 | 否 | 读取完整联系方式；访问写审计 |
| `customer.create` / `customer.update` | 是 | 是 | 否 | 否 | 否 | 只能写范围内客户 |
| `customer.contact.write` | 是 | 本人范围 | 否 | 否 | 否 | 改联系方式、备注；记录变更前后值 |
| `customer.merge` | 是 | 否 | 否 | 否 | 否 | 合并须填写原因；来源置 `MERGED` |
| `counterparty.read` / `counterparty.manage` | 是 | 读 | 读 | 读 | 否 | 仅管理员可新增、停用合作方 |
| `order.create` / `order.update` | 是 | 本人范围 | 否 | 审核后编辑例外 | 否 | 必须校验客户/合作方角色 |
| `order.event.post` | 是 | 本人范围 | 回款/付款按范围 | 否 | 否 | 金额事件必须原子生成现金流 |
| `order.exception.approve` | 是 | 否 | 否 | 是 | 否 | 包括 DG 混合单、未结清交付、减免/展期 |
| `finance.read` | 是 | 本人相关 | 按池 | 按范围 | 聚合只读 | 资金详情按资金池范围控制 |
| `finance.transfer` / `deposit.post` | 是 | 否 | 按池 | 否 | 否 | 划转必须原子生成一出一入；双人复核由审批流程实现 |
| `policy.manage` / `policy.approve` | 是 | 否 | 否 | 是 | 否 | 规则只能新版本生效，已用版本不可改 |
| `field-definition.manage` | 是 | 否 | 否 | 否 | 否 | 不得创建核算字段 |
| `audit.read` | 是 | 本人操作 | 本池操作 | 审批相关 | 否 | 审计日志不可编辑或删除 |

## 3. 数据范围与脱敏

| 对象 | 范围字段 | 无完整联系方式权限时显示 |
|---|---|---|
| 客户 | `owner_id` / 团队 | 手机 `138****0000`；微信、QQ 局部遮罩 |
| 订单 | `owner_id` / 团队 | 仅可见范围内订单及关联对象 |
| 资金池 | 授权 `pool_id` 列表 | 无范围则不返回明细或汇总 |
| 报表 | 团队 + 资金池范围 | 无 `finance.read` 时不展示金额明细 |

权限不足统一返回 `403 PERMISSION_DENIED`；越权对象不泄露是否存在，返回 `404 RESOURCE_NOT_FOUND`。联系人字段、客户合并、资金动作、规则审批、订单事件和活字段定义均必须写 `audit_logs`。
