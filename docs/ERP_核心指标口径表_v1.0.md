# ERP 核心指标口径表 v1.0

## 1. 目的

本表先固定“指标由谁产生、谁可以写、报表从哪里读”的治理口径。它不替代数据字典中的字段定义；若字段级定义与本表冲突，须先登记差异并完成裁决，不能在报表层自行解释。

## 2. 指标来源矩阵

| 指标编号 | 指标 | 主责域 | 原始事实 | 可计入条件 | 禁止行为 |
|---|---|---|---|---|---|
| MET-01 | 订单金额 | DOM-02 | 已确认订单及订单业务类型 | 订单有效、金额精确、未作废 | 报表自行修改金额 |
| MET-02 | 订单成本 | DOM-03 | 账号资产成本及成本调整凭据 | 资产成本已确认且关联订单 | 订单页面直接覆盖资产成本 |

## 3. 口径规则

### 3.1 金额

- 所有金额以项目金额类型和两位小数规则处理，不使用浮点参与业务计算。
- 汇总、分摊、冲销和返点必须保留来源记录；舍入差异必须有明确归属。
- 未确认、已撤销或已冲销的流水不得与有效流水重复计入。

### 3.2 时间

- 业务发生日、确认日、入账日和报表统计日必须区分。
- 报表默认按指标定义使用业务发生日或确认日，不允许页面之间各自选择日期字段。
- 跨日补录或冲销必须保留原发生日、实际操作时间和原因。

### 3.3 规则版本

- 新建订单、返点、分期等对象必须保存创建时的规则版本和快照。
- 规则版本的生效区间左闭右开；同一定义下不得重叠。
- 报表重算必须使用对象自身快照，不直接读取当前最新规则。

### 3.4 可追溯性

每个报表指标至少能回到以下一层来源：订单、业务事件、账号资产、资金流水、押金/返点记录、导入批次或质量问题。无法下钻的指标只能标记为“待治理”，不得假装为正式财务口径。

## 4. 指标验收样例

| 样例 | 预期结果 |
|---|---|
| 修改未来返点费率后查看历史订单 | 历史返点和订单利润不变 |
| 重复提交同一笔回款 | 只保留一笔确认流水，重复请求可定位 |
| 订单已创建但资金未确认 | 订单可见，正式回款和利润不计入 |
| 账号成本未确认但订单已交付 | 报表标记成本缺失，不静默计算为 0 |
| 导入行与系统流水金额不一致 | 批次进入差异状态，不能直接确认入库 |
| 资金流水被冲销 | 原流水保留，冲销关系和净额可追溯 |

## 5. 待补数据证据

以下项目进入阶段 1 清查，不在本表中凭空填写数值：

- 订单金额与订单业务类型的完整映射；
- 账号成本的来源、确认时点和调整凭据；
- 回款/押金/返点的流水类别与订单事件对应关系；
- 报表当前使用的日期字段和未确认数据处理方式；
- 历史导入批次与正式业务对象的关联完整率。
