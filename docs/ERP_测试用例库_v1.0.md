| 关联验收编号 | 有明确对应关系时引用 `ACC-F-xxx` 或 `ACC-S-xxx`；没有直接对应项时填写“场景验收” |

## 15. 覆盖率规则

| 覆盖维度 | 最低要求 |
|---|---|
| P0 功能 | 每个 P0 功能至少有 1 条正常用例和 1 条异常/边界用例 |
| 资金功能 | 必须验证流水状态、资金池、现金方向、核算属性和审计 |
| 分期功能 | 必须验证收款、未收、逾期、减免、展期、结清和交付限制 |
| 事实保护 | 已登记事件、已审核流水、已结算返点和已发生收款不得直接覆盖 |
| 权限功能 | 至少覆盖允许操作、拒绝操作和数据范围限制 |
| 报表功能 | 必须验证明细、合计、筛选、导出和权限口径一致 |
| 缺陷闭环 | 失败用例必须有缺陷编号，修复后重新执行并保留历史记录 |

## 18. 前端测试代码分片

前端采用“页面/组件作为测试文件边界，业务功能作为执行分片”的方式：页面相关测试放在对应业务目录，跨页面流程放在业务分片中。当前已完成 P0-P2 页面测试拆分：库存写入、客户活字段、报表明细、分期动作、代挂建单和工作台交互均已形成独立测试文件；`InventoryPanel` 台账详情与职责边界/状态筛选继续共享 mock fixture。页面测试默认使用 `renderLight`，只保留 antd 与 Session 权限上下文；确实验证主题、透明度或 `AppShell` 的用例继续使用完整 `renderApp`。普通点击优先用 `fireEvent`，表单输入和键盘语义仍使用 `userEvent`；必须使用 `userEvent` 时，每个测试复用 `userEvent.setup({ pointerEventsCheck: 0 })` 实例，避免重复初始化和重复 CSS 命中检查。

| 分组 | 覆盖范围 | 执行命令（在 `frontend/` 目录） |
|---|---|---|
| `fast` | 工具函数、API 客户端、基础 fixture 和配置 | `npm run test:fast` |
| `quick` | 登录、首页、设置、订单弹窗、策略和报表关键组件 | `npm run test:quick` |
| React 业务分片 | 库存/资金、客户、销售流程、导入/返点、报表/设置、共享 UI | `npm run test:react -- <测试文件>` |
| 完整分片回归 | 先跑 `fast`、`quick`，再并发执行 React 业务分片 | `npm run test:full` |
| E2E 关键流程 | 登录、业务写入等浏览器端关键流程 | `npm run test:e2e:critical` |
| 前端快速回归 | 类型检查、UI 守卫和关键 E2E | `npm run test:regression:fast` |

| 常用操作 | 命令 |
|---|---|
