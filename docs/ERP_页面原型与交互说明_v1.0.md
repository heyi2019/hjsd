# 宜游轩 ERP · 页面原型与交互说明 v1.0

> **页面依据**：[ERP PRD v1.0](ERP_PRD_v1.0.md) → [功能规格说明书 v1.0](ERP_功能规格说明书_v1.0.md)。本文件收紧页面入口，不删减业务核算、校验与审计规则。

## 1. 设计取向

页面保留六个一级入口。能在同一工作目标下完成的功能，使用 Tab、详情抽屉和操作弹窗承载，不为每个表或每项功能单独建页面。

| 原则 | 约定 |
|---|---|
| 业务统一入口 | HS、TH、DG、DFQ 都从“业务中心→新建订单”进入 |
| 资金统一入口 | 资金池、流水、划转、押金、对账在同一个“资金中心”内切换 |
| 经营统一入口 | 报表与异常不单独占一级菜单，在“经营中心”内切换 |
| 历史收起 | 历史迁移、补录、对账放入“设置→历史参考（P2）”，不出现在常用导航 |
| 三级轻量化 | 三级只允许为 Tab、详情页、抽屉或弹窗；不再增加左侧层级 |

## 2. 一级导航

| 一级菜单 | 路由 | 二级（页面内 Tab） | 主要功能 |
|---|---|---|---|
| 工作台 | `/dashboard` | 今日待办 / 资金提醒 / 风险提醒 | 今日收入支出、押金、TH 未闭环、DFQ 逾期、待审核 |
| 业务中心 | `/business` | 业务作业 / 订单台账 / 库存 / 分期 / 返点 | 四类业务的待办推进、建单、库存成本、分期收款与返点结算 |
| 客户中心 | `/customers` | 客户档案 / 客户需求（P1） | 客户资料、参与角色、关联订单、分期与历史互动 |
| 资金中心 | `/funds` | 总览 / 流水 / 划转 / 押金 / 对账（P1） | 资金池、审核、冲销、划转、押金、对账 |
| 经营中心 | `/operations` | 库存 R1 / 损益 R2 / 提成 R3 / 资金 R4 / 业务 R5 / 异常 | 经营分析与质量问题统一查看 |
| 设置 | `/settings` | 主数据 / 人员权限 / 活字段 / 经营规则（P1） / 历史参考（P2） | 业务、池、路由、人员、字段、规则、审计、历史资料 |

## 3. 业务中心（重新设计）

业务中心不是报表页，也不是单纯订单列表；它是把进行中业务推进到下一步的**作业台**。页面始终保留“新建业务”作为唯一主按钮，其他操作均从待办对象、订单、账号或合约详情发起。

```text
业务中心
├─ 业务作业（默认）   ← 今天需要继续处理的单
├─ 订单台账           ← 查找、筛选和回溯所有订单
├─ 库存               ← 以账号为载体的状态、成本、风险与售出
├─ 分期               ← 合约、收款计划和风险处置
└─ 返点               ← 归集、结算与未归集治理
```

### 3.1 页头与二级导航

| 区域 | 设计 | 规则 |
|---|---|---|
| 页头左侧 | 标题“业务中心” + 当前待处理单数 | 数量只表示作业量，不替代经营报表 |
| 页头右侧 | 搜索订单号/账号/合约号 + **新建业务**主按钮 | “新建业务”展开 HS、TH、DG、DFQ；从业务上下文进入时直接预选类型 |
| 二级 Tab | 业务作业 / 订单台账 / 账号 / 分期 / 返点 | 默认进入业务作业；各 Tab 保留独立筛选条件 |
| 公共筛选 | 经办人、日期、业务类型、状态 | 业务作业默认只显示“我可处理、未完成”的对象 |

### 3.2 二级 Tab：业务作业（默认）

业务作业是**统一待处理队列表**：所有业务对象按下一步动作集中排序，不做五组大小不一的卡片。顶部只放四个可点击的短指标；下方表格用于判断与进入原对象，**不在列表中直接完成过账**。

| 顶部指标 | 口径 | 点击后结果 |
|---|---|---|
| 待处理 | 当前用户有权限且未完成的所有业务动作 | 队列筛选为全部待处理 |
| 逾期 | HS 分期出售、DFQ 代分期中逾期的期次或合同 | 队列筛选为逾期 |
| TH 未闭环 | 已付同行但未完成买家回款的订单数 | 队列筛选为 TH 未闭环 |
| 待到账返点 | 未到账或待结算的返点记录数 | 队列筛选为 REB 待办 |

| 队列列 | 规则 |
|---|---|
| 业务 | HS / TH / DG / DFQ / REB 标签；标签不单独承载紧急程度 |
| 编号与对象 | 订单号、账号、合约号或返点单号；点击进入来源详情 |
| 当前状态 | 例如在库待售、待收买家款、本期应收、逾期、待到账 |
| 关键提示 | 只显示一个最关键事实：账龄、到期日、未闭环金额、应收金额或审批原因 |
| 下一步操作 | 明确动词，例如“售出”“分期出售”“登记收款”“客户结算”“登记结算”；点击先进入详情/确认任务 |

| 排序与状态 | 规则 |
|---|---|
| 默认排序 | 逾期 → 待审批 → TH 未闭环金额/账龄 → 本期应收 → 其他待办 |
| 临期 | 警告标签、到期日和剩余天数，不只使用黄色 |
| 逾期/未闭环/待审批 | 错误或警告标签 + 具体原因，排在队列前方 |
| 无可处理项 | 显示“当前没有待处理业务”，提供“新建业务”入口 |

### 3.3 二级 Tab：订单台账

| 三级入口 | 形式 | 功能编号 | 说明 |
|---|---|---|---|
| 订单业务视图 | 内层 Tab：总单 / 回收 HS / 提号 TH / 代挂 DG / 代分期 DFQ | ORD-01-01 | 总单显示全部订单；四个业务 Tab 只显示本业务，保留状态、人员、日期筛选与详情入口 |
| 订单列表 | 业务视图内的表格 | ORD-01-01 | 总单固定展示订单号、业务、状态、关键金额、更新时间；业务 Tab 追加本业务字段，例如 TH 未闭环、DFQ 下次到期日 |
| 新建业务 | 页头主按钮；当前业务视图内直接预选业务 | ORD-01-02、HS-01、TH-01、DG-01、DFQ-01 | 总单时先选择业务；DFQ 使用三步向导 |
| 订单详情 | 右侧详情页 | ORD-01-03 | 固定头部：订单号、业务、状态、成本、收入、利润；关闭后回到原 Tab 与筛选上下文 |
| 事件 / 资金 / 分期 / 返点 / 审计 | 详情 Tab，按业务动态出现 | ORD-02、FIN-02-03、DFQ-01、REB-01、BAS-05-03 | 事件提交前展示资金池、可用余额、库存或代垫影响；成功后显示流水号 |
| 利润分配（P1） | 订单详情 Tab | BAS-06-03、BAS-06-04 | 多人单才出现，比例合计 100% |

**卖号登记规则**：自有库存账号的卖出不新建独立“卖出单”。操作路径为“业务中心 → 业务作业（回收 HS·在库待售）或订单台账（回收 HS）→ 打开订单或账号详情 → 售出过账”；表单填写买家、成交金额、收款池及直接成本/手续费，系统同步生成售出事件、收款流水、利润结果并将账号更新为已售。同行提号卖给买家的场景必须新建 `TH` 订单；代挂、代分期分别新建 `DG`、`DFQ` 订单。

### 3.4 二级 Tab：库存、分期、返点

| Tab | 三级入口 | 功能编号 | 说明 |
|---|---|---|---|
| 库存 | 库存概览（在库 / 分期中 / 已售）/ 库存列表 / 账号详情抽屉（成本、状态、风险、关联订单） | ACC-01、RPT-01-01 | 账号是库存载体。默认只看 HS、DFQ 的自有或受控账号；TH 不进入库存。库存列表可按在库天数、成本、风险筛选；账号详情可发起售出过账 |
| 分期 | 内层 Tab：**分期出售** / **代分期**；合约列表 / 合约详情（计划、收款、换绑、风险） | HS-01-06、DFQ-01-02 至 DFQ-01-08 | 分期出售只显示 `HS` 在库账号创建的 `STOCK_SALE` 合约；代分期只显示 `DFQ` 创建的 `ADVANCE_PURCHASE` 合约。两类均按逾期、临期、本期应收排序，收款必须选择首付或期次 |
| 返点 | 归集列表（全部/待结算/未归集）/ 归集详情 | REB-01 | 待结算和未归集默认靠前；未归集不进入业务收益 |

## 4. 客户中心

客户中心是客户主数据与客户关系视图，不直接创建资金流水、库存或订单事件。订单录入时从客户中心选择已建档客户；如客户不存在，可在选择框内快速建档后回填。

新建客户时，系统按微信号、QQ、手机号给出重复候选但不强制拦截；管理员可在客户详情执行合并，保留目标客户号并迁移订单、分期、需求及审计关系。

| 二级 Tab | 三级入口 | 功能编号 | 说明 |
|---|---|---|---|
| 客户档案 | 客户列表 / 新建或编辑抽屉 / 客户详情 | CUS-01 | 一名客户可同时具有卖家、买家、委托方、分期客户等角色；角色从订单参与关系自动汇总，不要求人工重复维护 |
| 客户需求（P1） | 需求列表 / 需求详情 | CUS-02 | 代蹲、代出、定找等非资金占用需求；可转为业务建单但不自动生成订单 |

| 客户列表列 | 规则 |
|---|---|
| 客户编号、称呼/昵称、微信号、QQ、手机号、备注 | 联系方式不作为唯一键；敏感信息按权限脱敏并记录修改审计 |
| 角色标签 | 卖家、买家、委托方、分期客户；由 `order_participants` 汇总 |
| 进行中业务 | 当前未完成订单数、分期中合约数、逾期数；数字可钻取 |
| 最近互动 | 最近订单/收款/需求的日期与摘要 |
| 负责人、状态 | 负责人用于客户关系维护；停用客户不可用于新订单但历史可查 |

| 客户详情 Tab | 展示内容 |
|---|---|
| 概览 | 固定资料：称呼/昵称、微信号、QQ、手机号、来源、标签、负责人、备注；活字段区：客户偏好、来源细分、预算、常用平台、跟进备注等可后台新增；订单次数和最近成交由系统汇总 |
| 业务 | 关联订单，按 HS/TH/DG/DFQ 筛选 |
| 分期 | 分期出售与代分期合约、已收/未收、下次到期、逾期 |
| 需求（P1） | 客户需求与转单记录 |
| 审计 | 建档、资料变更、停用与合并记录 |

|---|---|---|---|

## 7. 设置

| 二级 Tab | 三级入口 | 功能编号 | 说明 |
|---|---|---|---|
| 主数据 | 业务类型 / 资金池 / 路由 / 合作方 | BAS-02、BAS-03 | 合作方用于同行、供货方、平台等非客户对手方；可新增、停用；有流水对象不可删除 |
| 人员权限 | 人员 / 角色 / 数据范围 / 审计日志 | BAS-01、BAS-05 | 审计日志只读，可跳转原对象 |
| 活字段 | 字段列表 / 新增或编辑抽屉 | BAS-04 | 仅非核算属性；有历史值只能停用 |
| 经营规则（P1） | 规则列表 / 版本详情 / 生效预览 | BAS-06、REB-01-07 | 提成、返点、分期、跌价、退款、DG 混合单规则；历史版本只读 |
| 历史参考（P2） | 导入批次 / 异常 / 补录与对账 | MIG-01 | 原始资料只读，不影响新业务录入和页面默认结果 |

## 8. 全局交互约束

| 场景 | 要求 |
|---|---|
| 资金影响事件 | 提交前显示池、金额、可用余额变化、库存/代垫影响；成功显示事件号和流水号 |
| TH 付同行 | 必须提示“占用可用余额，不计库存”；收买家款后显示闭环金额 |
| 分期收款 | HS 分期出售和 DFQ 代分期均必须选择首付或期次，展示应收、已收、本次、剩余；不可超收或直接已售 |
| DG 混合单 | 录入本金后出现风险标识与审批入口 |
| 返点未归集 | 单独 Tab 和灰黄状态；标明“未纳入业务收益” |
| 历史记录 | 仅设置内展示灰色“历史参考”标签；不自动补默认值 |

## 9. 页面验收

| 验收重点 | 页面 |
|---|---|
| 资金池收入、支出、押金、可用余额、TH 未闭环代垫清晰 | 工作台、资金中心总览、经营中心 R4 |
| 四类业务按正确资金和库存规则流转 | 业务中心订单台账、详情、库存/分期 Tab |
| 客户可跨业务追溯，且不把合作同行混为客户 | 客户中心客户档案、订单参与方 |
| 直接成本、两类分期合约、返点记录可追溯 | 业务中心库存/分期/返点 Tab、经营中心 R2/R5 |
| 规则影响未来、快照保护过去 | 设置经营规则、订单详情利润分配、经营中心 R3/R5 |
