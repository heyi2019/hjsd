本次审计针对领域治理阶段 1 的首批边界：交易履约是否直接构造资金流水、订单流程是否直接改账号资产、导入是否绕过业务写入、经营分析是否产生业务写入。审计依据为当前实现代码、已有测试和阶段 0 台账；本表只记录可执行的边界问题，不把只读查询误判为越权写入。

## 3. AUD-01 收口记录

### 3.1 原问题

订单事件登记需要在同一事务里创建事件流水、更新账号/订单状态，因此原实现由交易履约服务直接实例化资金流水模型。这样虽然原子性正确，但资金域的校验、编号、审核语义和审计职责无法形成统一入口。

### 3.2 已执行调整

- 新增资金域的“创建订单事件派生流水”服务入口。
- 交易履约只提供事件、订单、池、金额、方向、性质、核算属性和备注等命令参数。
- 流水编号仍按订单和分类生成；拆分到第二资金池时复用同一入口，依赖同一会话保证编号递增。
- 资金域负责资金池可用性、方向/性质、金额非负、核算属性、流水状态和资金流水审计。
- 事务边界未改变：事件、资金流水、账号状态和订单状态仍由上层一次提交或一次回滚。

### 3.3 验收证据

- 资金域服务契约测试：能创建带订单事件外键的已审核流水。
- 订单事件既有测试：订单事件仍返回关联流水，原有金额、拆分、状态和报表行为不变。
- 静态检查：交易履约事件模块不再直接构造 `Cashflow`；测试种子中的直接构造仅用于建立固定回归数据，不属于生产写路径。

## 4. 后续整改清单

### AUD-02：账号资产命令/回执

1. 为“入库、售出、取消、交付”定义资产域命令和结果对象。
2. 交易履约只发送命令，不直接修改账号状态字段。
3. 资产域返回状态变更、成本、库存编号和失败原因。
4. 增加交付失败、重复命令和取消补偿测试。

### AUD-05：利润分配归属

1. 确认利润分配是规则计算结果、结算凭据，还是两者分离。
2. 若属于结算凭据，写入入口归资金结算；规则域只负责版本化计算。
3. 若属于规则结果，必须保留规则版本、计算输入和确认状态。
4. 在裁决关闭前，不移动既有表或改变历史分配数据。

### AUD-06：跨域只读门面

1. 资金余额、押金占用、流水汇总统一由资金域提供查询服务。
2. 订单和报表可调用查询门面，但不得直接新增资金写操作。
3. 查询门面必须保留数据范围和资金池权限过滤。
