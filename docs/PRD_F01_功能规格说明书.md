## 1. 使用规则

### 1.1 编号结构

`模块-功能组-最小功能`。例如 `FIN-01-04`：资金模块 / 资金池总览 / 押金占用明细。

| 层级 | 示例 | 含义 | 开发粒度 |
|---|---|---|---|
| 模块 | `FIN` | 资金 | 一级菜单或独立领域 |
| 功能组 | `FIN-01` | 资金池总览 | 页面、抽屉或一个完整流程 |
| 最小功能 | `FIN-01-04` | 押金占用明细 | 一个可验收的用户动作 / 接口能力 |

### 1.2 每项规格的统一读法

下文每个最小功能均以紧凑格式给出：**角色/入口；前置；字段或动作；规则；数据影响；验收**。除非另写，`管理员`可做全部动作，`经办人`只能录入和编辑本人未审核记录，`财务`可审核资金相关记录，`查看者`只读。

### 1.3 全局不可突破的规则

1. 金额使用 `DECIMAL(18,2)`；前端显示可千分位，入库不使用浮点数。
2. 已登记事件、已审核资金流水、已结算返点、已发生分期收款均不可直接编辑或删除；通过冲销/补充事件修正。
3. `orders` 是业务汇总，`order_events` 是业务事实，`cashflow` 是资金事实；一笔会动钱的业务事件与现金流一对一关联。
4. `HS`、`TH`、`DG`、`DFQ` 为种子业务；系统可新增业务。订单编号分别为 `HS0001`、`TH0001`、`DG0001`、`DFQ0001`，按业务独立顺序递增。
5. 返点不是订单类型。返点记录编号为 `HS0001-RB01`；返点登记即收入确认，金额唯一取 `rebate_records.base_amount`。分次到账编号 `HS0001-RB01-CF-01/-02` 与 `rebate_settlements` 表于 2026-11-05 下线，相关 REB-01-03 / REB-01-05 / RULE-RB-05~09 / ACC-S-06 规格同步失效。
6. 活字段只承载非核算业务属性；金额、币种、资金池、事件类型、订单关联、状态、编号、日期、人员归属等核心字段固定。

### 1.4 设计来源与历史数据边界

| 来源 | 对功能实现的效力 |
|---|---|
| PRD 的业务规则与本文件功能规格 | **唯一开发依据**；新建页面、接口、校验、报表均按此实现。 |
| 数据字典、DDL、API 规范 | 实现约束；若与 PRD/本文件冲突，先修订这些实现文档。 |
| 历史数据、迁移报告、旧 PRD | 仅作导入、对账、回归测试和异常示例；不得改变新单字段、编号、状态机、核算或 P0 范围。 |

> 因此，导入不属于首版上线阻断项。新业务可先从“干净的新单”运行；导入资料以参考记录方式处理，缺失关系保留异常状态，不靠自动猜测补齐。

### 2.0.1 四级优先级定义（排期唯一口径）

| 优先级 | 交付阶段 | 定义 | 不做的影响 | 典型功能 |
|---|---|---|---|---|
| **P0** | 首版上线前 | 不做就无法正确录单、记账、迁移或验收；必须联调与测试通过。 | 不允许上线。 | 资金池收支押金、四类业务闭环、分期收款、返点记录、R1/R2/R3/R5 |
| **P1** | 上线后第 1 迭代 | 业务已经可以正确运行，但该能力会明显降低人工跟进或管理成本。 | 可临时用筛选、线下提醒或管理员处理。 | 数据范围、月结、账号风险、返点规则、异常工单、通知 |
| **P2** | 上线后第 2 迭代 | 提升效率、体验、分析或历史追溯，且不改变 P0 的业务事实。 | 保留可用但较手工的替代流程。 | 附件、导出、质量指标、迁移回滚 |
| **P3** | 暂不承诺日期 | 低频、优化型或仅在规模扩大后才需要的能力；先预留模型，不做界面与自动化。 | 无日常业务阻断。 | 路由影响模拟、跨期余额快照自动重建 |

**优先级调整原则**：发生业务口径、资金安全、监管/审计要求变化时，可上调；任何 P1/P2/P3 不能为赶工破坏 P0 资金可追溯性。

## 7. 上线验收门槛

1. 所有 P0 最小功能必须有对应接口测试和页面验收记录；测试用例名称以功能号开头。
2. 任何 P0 资金动作必须满足：无重复流水、可追溯、可冲销、审核前不入账、审核后可从池/订单双向钻取。
3. 资金池页面必须在同屏展示 **收入、支出、押金、可用余额**，不能只展示一个“余额”。
4. 账号直接成本（介绍费、作图等）必须进入账号成本和订单利润，不能误入运营费用。
5. TH 关联 PICKUP 提号实体但不计入自营库存资产，同行采购与买家回款按各自资金流水影响余额。
6. 分期合约必须严格一对一挂在 DFQ 代分期或 HS 分期出售订单；`ADVANCE_PURCHASE` 与 `STOCK_SALE` 不可混用，付款计划、实收、逾期、换绑状态可独立追溯。
7. 返点必须关联有效来源订单；待结算金额不作为已结算收益。
