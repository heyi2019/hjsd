## 五、维护规则

1. **升级即转正**：新版以终态口径全文重写，旧版 `git mv` 进 `archive/`，不在旧稿上打补丁。
2. **能力下线要留痕**：任何功能下线（如表、枚举、权限点、页面入口）必须在对应事实源文档中显式写入"已移除"段落，并列出原名称，避免后人误以为缺失是遗漏。
3. **禁止行号引用**：文档引用代码时写「文件 + 符号名」，不写行号。
4. **代码不得引用文档**：源码、脚本、CI 配置里不得出现文档文件名或版本号（禁止 `见 xxx_v1.0.md` 这类注释）。原因：文档升版会改名，代码注释随之腐化，且把「文档当权威」会让改文档看起来像改代码。代码注释只写**行为约束本身**，或指向代码内的符号（如 `core/security.py` 的 `PERM_*`）。
