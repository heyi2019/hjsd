# 文档目录

当前生效的 Markdown 文档直接存放于本目录；`archive/` 仅保存已作废或历史参考文件。文件名前缀和标题区分产品、架构、迁移、接口、页面、测试与治理主题。

开发开始时，先阅读以下五份主文档：

1. `ERP_PRD_v1.2_当前实现版.md`：当前前后端已实现能力、产品边界与迭代缺口。
   `archive/ERP_PRD_v1.0.md` 和 `archive/ERP_PRD_v1.1_当前实现版.md` 保留为历史版本，不作为当前功能依据。
2. `ERP_PRD_F01_功能规格说明书.md`：120 个可开发、可验收的最小功能编号；当前 PRD 需求范围为 119 项，已排除 `CUS-01-05`。
3. `ERP_数据字典_v1.0.md`：表、字段、枚举与关系。
4. `ERP_API接口规范_v1.0.md`：接口约定。
5. `ERP_业务裁决台账_v1.0.md`：历史争议、默认处理与后续裁决留痕。

测试执行还应阅读 `ERP_测试用例库_v1.0.md`：由高层验收场景拆分出的可执行测试用例，以及 `ERP_验收用例与测试数据_v1.0.md`：A01～A11 高层业务验收场景。

界面实现还应阅读 `ERP_UI设计规范_v1.0.md`：蓝色主题、布局、组件、资金风险呈现和可访问性标准。

页面实现、数据库建设、测试分别参考同目录的页面原型、DDL 与迁移方案、数据库建设实施方案与验收用例。数据导入映射和迁移报告仅用于 P2 的导入、对账与回归参考，不反向改变新业务设计。

工程开工还必须阅读 `ERP_本地开发与联调指南_v1.0.md`、`ERP_权限矩阵_v1.0.md`、`ERP_接口错误码与状态机_v1.0.md`；可复用的验收种子数据位于仓库 `tests/fixtures/`。
