# 文档目录

本目录只存放**当前生效**的文档；`archive/` 只保留 ux-audit 的 E2E 证据（JSON 与截图），历史文档已全部清退，需要时从 git 历史追溯，**不得作为开发依据**。

本文件是**全仓文档地图**：`docs/` 内的按章节登记，`docs/` 之外的收在「六、仓外文档登记」。

## 一、开工必读（3 份，构成唯一事实链）

| # | 文档 | 作用 | 口径地位 |
|---:|---|---|---|
| 1 | `PRD.md` | 产品边界、页面、核心功能、接口域、验收标准 | 产品事实源 |
| 2 | `数据字典.md` | 表、字段、枚举、编号规则、口径裁决 | **数据事实源**（字段级唯一依据） |
| 3 | `接口与权限契约.md` | API 约定与端点、错误码与状态机、24 个权限点 × 5 角色、数据范围 | **接口 / 状态 / 权限事实源** |

其余两份事实源（2–3）均可被代码证伪：`backend/app/domain/`、`app/domain/enums.py`、`app/core/security.py`、`app/core/state_machine.py`。**文档与代码冲突时以代码为准，并回改文档。**

## 三、测试体系（`testing/`）

测试资产的另一个入口是 `tests/README.md`（测试文件与执行入口索引），两者分工：本登记「规范与产物」，那边登记「测试代码在哪、怎么跑」。

### 3.1 规范层（1 份，改测试前必读）

| 文档 | 用途 |
|---|---|
| `testing/测试规范.md` | 测试体系唯一规范：分层架构、编号与模块、用例库与执行结果、CI 分层、文件边界、数据库安全红线 |

### 3.2 数据与自动产物

| 文件 | 用途 | 可手改 |
|---|---|---|
| `testing/测试元数据台账.csv` | **人维护元数据**：按 `记录类型` 分两类 —— `FEATURE` 功能编号（A01…SYS0x、旧编号映射、代码域、风险等级）、`PROMISE` 业务承诺（L0-L3、负责端、失效后果、验证证据，测试文件头声明的权威源） | 维护 |
| `testing/测试用例库.md`、`testing/测试用例库.csv` | 全栈可执行用例清单（含自动化文件与断言定位） | **禁手改**（脚本生成） |
| `testing/测试报告_YYYYMMDD.md`、`.json` | 最近执行批次报告，含历史批次计数；按生成日期命名，**现役目录只留最新一份**，过期件由生成器移入 `testing/报告归档/`（不入库） | **禁手改**（脚本生成） |
| `testing/测试结果库/results.jsonl` | 逐次执行结果流水 | **禁手改**（脚本生成） |

上表除 `testing/测试元数据台账.csv` 外均由脚本生成，**跑完测试若产生 diff 应随该次改动一并提交**（它们是「当前测了什么」的快照）。

`测试元数据台账.csv` 按 `记录类型` 分 `FEATURE` / `PROMISE` 两类：共用一张稀疏表、列名互不重叠。`catalog.load_registry()` 只取「功能编号」非空的行，`promise_catalog.load_ledger()` 只取「承诺编号」非空的行 —— **新增行必须填对应主键，否则读取方会静默跳过**。手工维护，不参与生成器整份覆盖。

另有两份 nodeid ↔ 测试编号的映射索引**不入库**：`tests/backend/_report/case_index.json`、`tests/backend/_report/case_number_map.json`。原因：每次执行都整份重写（约 584KB），入库只剩无意义 diff；`backend-gate.yml` 在跑完测试后执行 `scripts/gen_test_case_library.py` 重建，本地同理。**编号不依赖这两份不入库文件**：生成器在映射缺失时由 `_load_number_map()` 从入库的《测试用例库.csv》自举恢复序号，否则全新 checkout 会按排序重排、与入库快照错位（实测 2666 条里 1640 条漂移）。`tests/backend/conftest.py` 同样在索引缺失时由 `_load_case_index()` 自举，故全新 checkout / CI 跑 pytest 时执行记录仍带编号；两份都读不到才返回空映射（编号列缺省），且记录器异常一律吞掉，绝不阻断测试。另注：`backend-gate` 的 xdist 并行模式下记录器按设计不落结果库（避免多 worker 并发写坏 jsonl），自举主要保障串行运行与本地全新环境。

## 四、前端测试资产（顶层 1 份）

### 4.1 文件登记

| 文档 | 定位 |
|---|---|
| `前端测试用例库.md` | 前端**手工**用例与测试方法论（FE-001~FE-240 + 字段/弹窗/跨页一致性等方法说明） |

### 4.2 用例库双轨制（不要当成重复文件）

前端用例存在两套编号，二者维度不同、**不是新旧替代**：

| 轨 | 载体 | 编号 | 内容性质 |
|---|---|---|---|
| 轨 1：执行事实 | `testing/测试用例库.md`、`testing/测试用例库.csv` | `UT/IT/E2E-<功能编号>-<序号>` | 脚本从测试代码反向生成的**可执行清单**，覆盖后端 + 前端 + CI |
| 轨 2：前端方法论 | `前端测试用例库.md` | `FE-001 ~ FE-240` | **人工**用例 + 测试方法说明（轨 1 不含方法论） |

两者由 `tests/README.md` 第 8 节打通（FE-xxx → Vitest / Playwright 归属）。`FE-*` 是前端锚点编号，已被下游映射与报告引用，**不得废弃**。

测试用例库与功能编号映射保持双轨：前者由脚本生成执行清单，后者维护功能编号，不合并，避免破坏编号和生成流水线。

## 七、维护规则

1. **文件名不带版本号**：`docs/` 下现役文档一律用稳定文件名（如 `数据字典.md`），版本号只写在文档内的标题与「版本记录」表里；升版时**原地全文重写**，不改名、不产生 `v1/v2` 兄弟文件，也不再往 `archive/` 存旧稿（历史由 git 追溯）。带日期的例外只有测试报告：`testing/测试报告_YYYYMMDD.md/.json`，现役目录只留最新一份，过期件由生成器移入 `testing/报告归档/`（不入库）；用例库、映射与规范一律不带日期。
2. **能力下线要留痕**：任何功能下线（如表、枚举、权限点、页面入口）必须在对应事实源文档中显式写入"已移除"段落，并列出原名称，避免后人误以为缺失是遗漏。
3. **文档不得绑定代码实现位置**。文档绑代码 = 代码一改文档就散布假信息，且会造出「文档说我为准、我说代码为准」的环路。三级判据：

| 形态 | 例 | 判定 |
|---|---|---|
| **业务契约**：表名、字段名、枚举值、接口路径、错误码、权限点、编号规则 | `stocks.stock_no`、`POST /orders/{id}/links`、`PERM_FUNDS_AUDIT` | ✅ **必须写**。这是文档在定义、代码来遵守的东西，不是绑定 |
| **对齐锚点**：文件 + 符号名 | `core/security.py` 的 `ALL_PERMISSIONS`、`core/state_machine.py` 的 `ORDER_TRANSITIONS` | ✅ 允许。文档需声明「跟谁对齐」；符号改名时有编译/测试兜底 |
| **行号定位**：`文件:行号`、`文件:起-止` | `AppShell.tsx:210`、`OrdersPage.tsx:374-455` | ❌ 禁止。行号必漂，且漂了没有报错 |
| **目录路径定位**：完整实现路径 | `frontend/src/components/layout/AppShell.tsx` | ❌ 禁止。目录会重组（该文件现已移到 `frontend/src/app/`） |

   **唯一例外：时点性证据文档**（代码体检报告、测试执行报告、审计留痕、实测记录）。它们的价值本体就是「那一刻在哪个位置」，删了行号就无法复核。但必须同时满足两条：① 头部显式声明**证据基准日期**；② 显式声明**不得作为现行依据**。且此类文档只增不改，不随代码演进维护。

   判据速查：**这份文档描述的如果是「代码长什么样」，就不该作为现役事实源留存（结论归代码，过程留痕交 git 历史）；描述的是「业务必须怎样」，才配留在正位。**

   **边界：禁的是向代码定位，不是禁引用。** 文档之间可以、也应该互相引用 —— 跨文档定向一律走 `.md` 引用（`[数据字典](数据字典.md)` 或 `见 PRD.md`），不走"去代码某个位置看"。文档谱系必须能被读通；只引 `.md` 不引代码位置，是这套体系的成立前提。引用要满足两条：① 目标文件真实存在（目标用不带版本号的稳定文件名）；② 引用目标本身有效 —— **一份文档如果引用了已失效或已下线的作品，等于把自己也交出去了**。
4. **代码可以引用文档，但引用目标必须现役**：源码、脚本、CI 配置允许指向文档（如 docstring 里 `详见 docs/testing/测试规范.md`），三条约束：① 用不带版本号的稳定文件名；② 目标文件当前存在且未下线；③ 文档改名时同步更新所有引用。禁止的是**引用已失效 / 已作废的文档**（把死链写进代码）与引用文档**版本号**（升版后必然腐化），不是禁止引用本身。
5. **新增文档要登记**：任何新增的 `.md` 落入 `docs/` 或仓外目录，必须同步更新本文件的对应章节；自动生成的产物（`testing/测试用例库.md`、`testing/测试报告_YYYYMMDD.md`、`testing/测试结果库/results.jsonl`）写明"禁手改"并只登记产出脚本，不登记内容。
