缺陷清单

P0-1

资金中心整页白屏，并拖垮应用外壳

进入「资金中心」后正文 0 字、侧栏与顶栏一并消失，用户唯一出路是刷新浏览器。

  • 页面异常：TypeError: cashflows.filter is not a function（栈：FundsPage → Suspense → AppShell）
  • 前端消费：pools/FundsPage.tsx:95 把返回值直接当数组；shared/api/catalog.ts:613-623 按 Cashflow[] 声明
  • 磁盘后端：finance/router.py:252 response_model=list[CashflowOut]（数组）
  • 运行态后端：实测 GET /cashflows?limit=2 返回 {"items":[…],"total":N}
  • 进程：PID 14972，2026-10-21 00:09:03 启动，命令行无 --reload
根因：运行中进程与工作树契约不一致（分页改造 8bc3317 不在 main 祖先链）。处置：① 重启 8123 后端对齐代码（最快，需先确认常驻服务可重启）；② 前端做形状兼容 Array.isArray(x) ? x : x.items ?? []；③ AppShell 页面槽位加 ErrorBoundary，单页崩溃降级为本页重试。
P1-1

移动端全局横向溢出 70px

375px 视口下 7/7 页面 scrollWidth 445 > clientWidth 375，可左右拖动。表格 .ant-table 计算宽度 680px，overflow-x:auto 未形成有效约束，溢出穿透到文档级。

为容器链补 max-width:100%; min-width:0，把横向滚动收敛到 .ant-table-content 内部。
P1-2

筛选占位符与次要文字 1.83:1（55 处）

「按状态筛选 / 按业务筛选 / 按类型筛选」为 rgba(0,0,0,0.25)，对比度 1.83:1（阈值 4.5）；「合并 / 拉黑」1.82:1；深色主题同类 1.75:1。截图可见占位符近乎不可见。

占位符改用令牌化次级文字色（目标 ≥4.5:1），令牌层统一修改，勿逐页打补丁。
P1-3

行内操作链接对比度不足（80 处）

浅色：「返点 / 编辑 / 查看详情」rgb(10,132,255) on 白 3.65:1（30 处）；深色：「售出 / 寄售」2.25:1（50 处）、「返点 / 编辑」3.36:1（20 处）。行内操作是表格主操作路径。

链接色加深至 ≥4.5:1；深色主题行内次要文字整体提亮一档。
P1-4

导航不保留页面状态

实测：业务中心 →「分期与回款」→ 客户中心 → 返回业务中心，活动 Tab 变为「库存中心」；URL 全程不变，无法分享或收藏当前视图，刷新即回工作台。

引入 HashRouter（或至少把一级页 + Tab 写入 location.hash）；配合 keep-alive 保留筛选与分页。
P1-5

触控目标小于 24px（26 处）

库存中心 12（行内图标按钮 18×18、筛选输入高 22）、业务台账 11（「查看详情」56×17）、客户中心 2、经营中心 1。低于 WCAG 2.5.8 最小目标。

图标按钮统一 24×24 命中区（::before 扩热区，不改视觉尺寸）；行内链接补纵向内边距。
P2-1

键盘焦点环缺失 10 处

库存中心 4、业务台账 3、客户中心 2、经营中心 1：获得焦点后 outline:none 且无 box-shadow，键盘用户看不到当前位置。

统一 :focus-visible 令牌；禁止业务样式直接写 outline:none；可加静态门禁。
P2-2

控件缺可访问名 12+ 处

分页上一页/下一页、下拉内部搜索框、纯图标按钮均无 aria-label，屏幕阅读器一律读作「按钮」。

P2-3

500 错误暴露后端原文

注入 500 后页面出现 1 个可见告警，文案为「boom重新加载」——直接把后端 message 拼进 UI。业务页缺统一错误文案层。

按错误码映射用户可读文案，原始 message 仅进控制台/日志。
P2-4

破坏性操作确认近乎缺失（main 分支）

main 仅 1 个文件含 Popconfirm/Modal.confirm，loading= 覆盖 13 文件、MoneyInput 覆盖 8 文件，仍有 1 处裸 type="number"。2026-10-20 的交互整改（ConfirmButton / useAsyncAction / InlineError）未合入 main。

P2-5

侧栏品牌字 11px / 2.03:1

「宜游轩 · 经营工作台」在 6 页重复出现，11px + 38% 透明，浅色 2.03:1、深色 2.43:1。装饰性信息不应低于可读下限。

与历史整改的关系

本报告基线为 main，不包含 2026-10-20 的交互整改批次（af74c9c、881a94d、60a08ff、8bc3317、1864d49、21d5636）——这些提交在 test/speedup-prebundle 分支，git merge-base --is-ancestor 已确证不在 main 祖先链上。因此 P1-4（无路由）、P2-4（确认/loading 缺失）在该分支已闭环、在 main 仍开放；资金中心的契约漂移也源于该分支的后端改造与 main 前端混跑。

要让整改成果真正生效，需先把该分支合回 main，再以同一脚本复测一轮。
