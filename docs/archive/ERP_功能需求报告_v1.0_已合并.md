## 2. 项目目标与产品边界

### 2.1 项目目标

| 编号 | 目标 |
|---|---|
| OBJ-01 | 统一记录订单、账号库存、客户、合作方、资金流水、分期回款和返点 |
| OBJ-02 | 建立业务事件、库存变化、资金事实和利润结果之间的可追溯关系 |
| OBJ-03 | 通过权限、审批、审计和数据质量校验，降低错录、漏记和越权风险 |
| OBJ-04 | 提供库存健康、经营损益、提成对账、资金日报和业务损益分析 |
| OBJ-05 | 支持可配置业务类型、资金池、活字段、经营规则和标准化历史数据导入 |

### 2.2 产品边界

| 编号 | 边界项 | 需求定义 |
|---|---|---|
| SCOPE-01 | 产品定位 | 经营台账与核算辅助系统 |
| SCOPE-02 | 支付范围 | 不接入支付通道，不自动打款 |
| SCOPE-03 | 资金来源 | 资金事实由用户录入，或由已登记并审核的业务事件生成 |
| SCOPE-04 | 分类边界 | 业务模式、主业务类型和增值服务必须分开记录，不得混用 |
| SCOPE-05 | 历史数据 | 导入保留原始行、映射依据和异常记录，不自动猜测缺失关系 |
| SCOPE-06 | 当前不做 | 暂不实现分期追偿和损失核算自动化；逾期、减免、展期、违约、回收和转售动作已纳入系统 |

## 3. 用户角色与权限需求

### 3.1 角色定义

| 角色编号 | 角色 | 主要职责 | 核心权限范围 |
|---|---|---|---|
| ROLE-01 | 系统管理员 `admin` | 系统与主数据管理 | 全部业务、资金、报表、导入、用户、团队和配置能力 |
| ROLE-02 | 业务经办人 `operator` | 业务建档和订单处理 | 客户、合作方、订单、业务事件及本人可操作范围内的数据 |
| ROLE-03 | 财务 `finance` | 资金和对账管理 | 资金池、流水、押金、划转、审核及相关报表 |
| ROLE-04 | 业务审核人 `auditor` | 异常和经营审核 | 资金查看、订单异常处理、规则审批和报表查看 |
| ROLE-05 | 经营查看人 `viewer` | 经营数据查看 | 资金和经营报表只读 |

### 3.2 权限控制要求

| 编号 | 控制项 | 要求 |
|---|---|---|
| BAS-05-01 | 角色菜单权限 | 按角色控制菜单和操作入口 |
| BAS-05-02 | 数据范围控制 | 支持按人员、团队和资金池配置数据范围 |
| BAS-05-03 | 操作审计 | 关键操作记录操作人、时间、对象和结果 |
| CUS-01-03 | 联系方式保护 | 客户联系方式默认脱敏，显式读取按权限并写入审计 |
| SEC-01 | 后端鉴权 | 后端执行最终权限校验，前端按钮显隐不得替代接口鉴权 |
| SEC-02 | 事实保护 | 已登记业务事实、已审核资金流水、已结算返点和已发生分期收款不可直接编辑或删除 |
