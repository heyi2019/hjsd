## 2. 分类口径

| 业务 | 类型 | 增值服务 |
|---|---|---|
| 自营 | 回收（HS） | 分期出售（自营库存售出，`STOCK_SALE`） |
| 分销 | 提号（TH）、代挂（DG） | 代分期（DFQ，`ADVANCE_PURCHASE`） |

`capital_type` 是资金核算维度，不改变上述业务归属。订单编号与产品分类是不同维度：DFQ 可有独立订单编号，但仍属于分销增值服务。

## 4. 执行和验收方式

1. 每个任务开始前标注负责人、状态、依赖、涉及页面/接口和预计工作量；完成后记录实际结果及遗留问题。
2. 每阶段至少覆盖业务经办、财务、审核及只读等适用角色；同时验证允许操作和越权拒绝。
3. 涉及金额的场景核对订单、流水、资金池、库存、分期和报表之间的相关数据；涉及历史数据的操作保留追溯记录。
4. 验收使用隔离的测试环境和可重复测试数据。真实前后端联调、组件测试和接口测试分别记录，不能用其中一种代替全部业务验收。
5. 发现业务规则未定义或现有实现与业务口径冲突时，先记录问题和影响范围，明确规则后实施；不要自行将计划项标为已完成。

建议任务状态统一为：待排查、待开发、开发中、待验收、已验收、阻塞。实际排期以人员和工作量评估为准。
