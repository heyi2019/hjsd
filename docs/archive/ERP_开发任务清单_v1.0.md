# 宜游轩 ERP · 开发任务清单 v1.0

> **上游依据**：[PRD v1.2](ERP_PRD_v1.2_当前实现版.md) → [ERP_PRD_F01_功能规格说明书](ERP_PRD_F01_功能规格说明书.md) → 架构、数据字典、DDL、API。历史数据仅作 P2 迁移与回归参考，不决定新业务设计。

## 排期规则

| 优先级 | 任务处理方式 |
|---|---|
| P0 | 首版必须交付；每项任务必须关联功能规格编号、接口测试和页面验收。 |
| P1 | 首版稳定后补齐的管理能力。 |
| P2 | 导入、对账、导出及效率增强；不得阻塞新单上线。 |
| P3 | 仅预留模型，暂不排期。 |

|---|---|---|

| T01A | SYS-01-01 | 前端脚手架按 business-line-erp 组织 | AppShell、领域目录、路由与共享 API/state 结构一致；加载已复制设计系统样式 |
| T01B | SYS-01-01 | 后端脚手架按 business-line-erp 组织 | core/foundation/领域包、分层测试目录建立；过渡代码不决定新领域模型 |
| T02 | BAS-02 / BAS-03 | pools / 业务类型 / 路由主数据 | 新池、新业务无需改代码；停用保留历史 |
| T02A | CUS-01 | customers / order_customer_roles / 客户权限 | 微信号、QQ、手机号、备注可维护；客户可跨业务多角色；敏感资料修改可审计 |
| T02B | BAS-02-05 / CUS-01-05 | counterparties / order_counterparty_roles / 客户重复合并 | `CP` 编号与客户分离；参与方类型校验；重复候选不拦截、管理员合并可追溯 |

| T05 | REB-01 / FIN-04 / BAS-04 | rebate_records / deposits / 活字段 | REB 归集+分次结算；押金不进损益；活字段不影响核算 |

## 阻断规则

- 未通过池余额、经营损益、权益和新划转对称性检查，不进入页面扩展。
- 禁止自动匹配导入订单/账号/返点，禁止补造单边划转。
- 所有金额写入走 Service 事务与审计；测试覆盖金额精度、池路由、两类分期合约勾稽、返点结算、客户/合作方参与方校验、客户合并与活字段历史保护。
- 新业务交付不得等待导入；历史数据只可作为参考记录、迁移样本和回归样本。
