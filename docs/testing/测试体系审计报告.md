### 3.1 真实失败根因（P1-4，已修复）
全量唯一失败（修复前）：
```
FAILED tests/v1/test_migration.py::test_migration_refuses_legacy_database
  assert 0 != 0   # alembic upgrade head 在 SQLite 上 returncode=0（未拒绝）
```
该测试断言"把迁移目标指向遗留 SQLite `heijin.db` 必须在配置层被拒绝"。但迁移链已压平为单一活动基线 `0001`（走 `create_all`），且项目已**正式下线 SQLite**（工作记忆），故 alembic 现在能在 SQLite 上跑通——旧"拒绝保护"不再成立。属**测试断言了已移除的不变式**，不是业务回归。

**修复（2026-11-03 本轮）**：SQLite 已整体下线，`test_migration.py` 不再依赖 SQLite——改为向同一 PG 实例申请**临时库**（`CREATE DATABASE heijin_mig_probe_*` → `alembic upgrade head` → PG 内省 → `DROP DATABASE ... WITH (FORCE)` 清理），用 SQLAlchemy 跨方言 inspector 断言 schema / 种子 / CHECK 约束。原"拒 SQLite"用例删除（其不变式已由 `test_settings.py::test_sqlite_is_no_longer_supported` 在配置层覆盖），并改正向断言"迁移目标必须是 PostgreSQL"。`test_migration.py` 现 **20 例全绿**，且零触碰 dev / test / release / 生产任何既有库。另删除已无前提的死测试 `test_repair_baseline_schema.py`（修旧 ECS SQLite 库），并清理 `run_regression.py` 中两处失效引用。

### 3.2 跳过用例（1）
全量 1 个 skipped（某可选/条件用例），非缺陷。

### 4.1 残余 `sqlite://` 草稿测试（建议·非阻塞）
除已修复的 `test_migration.py` 与已删除的 `test_repair_baseline_schema.py` 外，仓库仍有少量测试以 `create_engine("sqlite://")` / `create_engine("sqlite:///:memory:")` 直接建 **SQLite 内存/临时库**跑用例。这些用例当前均**通过**，但用了已下线的 SQLite 作"顺手草稿库"，与"SQLite 已下线"现状不完全一致。逐项判断：

| 文件 | 用途 | 是否断言 SQLite 行为 | 建议 |
|---|---|---|---|
| `test_money_float_guard.py`（2 例） | 验证 `Amount` 的 float 往返/SUM 精度 | 否（Decimal↔float 不变量，与方言无关） | **保留**：SQLite 内存库仅为快速验证类型属性；PG 上 Amount 列是 NUMERIC，该风险本就消失，迁 PG 反而改测试语义 |
| `test_money.py`（1 例） | money 模块单元测试 | 否 | 保留（同上） |
| `test_foundation_contract.py::test_has_cashflow_returns_false_without_table` | 防御分支：空库无 cashflow 表返回 False | 否（只测"无表"分支） | 保留：SQLite 内存空库是取"无表"态最便捷手段 |
| `test_core_contract.py` 多处 | 引擎构建 / 健康检查 / "SQLite 不支持"断言 | 部分是（如 `test_sqlite_is_no_longer_supported` 正是验证下线，**应保留**） | 保留：验证"拒绝 SQLite"的用例是下线保护的一部分 |
| `test_numbering.py::test_concurrent_allocation_is_unique` | 并发取号唯一性（重要业务规则） | 否（测并发唯一性，但跑在 SQLite WAL） | **建议后续适配 PG**：该规则在 PG 锁/事务语义下更应被验证；涉及并行会话、改动较大，本轮未动 |

结论：仅 `test_numbering.py` 并发用例有实质适配价值（且当前能跑过），其余为与方言无关的属性/分支测试，**保留 SQLite 内存库作草稿不引入风险**。如需彻底消除 `sqlite://` 文本，可后续统一；不阻塞当前合并。
