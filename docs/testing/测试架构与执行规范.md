# 宜游轩 ERP 测试架构与执行规范

> 生效日期：2026-11-03｜适用范围：后端（FastAPI/PG）、前端（Vite/React/Vitest）
> 定位：本规范是测试体系的"宪法"，所有新增/修改测试须遵守。目标不是用例数量最大化，而是**每个关键业务规则都可被可靠验证**。

---

## 1. 分层测试架构

| 层 | 验证对象 | 依赖 | 速度 | 本项目落地 |
|---|---|---|---|---|
| **单元测试** | 单一规则/纯函数/组件 | 无 DB、无网络、无真实 HTTP | 秒级 | `run_regression.py unit`（16 文件，59 例，全绿） |
| **集成测试** | 组件真实协作（API↔Service↔DB） | 真实 PG 测试库（隔离） | 中 | `seeded_client`/`seeded_db`/`client`/`db` fixtures（后端 1481 + 前端组件 1038 = 2519 例） |
| **E2E 测试** | 用户完整操作链路 | 真实 Chromium + 真实后端 + ephemeral 库 | 慢 | `frontend/e2e`（15 个 Playwright 规格，53 条定义 / 运行时 62 例，整轮约 3.7 分钟全绿，含前/后端起停）；库 `heijin_erp_e2e` 每轮重建，`e2e-gate.yml` 阻塞 |

> 黑盒/白盒是**正交维度**，不与上述分层混淆：
> - 黑盒：输入 → 操作 → 输出 → 数据状态（业务正确性）。
> - 白盒：分支/异常/事务/并发/幂等（实现正确性）。
> 同一用例可同时承担黑盒断言（响应+DB 状态）与白盒断言（分支/回滚）。

## 2. 业务规则验证优先级（先定义正确，再验证正确）

1. **金额精度与计算**：`core/money.py`(Amount/DECIMAL(18,2)/to_money) — 禁止 float。
2. **状态机**：订单/库存状态转换（非法流转拒绝）。
3. **判重与幂等**：入库判重、重复收支、已售复购确认。
4. **权限**：未登录/越权/敏感字段脱敏。
5. **事务一致性**：失败回滚不产生幽灵数据（如试点验证的重复入库回滚）。

需求不明确的规则**登记待确认**，不自行发明（对应任务第六阶段·高风险）。

## 3. 命名与组织约定

- 功能编号：`BIZ-<模块>-<序号>`（模块缩写见映射表 CSV；沿用既有 `INV/ORDER/FUND/CRM/RPT/AUTH/SET`）。
- 测试文件：`test_<功能>.py` 或沿用既有 `test_*_contract.py`（被 `conftest` 启发式归入 contract 组）。
- 一个功能允许多个测试文件、一个文件服务多功能的合理情形；**反对**为整齐而大规模重命名/重构业务代码。
- 测试分类应使用 pytest 原生 `@pytest.mark`，逐步替代文件名启发式（P2-3）。

## 4. 数据库安全红线（强制）

1. 单元测试尽量不碰 DB；集成测试只用 `TEST_DATABASE_URL` 指向的隔离库。
2. `conftest` 已强制：库名含 `test`、黑名单 release/prod、本地禁止与 dev 同库；**新增测试不得绕过**。
3. 禁止连接生产/上线库；严禁真实支付/放款/外部通知副作用。
4. 任何建库/清库/迁移/结构变更**先确认目标环境可恢复性**（如 P1-1 修复仅限 test 库，需授权）。
5. 不得并发启动多个后端 pytest 进程指向同一测试库（TRUNCATE 竞态）。

## 5. 本地执行命令

```bash
# 后端
cd backend
.venv/bin/python3 -m pytest tests/v1/test_stock_intake_contract.py -v   # 单文件
.venv/bin/python3 run_regression.py unit                                # 纯单元
.venv/bin/python3 run_regression.py orders                              # 某域组
.venv/bin/python3 run_regression.py ci                                  # 全量（CI 前）

# 前端
cd frontend
npm run test:fast        # 快层
npm run test:quick       # 关键交互
npm run test:react       # 组件层
npm run test:ci          # 全量
```

## 6. 新增测试自检清单

- [ ] 明确功能编号与业务规则（来自映射表或已确认契约）。
- [ ] 断言覆盖正常/边界/失败；集成测试验证 **DB 状态**而非仅响应码。
- [ ] 不修改业务规则以迁就测试；不降低断言制造绿色。
- [ ] 不新增对生产库的连接；不引入真实外部副作用。
- [ ] 标记 `@pytest.mark` 以纳入正确分组。
- [ ] 本地运行通过后再提交。
