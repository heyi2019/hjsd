# 前端测试报告

## 1. 测试结论

本次修复了报表页、设置页隐藏 Tab 首屏全部挂载的问题，并完成测试并发分组与夹具隔离：轻量测试使用 3 worker 并行，重型 jsdom + antd 页面测试保持 1 worker 串行；浏览器状态清理不再提前加载业务模块，文件级 API mock 能稳定生效。

日常默认回归已压缩到 1 分钟内：8 个关键测试文件、56 个用例，本轮复测耗时 45.24 秒。完整回归已改为 8 个隔离任务、最多 2 个 React 分片并发：41 个测试文件、264 个用例全部通过，耗时 710.61 秒（约 11 分 51 秒），较此前 1942.31 秒（约 32 分 22 秒）下降约 63%。

## 2. 本次改动

- `ReportsPage` 改为仅挂载当前激活的报表 Tab。
- `SettingsPage` 改为仅挂载当前激活的设置 Tab。
- `SettingsPage` 测试补齐 HTTP 客户端 mock，避免访问 `127.0.0.1:8123` 并等待 15 秒超时。
- 新增回归断言：初始只调用库存 R1，不提前调用隐藏报表接口。
- 新增无业务依赖的浏览器状态夹具，统一清理 `localStorage`、`sessionStorage`、主题属性和 glass 变量。
- Vitest 拆为 `fast` / `react` 两个 project：纯逻辑与轻量测试多 worker；重型页面测试单 worker，避免 jsdom/antd 资源争抢。
- 新增 `test:fast`、`test:react`、`test:serial` 入口，便于按耗时层级定位回归。
- 将 `InventoryPanel`、`CustomersPage`、`FundsPage` 的写入/长路径用例拆到独立测试文件，降低后续多 worker 分片的粒度。
- 新增 `scripts/test-full-sharded.mjs`：fast 与 quick 先单独执行，React 页面按业务域拆成 6 个分片，最多 2 个分片同时运行。
- `npm test` 默认执行 quick 层；`npm run test:full` 执行限并发完整回归；`npm run test:full:serial` 保留原始串行入口。

## 5. 前端耗时拆解

当前前端测试共 41 个文件、264 个用例。按运行策略拆成三层：`fast` 组 7 个文件 / 40 个用例；`quick` 组 8 个文件 / 56 个关键用例；React 全量拆成 6 个业务分片，每个分片内部保持 1 worker，分片之间最多 2 个进程并发。第一轮拆分已把 3 个重型交互模块拆成 6 个文件，当前主要耗时集中在以下 14 个重型测试文件：

| 测试文件 | 用例数 | 主要耗时来源 |
| --- | ---: | --- |
| `accounts/InventoryPanel.test.tsx` | 13 | 库存读取、导出、详情、权限和筛选 |
| `accounts/InventoryPanel.write.test.tsx` | 7 | 账号编辑、售出、寄售、分期、返点写路径 |

已落地的优化方向：隐藏 Tab 懒挂载、浏览器状态夹具拆分、轻量测试多 worker、默认 quick 分层、重型页面读写拆分和限并发分片。实测单个重型分片内部开启 2 worker 会触发异步交互超时，因此当前稳定边界是“分片之间最多 2 并发、分片内部 1 worker”。若还要压到 5 分钟以内，需要继续把重型用例从 `userEvent` 全链路交互改为更窄的事件驱动夹具，并逐组复测。
