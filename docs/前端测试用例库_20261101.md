版本：2026-11-01
适用系统：宜游轩 ERP Dev 前端 `http://192.168.124.12:5188/`
执行原则：只通过页面操作；测试数据使用带日期的假数据；涉及文件时优先复用 `tests/fixtures/account-image-test-20261101.png`。

> 本文已将“编号测试用例库”和“测试方法说明”合并维护；用例编号、执行结果和缺陷证据均在同一文件中持续更新。配套执行记录见：[前端建单与页面交互测试报告_20261101.md](./前端建单与页面交互测试报告_20261101.md)。

## 1. 测试方法说明

### 1.1 测试目标

验证用户能否通过页面完成业务操作，并同时确认：

1. 输入校验是否阻止非法数据。
2. 提交后列表、详情、库存、台账、分期和报表是否同步。
3. 弹窗、下拉、分页、筛选、滚动、空状态和错误状态是否可理解。
4. 敏感信息、权限限制、重复提交和跨页面状态是否安全。
5. 每个失败场景能否稳定复现，并有编号用例和缺陷证据。

### 1.2 环境与数据约束

- 测试地址：`http://192.168.124.12:5188/`，仅在局域网 Dev 环境操作。
- 只通过前端页面填写、提交、筛选、导出和上传；不直接写数据库或调用业务接口造数。
- 测试数据必须使用可识别前缀和日期，例如 `test-*`、`前端测试-*`、`20261101`。
- 图片统一优先使用 `tests/fixtures/account-image-test-20261101.png`，避免每次重新生成不同文件。
- 不使用真实密码、真实手机号、真实客户资料或真实账号。
- 测试结束不强制删除数据；保留可复现数据，但在报告中列出单号、客户号、批次号和配置键。

### 1.3 用例执行方法

每个业务模块按以下顺序执行：

1. 新建一条最小合法数据，确认页面主路径可走通。
2. 对每个必填字段做空值、空格、边界、负数、小数和超长输入。
3. 重复提交同一数据，检查唯一性和幂等性。
4. 在成功后进入关联页面核对状态、金额、单号、列表和报表。
5. 在失败、超时、刷新和返回后检查表单是否保留、错误是否清理。

### 1.4 字段与下拉测试方法

对每一个下拉或可搜索选择器记录四项：

- 打开后选项是否完整，是否出现不属于当前业务的选项。
- 输入搜索词后是否能命中，清空后是否恢复全部选项。
- 选择上游字段后，下游选项是否联动刷新且不残留旧值。
- 选择“其他”后是否出现自定义输入，保存后展示值是否正确。

### 1.5 弹窗与反馈测试方法

每个弹窗至少测试：打开、空提交、非法提交、合法提交、取消、关闭、Esc、遮罩、滚动、二次确认、提交中重复点击、超时和刷新恢复。记录：

- 弹窗标题与当前对象是否一致。
- 错误信息是否靠近字段，是否重复或互相矛盾。
- 成功是否有 toast、列表刷新或可核对的结果。
- 关闭后是否残留上一个弹窗的错误、滚动位置或脏状态。

### 1.6 跨页面一致性测试方法

成功创建或变更一条数据后，至少回到两个关联页面核对：

- 订单号、库存号、客户号或资金流水号。
- 状态、业务类型、金额、成本、已收和待收。
- 创建人、负责人、时间和审计动作。
- 汇总报表与明细金额的计算口径。

若一个页面显示成功、另一个页面仍显示旧状态，按高优先级数据一致性缺陷登记。

### 1.7 导入、上传和导出测试方法

文件类功能需要分别测试：合法扩展名、错误扩展名、错误 MIME、空文件、超大文件、结构错误、重复导入、导入中刷新、回滚和终态按钮。导出需验证：

- 未选择导出项时是否阻止。
- 成功后是否有下载反馈、文件名或下载记录。
- 文件列是否符合权限和敏感数据要求。
- 导出结果是否和当前筛选条件一致。

### 1.9 缺陷判定与优先级

- P1：数据错误、资金错误、敏感信息泄露、权限绕过、重复创建或跨页面状态严重不一致。
- P2：主流程可继续但反馈、校验、展示、刷新、可用性或审计能力不符合预期。
- P3：文案、间距、排序、视觉细节或不影响业务的轻微问题。

缺陷记录至少包含：用例编号、环境、前置数据、操作步骤、实际结果、预期结果、截图/页面证据、复现频率、影响范围、优先级和关联单号。

### 1.10 回归策略

修复后按三层回归：

1. 冒烟：FE-001、FE-002、FE-008、FE-016、FE-025、FE-048、FE-058。
2. 缺陷回归：执行所有失败用例，并检查原缺陷数据没有被修复脚本破坏。
3. 关联回归：对订单、库存、客户、资金、分期、报表和设置各抽查一个跨页面闭环。

每次回归在用例库中保留执行日期和结果；不要只记录“已修复”，要记录实际页面证据。

### 1.11 本轮执行边界

本轮已通过前端完成建单、售出、分期、回款、退款、寄售、返点、客户、资金、导入、配置和视觉巡检；未修改业务源代码。失败项以 `docs/前端建单与页面交互测试报告_20261101.md` 为准，修复后使用本用例库编号执行回归。

## 2. 用例状态

- 通过：页面行为与预期一致。
- 失败：页面行为与预期不一致，已在测试报告登记缺陷。
- 部分通过：主流程可执行，但反馈、刷新、展示或跨页面一致性仍有问题。
- 待回归：修复后需要再次执行。
