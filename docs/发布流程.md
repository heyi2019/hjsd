# 黑金时代发布流程

## 1. 发布链路

发布只从本地 `main` 进入线上 `test`，`dev` 不直接推送线上：

```text
dev（本地 5188/8123）
  → 本地验证
本地 main worktree（5199/8125）
  → 推送 origin/test
CI 门禁
  → 远端 main
  → 构建镜像并部署阿里云 ECS
```

当前本地 worktree：

| 用途 | 目录 | 分支 | 前端 | 后端 |
|---|---|---|---:|---:|
| 开发 | `/Users/aries/黑金时代` | `dev` | 5188 | 8123 |
| 发布验收 | `/Users/aries/黑金时代-main` | `main` | 5199 | 8125 |

## 2. 发布前检查

必须满足：

- `dev` 的改动已提交，并已在 5188/8123 验证。
- 改动已合入本地 `main`。
- 本地 `main` 已在 5199/8125 完成回归和关键页面验收。
- `git status --short` 无意外未提交文件。
- 版本号、迁移、测试和发布说明已同步。
- 确认本次发布不会把本地开发库或生产数据导出到发布包。

## 3. 推送线上 test

在本地 `main` worktree 执行：

```bash
cd /Users/aries/黑金时代-main
git status --short --branch
git log -1 --oneline
git push origin main:refs/heads/test
```

不要从 `dev` 直接推送线上 `test`。

## 4. CI/CD

推送后由 GitHub Actions 执行：

```text
origin/test
  → lint-gate / frontend-gate / coverage-gate
  → auto-merge-test-to-main
  → deploy-production
  → 阿里云 ECS Docker Compose
```

CI 未全部通过时不得继续发布。不要绕过 CI 手工执行生产部署。

## 5. 阿里云 ECS 发布

生产部署目录：

```text
/opt/heijin/deploy
```

服务器约定：

- 前端通过 Nginx 对外提供 80/443。
- 后端只通过 Compose 内网访问。
- PostgreSQL 数据库端口只绑定本机，不开放公网。
- 生产密钥、数据库密码和 `.env` 不进入 Git 或发布包。

发布后在 ECS 现场检查：

```bash
ssh heijin-prod
cd /opt/heijin/deploy
docker compose ps
docker compose exec -T backend curl -fsS http://127.0.0.1:8123/api/v1/health
```

同时确认：

- backend、frontend、db 容器均为 healthy/running。
- 页面可以打开，登录和本次变更的关键路径可用。
- Alembic 版本、表数量和关键业务数据符合发布前基线。
- 发布前备份成功，备份文件和校验文件存在。

## 6. 数据库备份与回滚

正式备份使用 PostgreSQL 自定义格式：

```bash
cd /opt/heijin/deploy
bash scripts/backup_daily.sh
```

恢复必须使用仓库脚本，不要直接打包运行中的 PostgreSQL 数据目录：

```bash
bash scripts/restore_pg.sh --backup /opt/heijin/backups/<backup>.dump --yes
```

发生异常时：

1. 立即停止继续发布，不重复执行迁移或清库。
2. 保存 CI 日志、容器日志、健康检查和数据库版本信息。
3. 按当前版本的回滚说明恢复镜像或数据库。
4. 回滚后重新检查登录、关键读写路径和数据基线。

## 7. 安全边界

- 不在公网开放 8123、8125、5432 或 Docker API。
- `JWT_SECRET_KEY` 必须使用随机强密钥。
- 生产 `CORS_ORIGINS` 不允许使用 `*`。
- 不使用历史 SQLite 部署说明执行 PostgreSQL 正式发布。
- 发布流程有变化时，只更新本文件，历史版本放入 `docs/archive/`。
