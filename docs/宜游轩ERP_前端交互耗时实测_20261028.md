`alembic/versions/0004_account_stock_no.py` 迁移文件的 import 写错（`from sqlalchemy import sa` 在 SA 2.0 已移除），迁移**加载即报错、从未执行**，但库被 stamp 成 0004（head）→ 所有查 `accounts` 的接口抛 `no such column: accounts.stock_no` → **500**。

| 受影响端点 | 修复前 | 修复后 |
|------|------|------|
| `GET /accounts` | **500**（含 `stock_no` 查询） | **200, p50 46ms** |
| `GET /orders`（订单页首屏） | **500** | **200, p50 21ms** |
| `GET /orders/{id}`（详情抽屉） | **500**（依赖 accounts 链路） | **200, p50 5ms** |
| `GET /customers` | 正常 | 200, p50 18ms |

**波及范围**：资金中心、订单页首屏、订单详情抽屉、取消弹窗（均依赖 `/accounts` 链路）——这正是你体感的"很多页面/弹窗/换页卡"。

> 修复归属：0004 与 trade.py 属并行会话未提交文件，按红线我**保留修正、未代提交**，由该会话连同 trade.py 一并提交；库已正确迁移（363 账号按 id 升序 `KU0001…KU0363`，无重复，唯一索引 + STOCK_NO 序列就位）。

## 六、建单 / 取消 专项分析

### 6.1 已查清的前端流程冗余（后端均 <100ms，瓶颈在前端编排）

- **订单详情抽屉 `openOrder`**：3 个**串行**请求 `get → links → snapshot`，非并行。
- **分润弹窗 `openAllocations`**：每次打开都拉一次**全量 `/users`**（非按需）。
- **订单列表 `ordersApi.list()`**：**不带 page/page_size，每次切回把整张订单表全量拉回**，再本地 `slice+sort` 翻页。
- **`useReloadOnActive`**：每个页面"每次切回都整页重拉"（AppShell keep-alive 只隐藏不卸载，代价=切页=全部重拉）。

## 六-B、建单弹窗「打开慢 / 关闭慢」专项（2026-10-28 修复）

用户明确反馈：**点击「新建」弹窗弹出慢、关闭也慢**。定位到 `frontend/src/orders/CreateBusinessModal.tsx` 两个根因：

### 根因
1. **`destroyOnHidden`（原 line 321）**：弹窗每次关闭销毁 DOM、每次打开重新挂载 → 重新触发 4 个 list 请求 + 表单配置加载（共 5 个冷请求），且每次打开都重来。
2. **数据加载依赖 `[props.open]`（原 line 92-116）**：`Promise.all([customersApi.list(), counterpartiesApi.list(), poolsApi.list(), gameTypesApi.list()])` 仅在 open 后才发起；`useOrderFormConfig(props.open ? orderType : undefined)` 也仅在打开时加载表单字段配置。

> 后端这 5 个接口本身均 <55ms（实测 /customers 18ms、/accounts 46ms 等），慢在**「每次打开都重新走完整网络往返 + DOM 重建」**，而非接口延迟。

### 修复（单文件 `CreateBusinessModal.tsx`，未跨组件）
| 改动 | 内容 |
|------|------|
| 删 `destroyOnHidden` | 弹窗 DOM 常驻（关闭仅 `display:none`），不再销毁重建 |
| lookup 预热常驻 | 4 个 list 改为**页面挂载即 `Promise.all` 预热、仅成功初始化一次**（`didInitLookup` ref 守卫，失败不置位可重试），后续打开直接读内存 state |
| 配置常驻 | `useOrderFormConfig(orderType)` 始终预热（去掉 `open ?` 条件），不同业务类型随 `orderType` 切换自动重载 |

### 量化（⚠️ 推算值，非浏览器 A/B 实测）
> 基于本次会话**已实测的后端延迟 + 首/二屏渲染经验值**推算；Bash 工具故障未能跑 Playwright A/B 计时，待恢复后补真实数字。

| 维度 | 修复前（每次打开/关闭） | 修复后 | 提升 |
|------|------|------|------|
| 打开·网络等待 | 5 并发 GET（4 list + 表单配置），dev 代理下 **150–400ms**，每次重来 | 数据常驻内存，**0ms** | 消除 100% 网络等待 |
| 打开·整体体感 | ~350–600ms（网络 + DOM 重建 + 渲染） | ~200ms（仅 antd 显示动画） | **降约 40–65%，且确定无偶发卡顿** |
| 关闭·体感 | `destroyOnHidden` 销毁+重建 DOM（~100–200ms 开销） | 仅隐藏，无重建 | 消除重建开销 |
| 二次确认弹窗 | 表单 touched 才弹（防误关设计，保留） | 同左 | — |

**机制**：页面首次渲染即挂载 `CreateBusinessModal`（三处调用方均常驻渲染），挂载时即预热 4 个 list + 表单配置；用户点「新建」时 `open=true` 只切显隐，数据已在内存 → 秒开。关闭不销毁 → 再开仍秒开。

#### 六-B-补充：「有数据时关闭变慢」二次确认处理（用户 2026-10-28 补充反馈）

- **现象**：弹窗里填了数据再点 X/取消 → 弹「放弃/继续编辑」二次确认框 → 必须再点一次，体感「关闭变慢」。
- **定位**：`appModal.confirm` 仅是 `App.useApp().modal.confirm` 的即时转发（`shared/ui/appFeedback.ts:14-24`，模块级 `ctx` 单例，**非动态挂载**），**无渲染开销**；二次确认框内容盒原同样走 500ms 弹簧入场（与建单弹窗同源），已随「**六-B-补充2 入场动画 50ms 调优**」一并压到 50ms——「慢」来自二次确认那一交互跳（弹框→必须再点一次），属防误关设计，非性能卡顿。
- **已落地修复**：`CreateBusinessModal.tsx:74-76` 新增 `useEffect(() => { if (!props.open) form.resetFields(); }, [props.open, form])`。根因是 antd `Form` 默认 `preserve=true` + 删 `destroyOnHidden` 后 DOM 常驻但表单实例不销毁 → 字段值残留 → `isFieldsTouched()` 永久为真 → **填过一次后每次关闭都弹二次确认**（误伤「打开看一眼没动」场景）。`resetFields` 关闭即清空，消除该连锁。
- **裁决（用户 2026-10-28）**：保留二次确认，不去除——防误关数据安全优先。
- **量化（行为层面）**：

  | 场景 | 修复前 | 修复后 |
  |------|------|------|
  | 打开看一眼未填即关 | 偶发弹确认（残留值误判 touched） | 不弹，直接关 |
  | 填了数据关闭 | 弹二次确认（必要） | 弹二次确认（必要，保留） |
  | 填过一次后再次打开→关闭 | 每次都弹确认 | 仅本次真填才弹 |

### 前端缓存层行为验证（单测口径）
1. 并发同 GET → 只发 **1** 次网络请求（去重）；
2. TTL 内再 GET → 前台命中缓存瞬时返回；
3. POST 成功后 → 清空 GET 缓存，下次 GET 走网络拿新值（写失效）；
4. 首访 GET → **只发 1 次**（修复了早期双倍发送 bug）。
