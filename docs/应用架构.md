## 1. 应用形态

- **单页应用**，唯一入口；采用 `HashRouter`，无 URL 服务端路由，无 `pages/` 目录、无 `h5/` 目录。
- 当前页面及子页面由 hash 路由决定，应用内切换使用 React Router 导航；深链、刷新和浏览器前进后退沿用 URL 位置。
- 响应式三断点适配桌面 / 平板 / 手机；移动端底部导航有独立视觉顺序（业务 / 客户 / 工作台 / 资金），桌面沿用主顺序。

## 2. 导航与权限收口

一级导航六项（末项为「设置」，非「设置中心」）：

| Key | 标签 | 权限收口 |
| --- | --- | --- |
| `workbench` | 工作台 | 恒可见 |
| `business` | 业务中心 | 不收口 |
| `customers` | 客户中心 | 不收口 |
| `funds` | 资金中心 | `finance.read` |
| `operations` | 经营中心 | `report.read` |
| `settings` | 设置 | 不收口 |

设计取舍：仅对经营 / 资金视角收口（普通录入员工不应看到），其余入口保持现状，避免破坏既有角色（如 VIEWER 仅含 `finance.read` / `report.read`）的导航完整性。页面内另有 `PermissionGate` 做二次门控。

## 3. 目录组织

`frontend/src` 的六个业务板块与后端域、测试区域使用统一名称：

| 前端目录 | 承载应用 |
| --- | --- |
| `app/` | 应用外壳（`AppShell`）、导航、外观设置 |
| `workbench/` | 工作台：快捷入口、经营总览、通知 |
| `business/` | 业务中心：库存、订单台账和分期分别位于 `inventory/`、`orders/`、`installments/`；业务共用能力位于 `shared/` |
| `customers/` | 客户中心：客户、需求、合作方 |
| `finance/` | 资金中心：总览、明细、工作室运营、押金、对账；对应功能位于 `overview/`、`cashflow/`、`deposits/`、`reconciliation/`，工作室运营面板位于该域根目录 |
| `operations/` | 经营中心报表；报表位于 `operations/reports/` |
| `settings/` | 设置：主数据、活字段、列表列、人员与团队；登录认证、审计、用户、选项分别位于 `auth/`、`audit/`、`users/`、`options/` |
| `shared/` | UI 与 API 基础层：`api` `ui` `hooks` `state` `styles` `lib` |

**语义边界**：前端和后端的 `finance/` 是资金中心业务域；后端 `settings/field_definitions/pools.py` 是设置域中的资金池主数据。资金中心现有导航 key 仍为 `funds`，API 路径保持原有契约。

## 4. 会话与联调

- 登录页先探测 `/api/health`；后端未起或端口不一致直接提示连接问题，不把 Vite 代理错误显示成笼统 500。
- `useSession()` 暴露 `user`，由 `role` + `username` 驱动权限收口；开发构建（`import.meta.env.DEV`）保留零登录直通，仅用于本地联调。
- API 客户端集中在 `shared/api/`：`client.ts` 统一请求（鉴权头、错误处理），各 `*.api.ts` 按资源分组（如 `cashflows`、`orders`、`installments`、`reports`、`profitAllocation`），不放页面组件内。
- Vite dev 与 preview 共用同一套 `/api` 代理到 `127.0.0.1:${VITE_BACKEND_PORT}`（默认 8123）；局域网打开时走同源路径转发，规避 CORS / PNA 拦截。E2E 用 `vite build --mode e2e` + preview，强制注入 DEV 真值以启用直通。

## 5. 交互契约（前端硬约束）

- **控件高度 36px**（`--ui-control-height`）；不要回改为 44px（已裁决废止）。
- antd `Modal` 禁止嵌套受控 `Modal` children；`.login-card` 固定浅色。
- ≤640px 按列 key 打标（`ui-col-mobile-hide`）控制显隐，禁用 `nth-child`（列序一变即错位）。
- 危险操作两级确认；后端枚举状态值必须被 `StatusTag` 覆盖，否则 `ui_guards.mjs` 构建前先红。
- 报表导出受 `report.export` 门控；资金明细按 `pool_ids` 过滤，空集返回空列表。

## 6. 构建与质量

- `npm run build` = UI 守卫 → `tsc -p tsconfig.app.json` → `vite build`，类型检查范围为 `src`；`npm run check` 执行 UI 守卫及默认 TypeScript 配置，覆盖前端源码、测试和测试夹具。
- Vite 分包按缓存层拆为 react / antd / 业务三块，业务改动不污染第三方包 hash；`chunkSizeWarningLimit=1200`。
- 前端测试分 project：`fast`（单测为主）、`quick`、`react`、`react-deep`，另有 `test:changed`（改动影响面）与 `test:panel`；日常按影响选测，完整四层使用 `npm run test:full:all`。
- E2E（Playwright）覆盖建单 / 分期 / 资金 / 升级集成等关键链路；多文件并行偶发竞态时以串行复跑确认，不据此判回归。

## 7. 前端边界与禁区

- 不新建 `pages/` 或 `h5/` 目录；页面按业务域就近归属。
- 不把业务口径判断写死在前端：分期按钮可用性由后端 `available_actions` 下发，返点 / 利润 / 余额口径只展示后端结果，前端不自行重算。
- 不引用已下线能力（导入工作台、经营规则页、订单关联、`link_status`、资金性质 / 归属下拉、返点状态）；下线必须连页面入口与选项词典一并清除。
