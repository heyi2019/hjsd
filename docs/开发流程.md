# 黑金时代开发流程

## 1. 分支与本地环境

开发与发布使用两个本地 worktree：

| 用途 | 分支 | 目录 | 前端 | 后端 | 本地数据库 |
|---|---|---|---:|---:|---|
| 日常开发与验证 | `dev` | `/Users/aries/黑金时代` | `5188` | `8123` | `heijin_erp_dev` |
| 合并后验收与发布 | `main` | `/Users/aries/黑金时代-main` | `5199` | `8125` | `heijin_erp_dev` |

访问地址：

- `dev` 前端：http://127.0.0.1:5188/
- `dev` 后端文档：http://127.0.0.1:8123/docs
- `main` 前端：http://127.0.0.1:5199/
- `main` 后端文档：http://127.0.0.1:8125/docs

两套环境代码和端口隔离，但当前共用 `heijin_erp_dev` 数据库。涉及写入数据的验证会被两套环境看到，不能把该数据库当作数据隔离环境。

## 2. 日常开发

始终在 `dev` worktree 修改代码：

```bash
cd /Users/aries/黑金时代
git switch dev
```

前后端常驻服务会自动重载代码。开发时只使用 `5188/8123` 验证：

```text
前端：http://127.0.0.1:5188/
后端健康检查：http://127.0.0.1:8123/api/v1/health
```

功能完成后，先按 [测试流程](测试流程.md) 完成开发环境验证，再提交 `dev`：

```bash
cd /Users/aries/黑金时代
git status
git add <changed-files>
git commit -m "<message>"
```

## 3. 将 dev 合并到本地 main

验证通过后，在 `main` worktree 合并 `dev`：

```bash
cd /Users/aries/黑金时代-main
git status
git switch main
git merge dev
```

如果发生冲突，解决并完成合并后再继续；无法安全处理时使用：

```bash
git merge --abort
```

合并完成后，在 `5199/8125` 环境按 [测试流程](测试流程.md) 做一次 main 验收。

## 4. 由本地 main 发布到线上 test

`dev` 不直接推送线上 `test`。确认本地 `main` 验收通过后，在 `main` worktree 执行：

```bash
cd /Users/aries/黑金时代-main
git status
git log -1 --oneline
git push origin main:refs/heads/test
```

推送后由 CI 执行门禁和发布链路：

```text
origin/test
  → lint-gate / frontend-gate / coverage-gate
  → auto-merge-test-to-main 合入远端 main
  → 构建镜像并部署
```

不要手工把 `dev` 推到 `test`，也不要绕过 CI 直接在生产环境执行部署脚本。

## 5. 云端 main 发布后同步回本地

线上 `test` 通过 CI 自动合入云端 `main` 后，先刷新远端引用，再把云端 `main` 合并回本地 `main`：

```bash
cd /Users/aries/黑金时代-main
git fetch origin main
git merge origin/main
```

如果出现代码或测试冲突，暂停发布，逐项解决并运行 [测试流程](测试流程.md)；不要使用 `reset --hard` 覆盖本地提交，也不要强推远端。

## 6. 常用检查

```bash
# 查看两个 worktree
git -C /Users/aries/黑金时代 worktree list

# 查看 dev 状态
git -C /Users/aries/黑金时代 status --short --branch

# 查看 main 状态
git -C /Users/aries/黑金时代-main status --short --branch
```
