## 2. 分层模型（第一性原理）

依赖只允许自顶向下，环在 CI 被静态拦截（AST 分析，非正则）：

```
L0  core      ── 纯技术底座：连接/金额/时间/令牌/权限常量/CSV，零 ORM 依赖
     │
L1  domain    ── ORM 模型 + 枚举 + 跨域纯领域知识（会计属性映射、表单作用域）
     │
L2  shared    ── 跨域共享原语：被 ≥2 域引用、不属任何域、只依赖 core+domain
     │
L3  业务域    ── orders / customer_center / finance / stocks / installments /
                field_definitions / reporting / workbench / lists / auth /
                audit / attachments / options / notifications / profit_allocation
```

`importlinter` 5 条契约（backend-gate 强制）：① `core` 不依赖 `domain`；② `shared` 不依赖任何业务域；③ `orders` 不依赖 `finance`；④ `orders` 不依赖 `installments`；⑤ `stocks` 不依赖 `orders`。合法单向边：`reporting`/`workbench` → 各域（只读聚合），`finance`/`installments` → `orders`，`orders` → `customer_center`/`field_definitions`/`stocks`。

**共享原语归位**：利润口径 `shared/order_amounts.py`、订单访问 `shared/order_access.py`、扩展字段 `shared/form_values.py`、审计与编号 `shared/audit.py` / `shared/numbering.py`、数据范围 `shared/scope.py`。跨域写/读协作采用「请求方域定义 collaboration 注册表 + 提供方域模块底部自注册」，未注册直接 `RuntimeError`，防丢账。

## 3. 后端工程结构

- 唯一入口 `app/main.py`；`app/api_v1.py` 应用工厂：异常转换 + CORS + GZip + 请求上下文中间件，挂载 18 个 router 到 `/api/v1`。
- 写路径统一「Service 事务 + `record_audit`」，路由层不直接改模型；校验错误抛 `Validation` → 422，业务异常 `AppError` → 统一 `{code, message, details}`。
- 横切模块在 `core`：`money`（Amount）、`errors`、`tokens`、`security`（权限常量）、`state_machine`、`time`、`report_csv`、`request_context`、`ratelimit`、`settings`。
- 列表大响应（`/orders` 实测约 489KB）经 GZip 压缩到约 16KB（约 30x），`minimum_size=1024`。

## 4. 认证与授权

- 口令 PBKDF2-SHA256 哈希；JWT 令牌，撤销令牌存 `revoked_tokens`；生产强制从环境变量注入 `JWT_SECRET_KEY`（≥32 位）。
- 权限点闭集以 `core/security.py` 的 `ALL_PERMISSIONS` 为准（实测 23 项）；`require_permissions(...)` 返回 `Depends` 对象，直接作路由默认值，不再包一层 `Depends()`。
- 开发环境保留角色直通（仅本地权限联调）；生产进入登录页用正式管理员账号，首次部署由 `scripts/create_admin.py` 创建。

## 5. 迁移与库管理

- 活动链只有基线 `0001`（`create_all` + `seed_catalog`），head=`0001`；改 ORM 必须同步改基线，否则 `check_baseline.sh` 红。
- 落后库严禁 `stamp`；上线为原地增量（dump → drill → schema_diff → 换镜像 → 比对，主键必查 `pg_constraint`）。
- 结构变更前的破坏性动作（删枚举 CHECK、删列）必须四库原地执行并先备份；顺序错会整体回滚。

## 6. 测试体系

| 层 | 入口 | 说明 |
| --- | --- | --- |
| 后端 | `pytest tests/backend`（根 `pytest.ini`） | 按测试文件数维护 `tests/manifest.json`；xdist 并行 `-n4` 可用（worker 各自独立库，跑完回收）；默认只跑针对性用例 |
| 前端 | `npm run test:fast` / `test:quick` / `test:react` / `test:react-deep` | Vitest 多 project 分片；`test:full-sharded` 全量分片 |
| E2E | `npm run test:e2e` | Playwright，走 `vite build --mode e2e` + preview，注入 DEV 真值以启用零登录直通 |
| 门禁 | `run_regression.py` | 后端回归编排，`STRUCTURAL_PREFIXES` 决定针对性范围 |

- **测试库铁律**：`conftest` TRUNCATE 仅校验库名含 test；跑测试前必核 `TEST_DATABASE_URL ≠ dev`（应 `heijin_erp_test`）。
- **承诺台账**：`tests/config/catalog.py` + `docs/testing/测试元数据台账.csv` 双维护；测试文件头声明的承诺码必须在台账登记，否则门禁红。拆测试文件须同步 manifest `files` / `integration.files` / `byArea` 三处。

## 7. CI / CD 门禁

六个工作流：`main-ci-cd`（总调度）→ dispatch `lint-gate` / `frontend-gate` / `backend-gate` → 全绿后 dispatch `deploy-production`；另有 `rollback`。

| 门禁 | 关键检查 |
| --- | --- |
| lint-gate | `run_regression.py lint`、`lint-imports`（5 契约）、pyflakes |
| frontend-gate | `npm ci`、`npm run build`（含 `ui_guards.mjs` + tsc + vite build） |
| backend-gate | `check_baseline.sh`（临时库 + alembic + schema_diff，实测 0 差异）、pytest、manifest parity |

**发布纪律**：远端只有 `origin/main`，`git push origin main` = 上线（纯文档提交同样触发）；本地 `dev` 分支不推远端。UI 守卫校验后端枚举状态值都被 `StatusTag` 覆盖、无 `any`、可访问性——新增后端枚举状态守卫先红。
