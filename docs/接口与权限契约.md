# 宜游轩 ERP · 接口与权限契约

> 本文是 API 约定、错误码与状态机、权限矩阵的**统一事实源**。基础路径 `/api`；金额以字符串传输（如 `"1234.50"`），时间使用 ISO 日期；所有写接口由 Service 事务执行。
>
> **优先级**：接口以当前后端 OpenAPI 实现为准，PRD 只解释业务语义；状态机结构以 `backend/app/core/state_machine.py` 的 `ORDER_TRANSITIONS` / `ACCOUNT_TRANSITIONS` / `INSTALLMENT_TRANSITIONS` 为实现参考；权限点以 `backend/app/core/security.py` 的 `ALL_PERMISSIONS`（24 点）与 `ROLE_PERMISSIONS` 为准；业务动作、业务事件与资金明细的目标定义以 [系统动作定义](系统动作定义.md) 为准。**文档与代码冲突时以代码为准，并回改本文。**
>
> 不得为兼容旧数据改变新单请求结构、状态机或核算规则。分期回款、退款和经营支出均通过资金明细记录，不新增 `PAYMENT`、`REFUND` 或 `COST` 订单业务事件。状态变化只能由 Service 事务触发；前端根据权限、当前状态和接口返回控制按钮，不得自行推算财务状态。

## 1. 公共约定

| 约定项 | 当前规范 |
|---|---|
| 成功与错误状态码 | 成功：`200/201`；认证失败：`401`；禁止访问：`403`；资源不存在：`404`；方法不允许：`405`；状态冲突：`409`；请求参数或业务校验失败：`422`；请求限流：`429`；客户访问保护不可用：`503`。 |
| 客户联系方式 | 客户与合作方接口直接返回已建档联系方式；修改须 `customer.contact.write`；合并须 `customer.merge`。 |
| 客户选择与导出 | `GET /customers/options` 按可见范围返回最多 20 条有效客户的编号和名称，支持关键词及 `exact=true` 精确名称；导出要求 `customer.read` 与 `customer.export`。客户列表/详情每账号每分钟 300 次、选择 120 次、导出 30 次；非开发环境由 Redis 跨进程共享计数，未配置或不可用时返回 `503 RATE_LIMIT_STORE_UNAVAILABLE`。开发环境未配置 Redis 时使用进程内计数。 |
| 错误响应 | 所有错误统一返回 `{ "code": "...", "message": "...", "details": {} }`；参数校验失败时 `details.errors` 为字段错误数组。 |
| 错误示例 | `{ "code": "POOL_ROUTE_MISSING", "message": "未配置唯一的默认资金账户", "details": { "active_pool_ids": [1], "default_pool_ids": [] } }`——订单事件派生流水未指定账户且无法确定默认资金账户时返回。 |
| 请求追踪 | 请求可携带 `X-Request-ID`，仅接受最长 64 字符的可打印字符；未携带或格式不合法时服务端生成，并始终在响应头返回。受控动作审计记录保存该请求号，审计查询回显 `request_id`。 |
| 列表筛选 | 按各端点请求签名执行；日期报表支持 `from` / `to`。只有标注为"分页列表"的端点承诺 `limit/offset`，其他列表不应自行推断分页参数。 |
| 分页响应 | 统一返回 `{ "items": [], "total": 0, "limit": 100, "offset": 0 }`，不再返回裸数组。当前适用 `/orders`、`/customers`、`/stocks`；`limit` 范围为 1–500，`offset` 从 0 开始。 |
| 认证 | 统一使用 `Authorization: Bearer <JWT>`；仅 `app_env=development/dev/local` 接受 `X-Dev-User` 作为开发态身份切换，其他环境一律拒绝该请求头。首次登录及重置密码后，改密前仅允许读取当前用户、修改密码和退出；改密接口返回新令牌，旧令牌立即失效。生产环境不接受未绑定密码版本的旧令牌，需要重新登录。登录限流与客户访问保护复用 Redis、采用独立键空间；Redis 不可用时返回 503，不绕过保护。 |
| 接口发现 | 仅 development/dev/local 暴露 `/docs`、`/redoc`、`/openapi.json`；其他环境关闭交互式文档和 OpenAPI 发现接口。 |

订单 CSV／Excel 与库存导出均要求 `report.export`，并同时遵守原有订单／库存读取权限和数据范围。订单导出支持 `sort_desc`，与台账排序一致；库存台账导出 `mode=visible` 按列表字段配置导出页面可见列，`mode=full` 导出原有完整明细，未指定时兼容旧版完整明细。明细读取失败时，文件中的相关合计显示“不可用”，失败数通过 `X-Inventory-Detail-Failures` 返回。

订单导入不自动绑定库存，也不从成本、利润等汇总值推造资金流水。更新已有订单时，导出文件中的成本、利润、状态等派生列及非空只读详情须与当前可见记录一致，不能通过导入直接覆盖；账号资料的变更须在订单详情中处理。回收和代挂的新订单可导入账号描述。台账中来源明确且仍启用的自定义列按对应订单表单字段类型恢复，选项名称须唯一，数值型目前支持整数。操作、资金和返点明细按来源编号关联；买入、售出、取消及返点产生的关联流水只登记一次，同一事件可还原多笔资金流水。分期、押金等需来源凭证的历史明细，以及无法无损恢复的字段，预检或写入时明确拒绝；导出内容受账户权限限制，导入前须确认资料完整。订单详情导出优先读取关联库存的当前账号资料；未关联库存时使用订单快照，账号图片只导出数量。

订单详情编辑可提交 `expected_profile`，其中字段与本次实际修改的账号字段一一对应；后端取得账号锁后检查原值，同字段已变更时返回 `VERSION_CONFLICT`，不同字段可分别合并。库存与订单台账的详情编辑使用该检查；未提交该字段的旧接口调用保留原兼容行为。

资金中心的 `GET /deposits/page` 和 `GET /reconciliations/page` 支持 `pool_id`、`limit`、`offset`，返回 `{items, total, limit, offset}`；默认每页 10 条、最多 500 条，并沿用资金账户可见范围。原有 `GET /deposits` 和 `GET /reconciliations` 保持数组契约。对账列表及余额快照须有 `finance.read` 且按资金账户范围过滤；仅有 `order.create` 不开放对账余额。`GET /cashflows/export.csv` 的 `sort_desc` 与资金流水列表一致，默认最新在前；各批次及列配置取同一数据库只读快照，导出中途的数据变动不混入文件。

CSV 导出会为可能被表格软件当作公式的文本增加前导单引号，普通数字不变；读取本系统原始导出 CSV 时可用 `restore_spreadsheet_csv_text` 恢复文本。XLSX 将文本明确写为字符串单元格。CSV 被表格软件另存后可能改变转义标记，不应视为无损备份；参见 [OWASP CSV Injection](https://community.owasp.org/attacks/CSV_Injection)。

通知收件箱支持 `category=latest|sale|inventory|contract`、`cursor` 和 `limit`（默认 10，范围 1–50），返回 `items` 与 `next_cursor`；`latest` 仅返回未读消息。标记已读请求携带 `category` 和 1–10 个通知 ID；分润详情每次最多查询 10 个通知 ID。

业务提醒配置 `BUSINESS_OVERVIEW_REMINDERS` 的 `inventory_aging_days` 必须是 ASCII 十进制数字表示的 1–365 天整数；配置接口拒绝无效值，读取历史异常值时使用默认值 7。

### 2.1 分页列表

以下三个列表已经切换为严格分页契约，不再返回裸数组：

| 接口 | 默认 | 最大 | 常用筛选 |
|---|---:|---:|---|
| `GET /orders` | `limit=100` | 500 | `order_type`、`status`、交易日期、负责人、资金账户、关键词 |
| `GET /customers` | `limit=100` | 500 | `keyword`、`status` |
| `GET /stocks` | `limit=100` | 500 | `status` |

请求示例：`GET /api/orders?limit=20&offset=40&status=ACTIVE`

响应示例：

```json
{
  "items": [{"id": 41, "order_no": "HS20261000041"}],
  "total": 127,
  "limit": 20,
  "offset": 40
}
```

`total` 是应用当前权限范围和筛选条件下的总数；`offset + items.length >= total` 时表示已经到达末页。前端不得把 `limit` 当成总数，也不得根据"返回数量小于默认值"推断未授权数据不存在。

## 3. 关键请求

### 创建订单

`POST /orders`

```json
{"order_type":"HS","trade_date":"2026-10-04","account_snapshot":{"game_account":"game-001","game_type":"王者荣耀"},"customer_input":{"display_name":"小周","role":"SELLER","phone":"13800000000"}}
```

返回包含 `order_no`。三类建单使用 `account_snapshot` 内联创建并绑定账号；仅从既有账号继续建单时才传 `account_id`，两者不能同时传。`customer_roles` / `counterparty_roles` 可绑定已有档案；`customer_input` / `counterparty_input` 是建单内联草稿，由订单接口在同一事务内按客户昵称和联系方式、或供货方昵称和类型复用，未命中才建档并绑定订单。订单角色必须符合业务类型，且停用客户/合作方不可引用。TH 同行写 `counterparty_roles:PEER` 或 `counterparty_input.role=PEER`，DG 寄售方写 `customer_input.role=CONSIGNOR`；不得把同行或供货方写入客户。创建分期合约时，`STOCK_SALE` 接受符合库存及买入条件的 HS / TH 订单，`PICKUP_SALE` 接受 TH 订单；`CONSIGNMENT_SALE` 仅保留历史读取，DG 不新建分期。

### 客户与合作方

`POST /customers`

```json
{"display_name":"小周","contact_name":"周某","wechat":"zhou123","qq":"123456","phone":"13800000000","source":"老客转介绍","tags":["复购"],"owner_id":3,"note":"偏好苹果区","extra_values":{"budget":"3000"}}
```

固定字段为 `display_name/contact_name/wechat/qq/phone/source/tags/owner_id/note`；客户接口的 `extra_values` 仅接收当前表单字段配置允许的扩展键，并写入客户扩展值。订单、账号等实体的扩展值统一通过各自请求中的 `form_extra` 传输，并在创建/列表/详情响应中返回。返回可选 `duplicate_candidates`（微信号、QQ、手机号命中），不会阻止创建。`POST /customers/{id}/merge` 请求 `{"target_customer_id": 18,"reason":"同一微信号"}`，仅管理员可操作，来源客户置为 `MERGED`。

`POST /counterparties` 请求固定使用 `display_name/type/contact_name/wechat/qq/phone/note`；`type` 为 `PEER/SUPPLIER/PLATFORM`。订单创建、修改或客户/合作方停用时，如参与关系非法，返回 `422`：`PARTICIPANT_ROLE_INVALID`、`CUSTOMER_DISABLED` 或 `COUNTERPARTY_DISABLED`。

### 创建事件

`POST /orders/{id}/events`

```json
{"event_type":"BUY","amount":"1200.00","portion":"PRINCIPAL","occurred_on":"2026-10-04","pool_id":1,"counterparty":"同行A"}
```

成功后返回 event、派生 cashflow、重算后的订单摘要。TRANSFER 不允许由此接口单条创建。

### 分期收入与返点登记

- 分期收入（业务名称统一为“分期出售”；HS / TH 可按上述条件创建合约）：通过 `CASHFLOW` 记录 `CASHFLOW_DIRECTION=IN`、`CASHFLOW_REASON=INSTALLMENT_PAYMENT`，同步更新 `installment.paid_amount`，累计不得超过总应收；不新增 `PAYMENT` 订单事件。
- 返点登记：`{"rebate_type":"BUY","amount":"100","collected_on":"2026-10-04","pool_id":2}`；登记即关联一笔 `IN` 返点收入资金明细。如产生平台手续费，另登记 `OUT` 资金明细，不从返点收入中改写净额。

## 4. 前后端联调与治理

- 前端统一通过 `frontend/src/shared/api/client.ts` 发起请求；领域路径与响应类型按业务域拆分在 `frontend/src/shared/api/*.api.ts`（`catalog.ts` 现为 18 行再导出兼容层，`types.ts` 承载纯类型），页面不应直接拼接业务 URL。
- `GET` 请求由客户端做短时并发去重与 SWR 缓存；成功的写请求会清空 GET 缓存。分页列表由领域 API 按 `limit/offset` 自动翻页，页面层只接收业务数组。
- 后端路由必须声明 `response_model`；错误、参数校验和权限异常统一由应用工厂转换为 `{code,message,details}`。新增或修改接口必须同步契约测试与本文档。
- OpenAPI 以 development 环境的 `/openapi.json` 为机器可读事实源；Markdown 只解释业务约束，不替代 OpenAPI 的字段级定义。

## 6. 状态机

`BUY_CREDIT`、`PAYMENT` 等旧值已移除。

### 6.1 订单状态（4 态）

| 状态 | 含义 | 可执行动作 | 禁止 |
|---|---|---|---|
| `ACTIVE` | 可继续登记业务事件 | `INSTALLMENT`（转分期）、`COMPLETE`、`CANCEL` | 删除已发生事件 |
| `INSTALLMENT` | 已挂分期合约，回款中 | `COMPLETE`、`CANCEL` | 重复登记分期 |
| `COMPLETED` | 业务闭环 | `BUY`（撤销售出，回退 `ACTIVE`）、`CANCEL` | 新增普通 BUY/SELL；资金明细须按冲销规则处理 |
| `CANCELLED` | 已按冲销规则取消 | 无 | 重新启用原单；应新建订单 |

订单创建即为 `ACTIVE`（不设草稿态：订单不挂金额，空壳草稿无业务信息）。已产生现金流的事件不能删除，只能用 `CANCEL` / offset 事件按原池、原日期冲销。`CANCELLED` 为终态。

订单及库存凭证不可物理删除。历史 `DELETE /orders/{id}` 和 `DELETE /stocks/{id}` 在权限与目标存在性校验后返回业务校验错误；需要更正时使用对应业务的取消或冲销流程，原凭证及关联明细保留。

### 6.2 库存账号状态（3 态，生命周期轴）

`stocks.status` 是账号生命周期，与库存在场状态 `inventory_status`（`IN_STOCK` / `OUT_OF_STOCK`）是**两条独立轴**，不得混用。

| 当前 | 动作 | 下一状态 | 说明 |
|---|---|---|---|
| `WAITING` | `BUY_STOCK` | `WAITING` | 自营买入后保留在库 |
| `WAITING` | `SELL` | `SOLD` | 登记售出；售出方式由 `SALE_MODE=FULL` 或 `SALE_MODE=INSTALLMENT` 区分 |
| `WAITING` | `VOID` | `VOID` | 取消 |
| `SOLD` | `BUY_STOCK` | `WAITING` | 售出撤销后重新入库 |
| `SOLD` | `RECOVER` | `WAITING` | 分期逾期回收 |
| `SOLD` | `CANCEL_STOCK` | `WAITING` | 买入事实被取消 |
| `SOLD` | `CANCEL_SELL` | `WAITING` | 售出冲销 |
| `SOLD` | `CANCEL_SELL_END` | `VOID` | 售出冲销且业务终止 |
| `SOLD` | `VOID` | `VOID` | 取消 |
| `VOID` | — | — | 终态，拒绝一切业务动作 |

同一 `game_account` 可反复买入，每次收购都是独立实体，`game_account` **不唯一**。

### 6.3 分期合约状态（8 态）

| 状态 | 进入条件 | 允许动作 |
|---|---|---|
| `PENDING` | 合约创建、首笔收入未确认 | `CASHFLOW_CREATE[CASHFLOW_REASON=INSTALLMENT_PAYMENT]`→ACTIVE、`MARK_OVERDUE`、`SETTLE`、`CANCEL` |
| `ACTIVE` | 已有应收计划 | `CASHFLOW_CREATE[CASHFLOW_REASON=INSTALLMENT_PAYMENT]`、`MARK_OVERDUE`、`SETTLE`、`DEFAULT`、`CANCEL` |
| `OVERDUE` | 到期未足额收款 | `CASHFLOW_CREATE[CASHFLOW_REASON=INSTALLMENT_PAYMENT]`、`SETTLE`、`DEFAULT`、`CLOSE`、`CANCEL` |
| `SETTLED` | 所有应收已收或受控减免 | `DELIVER`→DELIVERED、`CANCEL` |
| `DELIVERED` | 已生成无金额 `DELIVER` | 只读 |
| `DEFAULTED` | 仅可从 `ACTIVE` / `OVERDUE` 登记违约 | `CASHFLOW_CREATE[CASHFLOW_REASON=INSTALLMENT_PAYMENT]`（追偿收入）、`CLOSE` |
| `CLOSED` | 逾期或违约后关闭结案 | 只读，终态 |
| `CANCELLED` | 无资金事实时取消 | 只读，终态 |

`DELIVER` 只能从 `SETTLED` 进入 `DELIVERED`，必须提供 `DELIVERY_DIRECTION=BUY/SELL` 及换绑凭证。分期收入由 `CASHFLOW_DIRECTION=IN`、`CASHFLOW_REASON=INSTALLMENT_PAYMENT` 记录；`DELIVER` 不生成现金流、不再确认收入。

**期次状态**（`installment_schedules.status`）：`PENDING` / `PARTIAL` / `PAID` / `OVERDUE` / `WAIVED`。每期 `due_amount` = 当期本金 + 当期服务费；减免累计 `waived_amount` 不改写原应收；展期只更新 `due_on`，不是独立状态。

**处置动作**（`installment_dispositions.action`）：`RECOVER` / `RESELL`，同一合约每类动作只能登记一次。

### 6.4 资金流水生效口径

资金流水登记即生效，直接参与余额、报表和对账；不再保存或返回独立的流水状态。
冲销不删除原流水，反向生成一笔新流水；内部划转经共享 `transfer_id` 一出一入。

### 6.5 客户、合作方与押金状态

| 对象 | 状态 | 规则 |
|---|---|---|
| 客户 | `ACTIVE` / `DISABLED` / `MERGED` | `DISABLED`、`MERGED` 不得新建订单参与关系；历史可查；合并目标须 `ACTIVE`，来源置 `MERGED` 并保留 `merged_into_id` |
| 合作方 | `ACTIVE` / `DISABLED` | 停用后不可参与新订单；有历史不可物理删除 |
| 押金 | `PAID` / `PARTIALLY_RETURNED` / `RETURNED` / `LOST` / `CANCELLED` | `returned_amount` 不得大于 `paid_amount`；缴退均有现金流；`LOST` 为损失核销 |

客户创建遇重复只返回 `duplicate_candidates` 提示，**不拦截**；仅管理员可合并，并迁移订单参与关系、分期客户关系、需求与引用。

### 6.6 其他对象状态

| 对象 | 状态 |
|---|---|
| 返点记录 | `OPEN` / `PARTIALLY_SETTLED` / `SETTLED` / `VOID` |
| 客户需求 | `OPEN` / `CONVERTED` / `CLOSED` |
| 对账 | `OPEN` / `RESOLVED` |

## 8. 权限矩阵

权限为「角色权限 + 数据范围」两层。角色决定能否执行动作；数据范围决定可见哪些订单、客户、资金账户和报表。默认最小授权，所有高风险动作写审计。

### 8.1 角色定义

| 代码 | 角色 | 典型职责 | 权限点数 |
|---|---|---|---:|
| `ADMIN` | 系统管理员 | 用户、团队、主数据、活字段、选项词典、客户合并 | 23（全部） |
| `OPERATOR` | 业务经办人 | 建客户、建单、登记业务事件 | 11 |
| `FINANCE` | 财务 | 资金流水、划转、押金、对账、财务侧事件 | 9 |
| `AUDITOR` | 业务审核人 | 审计查阅、报表 | 6 |
| `VIEWER` | 经营查看人 | 只读报表与资金汇总 | 2 |

数据范围由 `owner_scope`（`SELF` / `TEAM` / `ALL`）+ `pool_ids` + `team_ids` 决定，与角色正交：角色管"能不能做"，范围管"对谁做"。

分润对账是例外：拥有 `report.read` 的用户可在经营中心查看全员分润；`all_people=true` 不受订单 `owner_scope` 限制，`user_id` 可在全员范围内筛选。`mine=true` 只展示本人分润。导出仍需 `report.export`，并沿用查询时的人员筛选。
