## 1. 文档边界

本字典定义**新业务的固定物理契约**，事实来源为 `backend/app/domain/` 下的 ORM 模型与 `app/domain/enums.py`。任何与本文冲突的旧 PRD、旧迁移说明、旧测试报告均以本文为准。

历史资料仅按迁移映射以参考记录导入；历史列、旧表和脏值**不得**扩展或改变以下结构。字段名一律取数据库物理名，表名一律取 `__tablename__`。

**生成方式**：本文 §2/§3/§4 由脚本反射 SQLAlchemy `Base.metadata` 与 `enums.py` 全量实测生成（v2.6），逐表逐字段与 ORM 零漂移。业务口径裁决（§8 及各类约束说明）为长期有效的人工约定，不随字段增删改变。

**中文映射规则**：§4 字段名以 `物理名（中文）` 内联标注（228 个唯一字段按业务语义译名）；§3 枚举取值以 `VALUE（中文）` 内联标注，中文优先取前端 `labels.ts` 权威文案源（如 `ACCOUNTING_ATTRIBUTE_LABEL`、`FUND_FLOW_SOURCE_LABEL`），无前端文案的按业务语义给出；同名不同义的取值（如 `OPEN`/`ACTIVE`）按枚举类分别限定，不共用一张表。代码物理名始终是检索键与接口值，中文仅供阅读，不替代物理名。

## 2. 静态表清单与字段计数

## 6. 活字段边界

**可配置**：标签、渠道等级、账号卖点、预计上架日、客户偏好、客户来源细分、预算、常用平台、跟进备注、合作方备注。

**不可配置**：客户编号、称呼/昵称、微信号、QQ、手机号、订单参与关系、金额、池、收支方向、事件/业务类型、正式关联、库存/利润/应收计算字段。

参与核算的活字段必须升格为固定字段。活字段按 `order_form_fields`（定义）+ 各表 `form_extra`（值）落地，八类实体作用域见 §3.5。

客户新建时以微信号、QQ、手机号查询重复候选并返回提示，**不强制拦截**；仅管理员可合并，合并迁移订单参与关系、分期客户关系、需求与引用，来源置 `MERGED` 并保留原编号与完整审计。

## 7. 经营规则配置边界

返点率、手续费、提成率、分期规则、库存跌价规则、多人利润分配和退款分类**可配置**，但必须走 `policy_definitions` / `policy_versions` 与固定快照字段（`policy_version_id` + `policy_snapshot`），**禁止**写入活字段值。

固定不可配置项：DG 代挂沿用统一 `SELL` 事件登记卖出金额与订单利润，寄售方经 `CONSIGNOR` 关联，不配抽成比例或单独结算公式。

多人分配规则：`order_profit_allocations` 的 `allocation_type` 表示分润归属（`BUY` / `SELL` / `OPERATION`）或 `COMPANY`（不绑人），`role` 取 `AllocationRole`；分配基数按订单收入与关联支出资金明细计算，返点收益独立核算；买号/售出执行人自动绑定不可手改；四项合计必须 100%。

## 8. 口径裁决（长期有效）

1. `game_password` 明文存储为既定裁决，不加密、不脱敏。
2. `total` 语义 = 成交总额（gross），不等于 principal + profit。
3. 资金只到池一级，系统余额为池内已审核流水有符号和，无「开户余额」概念。
4. 历史 89 单可标 `UNLINKED`；19 笔返点保留未关联待人工补齐；不得自动匹配，不阻塞新单上线。
5. 蹭点→DG；氪金联盟提号/氪金提号/提号→TH；小荷包/经营池→`HJ_INVEST`；介绍费、作图费等支出统一登记为 `cashflow` 的 `OUT`，按资金原因和来源业务关联，不新增账号附加 `COST`；八月利润转 `UNLINKED_TRANSFER`，无原始凭证不补另一侧。
6. 金额一律 `DECIMAL(18,2)` / `Amount`，禁止 float；有流水的池、历史字段和核心凭证禁止物理删除，只能停用 / 取消 / 冲销修正。
7. 迁移活动链只有活基线 `0001`（`create_all` + `seed_catalog`）：改 ORM 即改基线、加内置字段改 `catalog_seed.py` blob，**不再加增量迁移**；结构落后的库不得 `stamp`。上线是原地增量补缺失，不是覆盖重建。
8. 利润 = 单订单全部收入 − 全部支出（可正/负/0），权威原语 `shared/order_amounts.py::order_cashflow_profit`；收入 = 流水 IN + 返点，支出 = 流水 OUT + 分期坏账；返点是收入「其中项」禁止再加；报表 R2「其中返点」独立 `sum(RebateRecord.amount)`。
9. 返点关联用业务编号：返点事件的 `order_events.source_type='REBATE'`、`source_id=rebate_no`（形如 `HS0001-RB01`），替代旧口径事后回填 `form_extra['rebate_record_id']`；审计 `entity_id` 与流水 `source_id` 同用业务编号，不用数据库自增主键。
10. 分期按钮可用性由后端 `installments/action_availability.py` 计算并随 `available_actions` 下发给前端回显；前端不按状态数组自行判定，口径收敛到后端唯一来源。
