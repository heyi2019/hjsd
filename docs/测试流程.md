# 测试流程

> 本文说明日常改动、云端 `dev` 验证和发布前的测试顺序。测试分层、数据库安全及用例管理以 [测试规范](testing/测试规范.md) 为准；开发和阿里云上线分别见 [研发流程](研发流程.md)、[发布流程](发布流程.md)。

## 1. 确定范围与环境

1. 根据改动选择相关后端测试、前端测试和关键页面；共享依赖或跨模块变动扩大测试范围。纯文档改动检查内容、链接及相关契约。
2. 数据库测试使用独立测试库，核对 `TEST_DATABASE_URL` 与开发库、上线库及生产库隔离；测试夹具可能清理测试数据。具体配置和安全限制见 [测试规范](testing/测试规范.md)。
3. 在本地 `dev` 的 `5188/8123` 进行开发验证；云端 `dev` 门禁复验提交。不再使用本地 `main` 环境。

## 2. dev 修改后验证

- 后端执行与变更相关的 pytest 或 `run_regression.py` 分组；数据结构变动还要验证迁移与数据库基线。
- 前端执行 `cd frontend && npm run check`、`npm run test:changed`；涉及构建、依赖或发布时运行 `npm run build`。
- 交互或前后端联动改动检查涉及的列表、详情、创建、编辑、删除和权限路径，按需查看浏览器控制台及请求结果。
- 测试失败先保留错误、修复并复测，再提交或交付。常规 React 测试层最大 4 workers，其他分层按 [测试规范](testing/测试规范.md) 中的配置执行。

## 3. 云端 dev 验证

确认相关修改已提交、本地验证通过并推送 `origin/dev`；核对云端提交及 lint、frontend、backend 三道门禁结果。失败时保留错误并修复复验。

dev 的 push 和 PR 按事件包含的完整提交范围选择相关测试；变更涉及公共结构、工作流或测试清单时扩大范围，提交范围不可靠时退回全量常规测试。手动门禁未提供范围时同样运行全量常规测试；需要浏览器 E2E 时显式选择 `full_suite`。

发布前依据 `origin/main` 与拟发布的 `origin/dev` 提交差异选择测试；需要指定范围时可将仓库根相对路径用英文逗号连接，通过 `TEST_CHANGED_PATHS` 传给 `npm run test:changed`。未检测到前端变更时，该命令不会运行测试，不能将其视为验收通过。

## 4. 发布前验证与交接

1. 发布前按影响执行全量回归、前端构建及必要的数据库基线检查，记录通过情况和未解决问题。
2. 真实浏览器 E2E 按需执行；自动发布普通变更按范围选测，生产数据库重建必须运行前后端全量和浏览器 E2E。三道门禁通过后才开始部署；测试范围见 [测试规范](testing/测试规范.md)。
3. 验证完成后依据 [版本管理](版本管理.md) 准备版本建议及更新内容，再按 [发布流程](发布流程.md) 进行发布前检查。推送 `origin/main` 必须有用户明确发布指示。
