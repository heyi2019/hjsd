# 黑金时代测试流程

## 1. 测试顺序

测试分为两轮：先验证 `dev`，确认修复有效后再验证本地 `main`。

测试基准以本地代码为准：本地 `dev` 是系统定义的最新版本，云端 `test` 仅用于发布验收。云端与本地有差异时，不以云端代码替换本地代码；需要带回的内容必须先逐项评估，再在本地适配并重新测试。

```text
dev（5188/8123）
  → 自动化检查 + 人工页面验收
  → 合并到本地 main
  → main（5199/8125）再次验收
  → 推送 origin/test
```

## 2. 开发分支验证

在 `dev` worktree 执行：

```bash
cd /Users/aries/黑金时代

# 后端测试
cd backend
.venv/bin/python -m pytest

# 前端类型、守卫与构建
cd ../frontend
npm run check
npm run build
```

人工验收地址：

- 页面：http://127.0.0.1:5188/
- 健康检查：http://127.0.0.1:8123/api/v1/health
- 接口文档：http://127.0.0.1:8123/docs

重点验证本次修改涉及的列表、详情、创建、编辑、删除和权限路径，并检查浏览器控制台和页面是否出现 4xx/5xx。

## 3. 本地 main 验收

`dev` 验证通过并合并到本地 `main` 后，在 `main` worktree 执行同一组必要检查：

```bash
cd /Users/aries/黑金时代-main

cd backend
.venv/bin/python -m pytest

cd ../frontend
npm run check
npm run build
```

人工验收地址：

- 页面：http://127.0.0.1:5199/
- 健康检查：http://127.0.0.1:8125/api/v1/health
- 接口文档：http://127.0.0.1:8125/docs

如果 main 验收失败，先不要推送 `origin/test`；回到 `dev` 或在 main 合并提交上定位问题。

## 4. 按改动范围选择测试

| 改动范围 | 最低要求 |
|---|---|
| 纯前端组件或交互 | `npm run check`、相关 Vitest、5188/5199 页面人工验收 |
| API、权限、状态机 | 后端相关 pytest / regression、前端相关页面验收 |
| 数据模型或迁移 | 后端迁移测试、相关 API 测试、数据库状态检查 |
| 前后端联动功能 | 前后端检查、关键写路径人工验收、dev 与 main 各验证一次 |

当前不把真实浏览器 E2E 作为默认门禁；需要页面体检时，可按本地联调指南中的 UX audit 说明单独执行。

## 5. 数据纪律

- `dev` 与本地 `main` 当前共用 `heijin_erp_dev`，两套环境的写入会互相可见。
- 禁止在本地开发验证中连接生产库。
- 测试失败时保留错误输出、请求路径和复现步骤，不要用清库或回滚数据掩盖问题。
