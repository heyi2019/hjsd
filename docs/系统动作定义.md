# 宜游轩 ERP 系统动作定义 v1.0

> **附件归属**：[PRD](PRD.md) ｜ **适用分支**：`dev` ｜ **编写日期**：2026-11-10
>
> 本附件统一说明业务事件、状态机动作、审计动作和页面展示动作的边界，是 `dev` 分支的当前业务口径。它不替代数据字典中的字段与枚举定义；如与历史规格中的旧字段或旧路径冲突，以本附件和数据字典 v2.0 的当前业务口径为准。旧订单事件编码不保留兼容入口，代码、接口和页面均直接使用本附件定义。

## 1. 动作的层次

系统中的“动作”不是一个单一概念，必须按所属层次理解：

| 层次 | 技术载体 | 作用 | 示例 | 是否形成业务事实 |
|---|---|---|---|---|
| 业务动作 / 操作名 | 页面和业务人员使用的操作名称 | 表达业务人员要执行什么操作 | 买号、售出、交付、运营、分润、取消 | 否；属于动作定义 |
| 业务事件记录 | 订单或运营业务事实 | 记录业务动作实际发生了什么，不等同于资金收支 | `BUY`、`SELL`、`DELIVER`、`CANCEL`、`OPERATE`、`REBATE` | 是 |
| 资金明细 | `cashflow` | 记录钱的收入与支出，可关联业务来源和分期合约 | 收入、支出、退款原因 | 否；形成资金事实 |
| 状态机动作 | Service 状态转换动作 | 让订单、库存账号或分期合约从一个状态转到另一个状态 | `INSTALLMENT`、`COMPLETE`、`SETTLE`、`DEFAULT` | 不一定；通常由业务事件或流程动作触发 |
| 审计动作 | `audit_logs.action` | 记录谁在什么时间对什么对象做了什么系统操作 | `ORDER_CREATE`、`ORDER_UPDATE`、`EVENT_POST` | 否；它是操作留痕 |
| 页面展示动作 | 前端中文文案、分组和按钮 | 把底层编码翻译成业务人员能理解的操作入口 | “账号入库”“账号出库”“登记回款” | 不单独形成事实 |

同一个用户动作可能同时产生多层记录。例如点击“登记售出”会登记一条 `SELL` 业务事件、更新订单和库存状态；如果同时收款，再单独登记一条收入资金明细；最后写入 `EVENT_CREATE` / `EVENT_POST` 审计记录。页面只展示“账号售出”“收入”或“账号出库”，不直接展示底层编码。

## 2. 业务动作与事件记录

业务动作就是业务操作名；业务动作执行后形成业务事件记录。业务事件记录只描述订单、库存、交付、运营、分润等业务事实，不描述收入或支出。业务事件发生后可以关联资金明细，也可以不关联；两者不是一一等价关系。

| 业务事件编码 | 操作名 | 业务事件定义 | 资金明细关联 | 主要适用范围 | 关键规则 |
|---|---|---|---|---|---|
| `BUY` | 账号入库 / 登记买入 | 取得账号或业务资源 | 可关联买入支出明细 | HS、TH | DG 不允许登记 `BUY`；业务事件和支出明细分别保留 |
| `SELL` | 账号售出 / 账号出库 | 记录账号或业务已经售出；`SELL` 的售出方式分为全款和分期 | 全款关联收入明细；分期关联后续回款收入明细 | HS、TH、DG | 同一订单只能登记一次售出事实；全款 / 分期是 `SELL` 的业务属性，不是两个不同动作 |
| `DELIVER` | 交付 | 确认账号或服务已经完成交接 | 通常不关联资金明细 | 交付方向为买号或卖号 | 根据业务角色记录交付方向属性；交付事实和资金记录分开 |
| `CANCEL` | 取消 / 冲销 | 取消未完成业务，或对原业务事实做受控反向处理 | 按原业务规则关联冲销明细 | 全部业务 | 原事件和原流水保留；取消不直接覆盖资金明细 |
| `OPERATE` | 运营 | 记录账号或订单的运营工作；运营类型为作图、描述、寄售、下架 | 不自动产生资金明细；如确有外部支出，另登记支出明细并关联运营事件 | HS、TH、DG | 作图、描述、寄售、下架是运营属性，不是四个业务动作；寄售和下架也不等同于 DG；运营不改变买入、售出、交付状态 |
| `REBATE` | 返点 | 记录关联订单的返点事实；返点类型为买号返点或卖号返点 | 关联返点收入明细 `IN` | HS、TH、DG | 买号返点 / 卖号返点是 `REBATE` 的业务属性，必须关联来源订单；返点记录和收入明细分别保留 |

### 2.1 `SELL` 的售出方式

`SELL` 只有一个售出动作；全款和分期只是这个动作的两种业务方式。

| 售出方式编码 | 页面中文展示 | 业务含义 | 资金明细 | 后续流程 |
|---|---|---|---|---|
| `FULL` | 全款售出 | 买方一次性完成售出款项支付 | 关联一笔或多笔 `IN` 资金明细 | 售出完成后按业务规则办理卖号交付 |
| `INSTALLMENT` | 分期售出 | 买方先建立分期售出关系，再按期支付 | 每次回款单独登记 `IN` 资金明细 | 回款结清后办理卖号交付；未结清不能交付 |

### 2.2 业务属性，不新增动作

以下差异用于描述同一个业务动作的具体方式、方向、类型或归属，不新增业务事件编码：

| 所属动作 / 记录 | 属性编码 | 属性值编码 | 页面中文含义 | 技术载体（模块） | 说明 |
|---|---|---|---|---|---|
| `SELL` | `SALE_MODE` | `FULL`、`INSTALLMENT` | 全款售出、分期售出 | `orders` | 都是 `SELL`；属性决定收款方式和交付条件 |
| `DELIVER` | `DELIVERY_DIRECTION` | `BUY`、`SELL` | 买号交付、卖号交付 | `orders` | 都是 `DELIVER`；页面可以展示为两个选择项，但不新增两个交付事件 |
| `OPERATE` | `OPERATION_TYPE` | `IMAGE`、`DESCRIPTION`、`CONSIGNMENT`、`UNLIST` | 作图、描述、寄售、下架 | `orders` | 都是 `OPERATE` 的运营记录；不拆成四个业务动作 |
| `REBATE` | `REBATE_TYPE` | `BUY`、`SELL` | 买号返点、卖号返点 | `orders`、`finance` | 都是 `REBATE`；属性说明返点来源和业务归属 |
| `cashflow` | `CASHFLOW_DIRECTION` | `IN`、`OUT` | 收入、支出 | `finance` | 只有收入和支出两个方向，不是业务事件动作 |
| `cashflow` | `CASHFLOW_REASON` | `SALE`、`INSTALLMENT_PAYMENT`、`REBATE`、`PURCHASE`、`REFUND`、`OPERATING_EXPENSE` | 售出、分期回款、返点、买入、退款、经营支出 | `finance` | 说明钱为什么发生；退款等原因不新增订单业务事件 |
| `CANCEL` | `CANCEL_MODE` | `CANCEL_PENDING`、`REVERSE_FACT` | 取消未完成业务、冲销原业务事实 | `orders`、`finance` | 都是 `CANCEL`；通过属性、原记录关联和冲销关系区分 |

页面可以把属性作为表单选项或筛选条件展示，但审计、业务事件和资金明细仍按所属动作和记录对象落库。操作明细的页面展示分类统一为“账号入库 / 账号运营 / 账号出库”；三类建单分别展示“回收入库”“提号入库”“代挂入库”，售出展示“账号售出”。其中 DG 的“代挂入库”来自建单事实展示，不新增技术上的 `BUY` 事件。

### 2.3 事件与资金流水的关系

业务事件、资金明细和审计记录是三类不同记录：

1. **业务事件**回答“业务发生了什么”，例如 `BUY`、`SELL`、`DELIVER` 或 `CANCEL`。
2. **资金明细**回答“钱进来还是出去”，即收入或支出，并通过关联关系指向业务来源。
3. **审计记录**回答“谁在什么时间执行了什么系统操作”。

一个业务事件可以关联零条、一条或多条资金明细；没有资金影响的业务事件只保留业务记录。资金明细的收入 / 支出方向不能反过来改变业务事件的含义。内部划转不是业务事件，而是成对资金明细，通过 `source_type=TRANSFER` 与同一 `source_id` 关联。

### 2.4 资金明细方向与原因

资金明细只处理收入 / 支出方向及资金原因，不作为订单业务事件：

| 资金动作 | 方向 | 业务来源 | 说明 |
|---|---|---|---|
| 收入 | `IN` | 售出、分期回款、返点等 | 记录资金进入哪个资金账户，并关联来源订单或业务事实 |
| 支出 | `OUT` | 买入、退款、经营支出等 | 记录资金从哪个资金账户支出，并关联来源订单或业务事实 |

“回款”“退款”是资金明细的业务原因或明细类型，不是订单业务事件。退款必须关联原订单或原收入来源，但不在订单事件表中新增一个退款事件。

> 旧版支出事件不属于当前动作定义；本次 dev 数据重建不迁移历史业务事件。新的页面、接口和订单事件不得再产生 `COST`、订单事件 `PAYMENT` 或订单事件 `REFUND`。

## 3. 三类业务的动作路径

当前 `dev` 业务主类型为 HS、TH、DG。DFQ 相关内容属于历史规格，不作为新业务动作依据。

| 业务 | 业务含义 | 可登记的核心动作 | 主路径 | 资金口径 |
|---|---|---|---|---|
| HS | 自营回收 | `BUY`、`SELL`、`DELIVER`、`CANCEL` | 全款：`ACTIVE → BUY → SELL[SALE_MODE=FULL] → CASHFLOW[CASHFLOW_DIRECTION=IN, CASHFLOW_REASON=SALE] → DELIVER[DELIVERY_DIRECTION=SELL] → COMPLETED`；分期：`ACTIVE → BUY → SELL[SALE_MODE=INSTALLMENT] → INSTALLMENT → CASHFLOW[CASHFLOW_DIRECTION=IN, CASHFLOW_REASON=INSTALLMENT_PAYMENT] → DELIVER[DELIVERY_DIRECTION=SELL] → COMPLETED` | 买入关联支出明细；售出或分期回款关联收入明细 |
| TH | 分销提号 | `BUY`、`SELL`、`DELIVER`、`CANCEL` | 全款：`ACTIVE → BUY → SELL[SALE_MODE=FULL] → CASHFLOW[CASHFLOW_DIRECTION=IN, CASHFLOW_REASON=SALE] → DELIVER[DELIVERY_DIRECTION=SELL] → COMPLETED`；分期：`ACTIVE → BUY → SELL[SALE_MODE=INSTALLMENT] → INSTALLMENT → CASHFLOW[CASHFLOW_DIRECTION=IN, CASHFLOW_REASON=INSTALLMENT_PAYMENT] → DELIVER[DELIVERY_DIRECTION=SELL] → COMPLETED` | 买入关联支出明细；售出或分期回款关联收入明细 |
| DG | 代挂 | `SELL`、`DELIVER`、`CANCEL` | 全款：`ACTIVE → SELL[SALE_MODE=FULL] → CASHFLOW[CASHFLOW_DIRECTION=IN, CASHFLOW_REASON=SALE] → DELIVER[DELIVERY_DIRECTION=SELL] → COMPLETED` | 不登记本方买入支出；代挂当前只支持全款售出，实际售出关联收入明细 |

### 3.1 DG 代挂的特殊定义

DG 的关键不是“有没有 `SELL` 事件”，而是“这张单从建单起就是替客户卖号”：

- DG 不产生本方买入动作，因此不能登记 `BUY`；代挂订单不通过订单事件登记支出。
- DG 尚未成交时，订单已经属于“卖号交付”方向，详情页应展示卖家交付表格，而不是“暂无卖家交付”。
- 真正成交时才登记 `SELL`；这条事件表示销售事实和利润/服务收入，不表示本方发生买入支出。
- 因此，DG 可以在没有 `BUY` 的情况下存在；没有 `SELL` 只表示尚未登记成交，不表示它是买号交付单。

## 4. 状态机动作

状态机动作是“允许状态如何变化”的规则，不应与 `EventType` 混为一谈。

### 4.1 订单状态

| 当前状态 | 状态机动作 | 下一状态 | 说明 |
|---|---|---|---|
| `ACTIVE` | `INSTALLMENT` | `INSTALLMENT` | 建立分期合约，进入回款流程 |
| `ACTIVE` | `COMPLETE` | `COMPLETED` | 完成无须新增普通事件的业务闭环 |
| `ACTIVE` / `INSTALLMENT` | `CANCEL` | `CANCELLED` | 取消订单；有资金事实时必须按冲销规则处理 |
| `COMPLETED` | `BUY` | `ACTIVE` | 仅用于允许重新入库的售出撤销场景，保留历史事实 |
| `COMPLETED` | `CANCEL` | `CANCELLED` | 对已完成业务执行完整冲销 |
| `CANCELLED` | 任意业务动作 | 拒绝 | 取消是终态 |

### 4.2 库存账号状态

库存账号状态是账号生命周期，不等同于订单状态或库存页的交付方向：

| 当前状态 | 动作 | 下一状态 | 说明 |
|---|---|---|---|
| `WAITING` | `BUY_STOCK` | `WAITING` | 买入后仍在库 |
| `WAITING` | `SELL` | `SOLD` | 登记售出；`SELL` 不区分全款或分期，售出方式作为业务属性记录 |
| `SOLD` | `RECOVER` | `WAITING` | 分期逾期回收 |
| `SOLD` | `CANCEL_STOCK` | `WAITING` | 买入事实冲销并重新入库 |
| `SOLD` | `CANCEL_SELL` | `WAITING` | 售出事实冲销并重新入库 |
| `SOLD` | `CANCEL_SELL_END` | `VOID` | 售出冲销且业务终止 |
| `VOID` | 任意动作 | 拒绝 | 终态 |

### 4.3 分期合约状态

分期收款通过资金明细登记收入，结清后使用业务事件 `DELIVER`；资金明细收入不是订单业务事件，也不是普通 `SELL` 的别名。

| 当前状态 | 动作 | 下一状态 | 说明 |
|---|---|---|---|
| `PENDING` | 收到收入明细 | `ACTIVE` | 收到首笔受控回款 |
| `ACTIVE` / `OVERDUE` | 收到收入明细 | 原状态或受控状态 | 允许部分收款和多次收款 |
| `OVERDUE` | 最后一个逾期应收被收清、减免或展期 | `PENDING` / `ACTIVE` | 其余期次尚未结清时，按是否已有收款恢复正常状态 |
| `ACTIVE` / `OVERDUE` | `SETTLE` | `SETTLED` | 应收已结清或完成受控减免 |
| `SETTLED` | `DELIVER` | `DELIVERED` | 结清后确认交付，不产生现金流 |
| `ACTIVE` / `OVERDUE` | `DEFAULT` | `DEFAULTED` | 登记违约 |
| 可取消状态 | `CANCEL` | `CANCELLED` | 未满足条件时取消合约 |

## 5. 审计动作定义

审计动作只记录“系统做了什么”，不代替业务动作、业务事件或资金明细。同一次用户操作可以同时产生一条审计记录、一个业务事件和一笔资金明细；它们是分层关联，不是重复定义。

本节列出订单、账号、业务事件、分期、交付、返点、资金和分润相关的常用审计动作。审计编码一行一个，不使用斜杠合并；页面可以使用相同的中文文案，但底层编码必须按记录对象保持独立。

| 分类 | 审计动作 | 中文含义 | 记录对象 | 与业务事件 / 资金明细的关系 |
|---|---|---|---|---|
| 订单 | `ORDER_CREATE` | 新建订单 | 订单 | 建立业务容器，不等于 `BUY` |
| 订单 | `ORDER_UPDATE` | 编辑 | 订单 | 修改订单资料，不产生售出或买入事实 |
| 订单 | `ORDER_CANCEL` | 取消订单 | 订单 | 记录取消操作；是否产生 `CANCEL` 或冲销资金明细由业务规则决定 |
| 业务事件 | `EVENT_CREATE` | 新建业务事件 | 业务事件 | 建立事件草稿，通常尚未成为正式业务事实 |
| 业务事件 | `EVENT_POST` | 过账业务事件 | 业务事件 | 将业务事件正式写入业务事实；有资金影响时关联收入 / 支出资金明细 |
| 账号 | `ACCOUNT_CREATE` | 新建账号 | 库存账号 | 建立账号资料，不等于账号入库 |
| 账号 | `ACCOUNT_UPDATE` | 编辑 | 库存账号 | 修改账号资料；页面不再单列“编辑账号”动作 |
| 库存 | `ACCOUNT_DELETE` | 历史库存删除 | 库存 | 保留旧审计编码用于读取历史；现行库存凭证不可物理删除 |
| 订单 | `ORDER_DELETE` | 历史订单删除 | 订单 | 保留旧审计编码用于读取历史；现行订单凭证不可物理删除 |
| 分期 | `INSTALLMENT_CREATE` | 新建分期合约 | 分期合约 | 创建分期容器，不等于已收款 |
| 分期 | `INSTALLMENT_CANCEL` | 取消分期合约 | 分期合约 | 记录合约取消，不自动删除已有收款明细 |
| 分期 | `INSTALLMENT_PAYMENT` | 登记分期收入 | 分期合约、资金明细 | 形成一笔收入资金明细，不新增订单业务事件 |
| 分期 | `INSTALLMENT_EARLY_SETTLE` | 提前结清 | 分期合约 | 改变结清状态，不重复确认收款 |
| 分期 | `INSTALLMENT_OVERDUE` | 登记逾期 | 分期合约 | 更新分期状态，不自动形成资金明细 |
| 分期 | `INSTALLMENT_DEFAULT` | 登记违约 | 分期合约 | 更新分期状态，后续处置按业务规则执行 |
| 分期 | `INSTALLMENT_WAIVE` | 登记减免 | 分期合约 | 记录应收减免；如涉及资金冲销，另关联资金明细 |
| 分期 | `INSTALLMENT_EXTEND` | 延期 | 分期合约 | 调整分期计划，不等于收款或售出 |
| 分期 | `INSTALLMENT_RECOVER` | 分期回收 | 分期合约、库存账号 | 形成回收处置轨迹，不等于买号或售出 |
| 分期 | `INSTALLMENT_RESELL` | 分期转售 | 分期合约、订单、库存账号 | 记录转售处置；产生的收入 / 支出按资金明细记录 |
| 交付 | `DELIVER_CREATE` | 登记交付 | 交付记录 | 对应 `DELIVER` 业务事件；交付本身不重复产生收入 |
| 返点 | `REBATE_CREATE` | 登记返点 | 返点记录、资金明细 | 对应 `REBATE` 业务事件，并关联一笔收入资金明细 |
| 返点 | `REBATE_UPDATE` | 编辑返点 | 返点记录 | 修改返点资料；金额变化需同步校验关联资金明细 |
| 返点 | `REBATE_DELETE` | 删除返点 | 返点记录 | 删除前必须保留审计；已入账金额不得无痕删除 |
| 资金 | `CASHFLOW_CREATE` | 登记资金明细 | 资金明细 | 记录收入或支出；不自动新增业务事件 |
| 资金 | `CASHFLOW_REVERSE` | 冲销资金明细 | 资金明细 | 保留原流水并建立冲销关系，不物理删除原流水 |
| 分润 | `PROFIT_ALLOCATION_SET` | 设置分润 | 分润记录、订单 | 记录利润归属；对应支出资金明细必须按分润结算规则关联 |

以下编码仅为历史审计日志兼容值，不属于当前新增动作：`REBATE_SETTLE`、`REBATE_REVERSE`、`REBATE_VOID`。它们可以继续用于旧日志展示，但新流程不得继续写入。

审计日志中的 `action` 必须使用稳定的英文编码；页面、筛选项和导出展示使用统一中文词典。任何未配置中文词典的编码都必须有安全回退，不得把底层编码作为面向用户的最终文案。

## 6. 页面动作展示规则

页面应展示“业务人员要做什么”，而不是把数据库枚举直接暴露给用户：

| 底层编码 | 推荐页面文案 | 适用页面语义 |
|---|---|---|
| `BUY` | 账号入库 | 取得账号、进入库存 |
| `SELL` | 账号售出 / 账号出库 | 记录真实成交、账号出库 |
| `DELIVER` | 交付 | 账号或服务完成交接 |
| `CANCEL` | 取消 / 冲销 | 取消未完成业务或冲销原事实 |
| `OPERATE` | 运营 | 作图、描述、寄售、下架等运营工作 |
| `REBATE` | 返点 | 登记买号返点或卖号返点 |

库存中心和订单台账共享账号编辑、售出、寄售、返点、资金收支、交付等页面动作。订单台账展示全量订单，库存中心只是同一业务数据按“在库”条件筛选后的视图；“分润配置”仅属于订单台账，且订单售出后才可用。动作根据订单状态、库存状态、业务类型和权限控制可用性。回款、返点属于收入明细，退款属于支出明细，利润分配配置不产生资金明细。

### 6.1 页面动作范围

| 统一动作 | 可用条件 | 说明 |
|---|---|---|
| 新建订单 | 按新建权限 | 两个视图进入同一套订单创建能力 |
| 编辑 | 记录可编辑且有权限 | 不再单列“编辑账号”；订单和账号资料统一归入编辑 |
| 售出 | 账号在库且满足售出条件 | 全款售出或分期售出 |
| 返点 | 有来源订单且满足返点条件 | 页面动作统一叫“返点”，再选择买号返点 / 卖号返点 |
| 分润配置 | 订单已售出、利润可计算且有权限 | 仅在订单台账配置分润归属对象及比例/金额；库存中心不提供入口；不登记实际分润支出 |
| 资金收支 | 有资金明细权限 | 页面动作统一叫“资金收支”，再选择收入 / 支出和资金原因 |
| 交付 | 满足买号或卖号交付条件 | 页面动作统一叫“交付”，再选择买号交付 / 卖号交付 |
| 运营 | 记录未终止且满足运营条件 | 页面动作统一叫“运营”，再选择作图、描述、寄售、下架 |
| 取消 | 符合对应业务取消条件 | 保留订单、库存和关联凭证，按业务规则生成更正记录 |

页面可以把“寄售”“下架”等运营属性做成快捷入口，但提交后仍记录为 `OPERATE`，并通过运营类型区分；不能因此新增独立业务动作编码。

### 6.2 交付方向属性

底层统一使用 `DELIVER` 业务事件，页面动作名称统一为“交付”，根据交付对象记录交付方向属性：

| 交付方向属性 | 业务含义 | 适用场景 |
|---|---|---|
| 买号交付 | 从卖家或供货方接收买入账号 | HS/TH 买入账号后的接收 |
| 卖号交付 | 向买方交付已经售出的账号或服务 | 全款售出、分期结清后的交付、DG 代挂 |

买号交付和卖号交付是 `DELIVER` 的两个方向属性，页面可以作为两个选择项或快捷入口展示，但不新增两个业务事件。

展示分组也必须按业务语义推导：

- **交付**：页面统一展示交付动作，再根据业务角色选择“买号交付”或“卖号交付”。
- **买号交付**：HS/TH 买入账号时，向卖家或供货方接收账号。
- **卖号交付**：全款售出后的交接、分期结清后的 `DELIVER`，以及业务类型为 DG 的订单。DG 即使暂时没有 `SELL`，也应按卖号交付展示。
- **操作追溯**：展示审计动作的中文文案，例如“新建订单”“登记业务事件”，不把 `ORDER_CREATE`、`EVENT_POST` 直接展示给用户。

## 7. 不变量与验收口径

1. 订单业务事件不包含独立的支出类动作；所有支出统一写入资金明细并使用 `OUT`。DG 不得出现 `BUY`，其盈利登记不依赖一条虚构的买入动作。
2. `SELL` 是实际售出事实；没有 `SELL` 时，DG 只是“尚未成交”，不是“买入单”。
3. 分期回款是收入资金明细；`DELIVER` 是交付业务事实，交付不重复产生收入。
4. `CANCEL` 和退款支出不得删除原订单事件或原资金流水，必须保留可追溯关联。
5. 审计动作不得代替业务事件；`ORDER_CREATE` 不等于 `BUY`，`EVENT_POST` 也不等于 `SELL`。
6. 页面中文文案、操作分组和审计列表均不得直接显示未翻译的 `BUY`、`SELL`、`ORDER_CREATE` 等底层编码。
7. 资金明细只有“收入 / 支出”两个现金方向；所有支出统一归入资金明细，不再额外创建订单支出动作。

### 7.1 典型示例：DG 代挂单

以 `DG0031` 为例：

1. 建单：写入 `ORDER_CREATE` 审计，订单进入 `ACTIVE`；此时没有 `BUY`。
2. 建单后查看交付信息：按 DG 的业务角色展示“卖号交付”表格，即使还没有 `SELL`。
3. 实际成交：登记一条 `SELL`，金额按代挂利润 / 服务收入口径入账，写入事件审计和资金流水审计。
4. 业务完成：订单进入 `COMPLETED`；后续如退款，登记一笔支出资金明细并关联原 `SELL`，保留原售出事实。
