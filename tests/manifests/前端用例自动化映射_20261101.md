## 3. 现有自动化入口

### Vitest

```text
cd frontend
npm run test:fast
npm run test:quick
npm run test:react
npm run test:react-deep
```

深度回归已拆为四个分片：`shell`、`business`、`governance`、`support`。单片执行方式见项目结果报告。

### Playwright

```text
cd frontend
npm run test:e2e:critical
npm run test:e2e
npm run test:visual
```

关键写路径使用独立 E2E 后端和数据库，不使用开发环境的业务数据库。

## 4. 后续补映射规则

新增或补齐自动化时，在手工用例表格中增加“自动化路径”字段，格式统一为：

```text
Vitest: src/orders/CreateBusinessModal.test.tsx
或
Playwright: e2e/business-write.spec.ts
```

同一条 FE 用例可以关联多个自动化文件，但不能把“同模块已有测试”直接当作该用例已覆盖。

优先补以下类型：

1. 当前失败且涉及数据正确性的用例。
2. 重复提交、超时、刷新、重试和结果未知场景。
3. 下拉选项完整性和字段联动。
4. 弹窗关闭、错误清理和保存反馈。
5. 报表导出、敏感字段和跨页面状态一致性。

## 5. 当前结论

前端自动化测试已经覆盖主要模块，但与 240 条手工用例还不是一对一关系。当前应把此文档作为映射基线，修复一个问题就补一条自动化关联，避免只增加手工测试数量而不增加可重复的自动化保护。
