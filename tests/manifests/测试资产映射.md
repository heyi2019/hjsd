# 测试资产映射

> 本文只维护两类映射：手工 `FE-*` 用例 ↔ 自动化归属、测试资产 ↔ 执行入口。
> 目录结构、分层规则、耗时基线与当前缺口以 `tests/README.md` 为唯一现行索引；本文不重复维护文件清单、通过数量与具体命令，避免二次漂移。

## 1. FE 手工用例 ↔ 自动化归属

`FE-001 ~ FE-240` 是前端手工用例锚点（`docs/前端测试用例库.md`），**不得废弃**。下表按业务范围登记自动化归属；「已有关联自动化」只表示对应模块已有测试，**不代表逐用例覆盖，也不代表当前通过**。

## 2. 测试资产 ↔ 执行入口

| 资产 | 位置 | 执行入口 |
|---|---|---|
| 后端单元 / 集成 / 契约 | `tests/backend/{unit,integration}/<区域>/` | `tests/README.md` 第 5 节「后端」 |
| 后端回归分组（唯一事实源） | `backend/run_regression.py` | 同上；分组定义不在本文重复维护 |
| 前端单元 / 组件 | `tests/frontend/{unit,module}/<区域>/` | 第 5 节「前端」 |
| E2E | `tests/e2e/<区域>/` | `npm run test:e2e`，按需手动，不接发布门禁 |
| 手工用例 | `docs/前端测试用例库.md` | `FE-001 ~ FE-240` 页面操作 |
| 元数据台账 | `docs/testing/测试元数据台账.csv` | `FEATURE` 功能编号 / `PROMISE` 业务承诺；后者由测试文件头承诺 ID 与 `test_promise_declaration.py` 守卫 |
| 用例库 / 报告 / 执行记录 | `docs/testing/` | 脚本生成，见 `docs/README.md` 3.2 |
| 归档证据 | `docs/archive/ux-audit/` | E2E 用例与 `ux-audit.mjs` 直接读取，**不可删** |

## 3. 补映射规则

新增或补齐自动化时，在手工用例表格中增加「自动化路径」字段，格式统一为：

```text
Vitest: tests/frontend/module/business/CreateBusinessModal.test.tsx
或
Playwright: tests/e2e/cross/business-write.spec.ts
```

同一条 FE 用例可以关联多个自动化文件，但不能把「同模块已有测试」直接当作该用例已覆盖。优先补：

1. 当前失败且涉及数据正确性的用例。
2. 重复提交、超时、刷新、重试和结果未知场景。
3. 下拉选项完整性和字段联动。
4. 弹窗关闭、错误清理和保存反馈。
5. 报表导出、敏感字段和跨页面状态一致性。

## 4. 结果归档规则

- 运行日志、覆盖率、Playwright HTML 报告和临时截图不入库，走 `.gitignore` 产物规则。
- 可复用假数据、图片与导入样本放 `tests/fixtures/`；`.env.*-test`、数据库备份及含密钥或业务数据的文件不得提交。
- 可复现的测试结论与缺陷证据放 `docs/` 现役文档；过期的 `测试报告_YYYYMMDD.*` 由生成器移入 `docs/testing/报告归档/`（不入库），不得用历史报告替代当前结果。

## 5. 当前结论

前端自动化已覆盖主要模块，但与 240 条手工用例还不是一对一关系。修复一个问题时补一条自动化关联，避免只增加手工用例数量而不增加可重复的自动化保护。
