## 3. 前端回归层映射

| 层级 | 内容 | 适用场景 |
|---|---|---|
| `fast` | 轻量逻辑和快速组件测试 | 提交前快速反馈 |
| `quick` | 稳定的核心页面测试 | 日常开发 |
| `react` | 常规 React/jsdom 测试 | 测试分支和普通 CI |
| `react-deep` | 重型 Modal、userEvent 和深度交互测试 | 夜间、主分支或发版前 |
| Playwright critical | `integration.spec.ts`、`business-write.spec.ts` | 关键业务链路 |
| Playwright full | `frontend/e2e/` 全部场景 | 完整回归 |

## 4. 测试结果归档规则

- 运行日志、覆盖率、Playwright HTML 报告和临时截图不提交到代码库，统一使用 `.gitignore` 中的产物规则。
- 可复用的假数据、图片和导入样本放在 `tests/fixtures/`。
- 可复现的测试结论和缺陷证据放在 `docs/` 的当前报告中。
- 过期报告移动到 `docs/archive/`，但不能用历史报告替代当前版本结果。
- `.env.*-test`、数据库备份和任何包含密钥或业务数据的文件不得提交。
- 自动化执行证据统一放在 `tests/results/`，必须记录命令、环境、通过数量和未覆盖范围。
