## 各任务详细说明

### T01 脚手架（0.5d）
- 后端：`backend/` FastAPI + SQLAlchemy，SQLite 文件 `data/heijin.db`，CORS 开 5173。
- 前端：`frontend/` Vite+React+TS+antd5，`npm run dev` 起 5173。
- 验收：`GET /` 返回 API 文档；前端首页渲染空白布局。

### T02 数据层（0.5d）
- 按数据字典§2 建 Account/Order/CashFlow/Installment/Lead 五 model。
- ProfitService 提供 `principal_wallet()` / `profit_wallet()` 聚合函数（视图逻辑）。
- 验收：pytest 测聚合；`total=principal+profit` 约束在 model 层校验。

### T03 迁移脚本（1d）
- `scripts/migrate_from_kdocs.py`：读取金山文档 5 表（kdocs 连接器）→ 清洗（数据字典§3.2）→ 写 SQLite。
- 输出迁移报告：总行数、删除测试行数、荷包余额 vs 流水末位差异。
- 验收：迁移后 profit_wallet + principal_wallet 与文档末位余额(约¥43,582)偏差<¥1（差异在迁移报告说明）。

### T04 M1 记账流水（1d）
- 页面 `/cashflow`：antd Table + Form，增删改查。
- 字段：日期/类别(枚举)/收支/金额/备注；按月份、类别筛选。
- 验收：录入一条运营支出，余额视图更新。

### T05 M2 账号库存（1d）
- 页面 `/accounts`：Table + Form，状态标签(在库绿/已售灰/分期中橙)。
- 字段同数据字典§2.1；支持状态手动变更。
- 验收：新增账号→状态在库；改已售→列表变色。

### T06 M3 订单中心（1.5d，核心）
- 页面 `/orders`：双字段录入（本金 / 利润 分离输入，禁用单金额）。
- 录「卖出」单：选 account → 自动 status→已售，写 cashflow×2，触发 ProfitService 重算。
- 校验：total=principal+profit 前端+后端双校验。
- 验收：录一笔回收(本金3769+利润947) → 该 account 变已售，本金荷包+3769，利润荷包+947，仪表盘同步。

### T07 M6 报表（1d）
- 页面 `/reports`：两个核心表。
  - 真实利润表(按月)：已实现利润 − 运营消耗(房租+办公+薪资)。
  - 库存占用表：在库账号数、占用本金、预期利润(售卖−本金)。
- 验收：导出 Excel 列名对齐金山文档。

### T08/T09/T10（P1，各 1d）
- 分期：建合约、每期补款登记、逾期(到期未补)标红 + 列表筛选。
- 需求：代蹲/代出任务池，状态流转。
- 高级报表：按回收员/售卖员利润、按渠道返点、分期应收追踪。

## 开工建议顺序
`T01 → T02 → T03(先有真实数据可验) → T04 → T05 → T06(核心联动) → T07(见价值)`。
P1 三件在 MVP 跑通后补。

## 关键风险
- **R1 本金/利润漏拆**：T06 双字段强制录入 + 模型校验兜住。
- **R2 迁移脏数据**：T03 清洗规则(删测试行/金额重算)必跑，差异进报告。
- **R3 荷包与流水末位对不上**：T03 交叉校验，偏差需解释（历史已发现约¥1000 出入，源自原表本金归集）。
